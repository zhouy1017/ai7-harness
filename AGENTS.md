# AI7 Harness Project

## Project phase

This repository is in architecture and migration design; the 36-question design interview is complete and no implementation has started. Agents arriving without prior context should read `HANDOFF.md` first, then this file. Read `kick-in/README.md` and the current `PROGRESS.md` before acting. Do not add product implementation, copy source from either input repository, vendor Harness, or merge histories until the relevant accepted decision explicitly authorizes it.

The design room is a Git repository published as private `zhouy1017/ai7-harness` on branch `main`. AI7 is proprietary with all rights reserved to the sole rights-holder; see `LICENSE`. The owner is the sole rights-holder of the private predecessor and has authorized reuse of its code, documentation, tests, and fixtures for AI7, so source copying is unblocked — subject to the per-asset provenance ledger, sanitization review, and provider-terms checks that still apply. Upstream third-party obligations do not automatically extend to an AI7-branded distribution and must be verified per component, with a maintained third-party notices file in every build.

Sample manuscripts are governed separately. They are real manuscripts, authorized for AI7 use, and their constraint governs persistence and publication rather than processing. Sending manuscript content to a configured model provider is permitted and is the basic feature of AI7, not an exception; it is controlled processing, never public release. Manuscripts are never stored in any repository, public or private, in history or working tree — private visibility does not cure this — and never enter hosted CI, build artifacts, distributable fixtures, corpora, mock-provider evidence, or the shipped product. They carry no redistribution right and reach no public channel without Public Release Permission.

The product display name is exactly **AI7**. There is no separate Chinese product name, and Harness is never user-facing branding — it is the execution foundation and appears only in third-party notices. Repository suffixes such as `-harness`, `-reborn`, and `-redesign` are developer-facing markers distinguishing development tracks; they carry no product meaning, and no agent should rename a repository to "fix" them.

All AI7 projects are solely owned by the repository owner, and agents are authorized to modify them. That is a statement of rights, not of workflow: the Repository Development Dispatch role authority still applies, so a Worker still never merges, pushes to `main`, publishes, or takes external actions regardless of the rights the owner holds.

Review original-AI7 documentation one topic cluster at a time through `kick-in/08-source-document-inheritance.md`. Do not copy source documents wholesale. Accepted new decisions and canonical context definitions outrank source-project instructions; unresolved source material remains evidence only. Harness-specific inheritance is an architecture-maintainer decision, subordinate to accepted AI7 product and safety constraints.

The new AI7 is a Chinese-first Standalone desktop product for Windows and macOS, for professionals in leading literary publishing houses in mainland China. The owner requires a consistent product outlook across both platforms; the exact consistency contract is a reopened Phase 0 decision, so do not silently infer full feature parity, pixel identity, identical native controls, or identical packaging. Microsoft Word integration is excluded from V1 scope: there is no cross-surface parity, COM add-in, synchronization protocol, Word packaging, or Word verification gate. The legacy Standalone and Word UI implementations, layouts, editors, and component models are not migration baselines; retain or revise user outcomes only when individually accepted.

Long Chinese manuscripts are a required feature with binding scale tiers counted in Chinese characters: no sensible performance degradation below 500K, no critical performance issue up to 1M, and no crash or unresponsiveness up to 10M. The renderer never holds a whole manuscript; the authoritative model lives in the AI7 service over a store that pages by Manuscript Block, whole-manuscript operations stream in the service off the UI thread with cancellation and progress, no unbounded in-memory structure exists at any layer, and the memory ceiling is tested at the 10M tier. Windowed display is accepted rather than tolerated, so the binding constraint is whole-manuscript index time: find, replace, and jump must complete in reasonable time at every tier, served by disk-backed block, CJK-aware substring full-text, and outline indexes. Typing latency depends on window size and never on manuscript size. Prove the tiers with an early performance gate against generated corpora and a real long sample, not at the end.

AI7 ships as an Electron application over three processes on both supported platforms: a thin Electron main shell, a renderer holding the UI and editor with context isolation on and Node integration off, and a separate Node service process holding AI7 domain services plus the composed Harness runtime as the one local authority. That separation keeps the UI responsive under parallel Runs, isolates crashes from unsaved text, and makes the service drivable headlessly for the pull-request gate. Local IPC prefers stdio and never opens a TCP listener. Windows named-pipe support remains an accepted option from the earlier topology; the exact macOS carrier and any platform-specific protocol adaptation are open Phase 0 decisions. ProseMirror is the editor foundation, operating over bounded windows mapped to global Manuscript Block identities.

Treat professional long-form text editing as a release-critical Standalone outcome. The independent UI/UX design must address long Chinese manuscripts, extensible structure and exact selection, durable editing/recovery, proposals/review, Chinese input/typography, and import/export fidelity without assuming the old editor. For representative publishing workflows, classify inline styles, comments/revisions, notes, tables, images/captions, sections, headers/footers, and round-trip behavior explicitly as preserve, degrade with disclosure, or reject—never lose them silently. Failure of the evidence-backed Standalone Editing Sufficiency Gate triggers diagnosis of editor, document-conversion, or genuinely Word-dependent workflow gaps; Word may enter a later release only through a separate ADR showing that live integration is the proportionate remedy.

Treat manuscripts, sources, and derivatives as Unpublished Editorial Material until Public Release Permission exists. Prevent unauthorized exposure through public channels, but do not silently inflate this into a classified/high-secrecy threat model.

Keep the Book as the source, privacy, and mutation authority, while every Book-owned Editorial Deliverable follows its own Workflow Instance pinned to a versioned Workflow Profile. V1 profiles cover Manuscript, Promotion Article, News Report, and Review Article; they compose seven shared phases—intake, source development, drafting, review/verification, finalization, delivery, and maintenance—which may overlap, reopen, or be skipped with a recorded reason.

Workflow state is durable editorial business state, not a Harness Workflow or Session. AI-assisted Task Skills may propose content and records, but only narrow deterministic commands may mutate Workflow Instances, Editorial Artifacts, Workflow Gates, Signoff Records, or Delivery Packages. Completion or signoff never implies factual truth, legal or regulatory authority, Public Release Permission, or Learning Eligibility.

Keep task source/mutation scope separate from editorial learning scope. A manuscript task may use its Book plus explicitly selected Cross-project sources; corpus-wide adaptation must flow through governed House Editorial Memory and must not silently expose another Book's raw text or facts.

Treat Series as an explicit richer-sharing exception: member Books may share governed Series Knowledge and a Series read scope, but every manuscript mutation remains targeted to a specific Book and revision.

Long manuscripts exceed any model context window, so AI7 retrieves over manuscripts as well as imported sources. Retrieval returns candidates and never truth: only Exact Fetch against the pinned Manuscript Revision yields authoritative text, and fuzzy or vector matching can never certify a quotation. The Manuscript Revision is the sole authority; the editor window, lexical index, outline, and retrieval chunks with their embeddings are derived projections that are disposable and rebuildable from it. Chunks and embeddings serve models while the editor reads ordinary text, so projections may use boundaries suited to their consumer rather than a shared unit. The requirement is consistency across forms: every projection records its derivation revision, rebuilds from the authority alone, invalidates by text-range overlap, tombstones deletions, and re-derives at Manuscript Checkpoints. A stale projection yields a stale ranking rather than merely stale text, so the remedy is re-derivation and re-ranking, not text substitution. Retrieval strategy — lexical, vector, or hybrid — is deferred to the store-and-index spike. Retrieval indexes derived from manuscript text are manuscript derivatives and never enter a repository, hosted CI, or a distributable artifact.

Treat an imported manuscript revision as the Textual Source of Record for what the document exactly says, never as a truth oracle for its assertions. AI7 must identify possible factual and semantic errors through evidence-bearing review, distinguish textual fidelity from factual verification, and express fixes as exact-revision Correction Proposals rather than silently rewriting source text.

Factual Verification follows the active versioned Factual Verification Policy Document. Record Reference Integrity, Claim Support, and Factual Verification independently; preserve unresolved or conflicting evidence, and use Foundation Model knowledge only to raise verification questions or guide research, never as factual evidence by itself.

Apply the accepted content/evidence rules explicitly: exact quotations require Quotation Verification against authoritative original text; source-derived factual claims require cited Evidence Links; current or external factual claims require timestamped research evidence; editorial interpretations are identified as judgment rather than proven fact; and creative or promotional synthesis remains generated text while each quoted, factual, or canonical subclaim follows its own evidence class.

Preserve manuscript history through stable Manuscript Blocks, immutable reconstructable Manuscript Revisions, text-only Manuscript Branches, per-branch durable Edit Journals, meaningful Manuscript Checkpoints, and independent verified Recovery Snapshots. Keep these records distinct from Source Versions, Source Index Chunks, Run Continuation Checkpoints, Harness technical checkpoints, and Harness Sessions.

All model-generated manuscript changes begin on Proposal Branches. Apply is atomic and exact-pin-bound: identical or non-interacting different-block changes may merge automatically, while different same-block changes and ambiguous structural interactions require explicit editor resolution; model-composed resolutions remain proposals.

Never use unqualified Approval as a domain authority. Distinguish Run Authorization, Execution Grant, Proposal Decision, Review Decision, Effect Approval, and Public Release Permission. One user interaction may create more than one exact record, but no decision or grant is proof that an Effect committed.

Every authoritative or externally visible Effect has stable identity, declared replay policy, exact target/payload binding, staged verification when applicable, per-Effect atomic publication, and an Effect Receipt or explicitly classified outcome evidence. Material drift invalidates Effect Approval; ambiguous external outcomes stop automatic retry and fallback; cancellation never claims to undo committed Effects.

Keep stable English domain terms for architecture and record identifiers, and maintain one preferred Simplified Chinese label for every accepted glossary term. Chinese-first product surfaces use the preferred Chinese label; `GLOSSARY.md` is the bilingual index, while each context `CONTEXT.md` remains the canonical definition owner.

AI7 owns the quality evaluator Harness does not provide. Capture Quality Signals from explicit editor feedback, editor-authored content, and proposal decision/version differences; derive verbatim acceptance, revision distance, survival to delivery, dissatisfaction by dimension, and workload displacement measured as edit volume weighted by a once-declared phase effort weight. Per-task time tracking is rejected. Signals are captured globally on the local instance and attributed for per-Book, per-editor, and per-house aggregation, but aggregating metrics globally never grants global retrieval access. AI7 must operate at zero data: no sample threshold may block operation or proposal, and sample size gates auto-activation alone. Query accept/reject/change reasons through a quick non-blocking one-click interaction that offers several alternatives, pre-selects none, and tracks guess acceptance versus correction — otherwise the system learns its own suggestion instead of the editor's judgment. Editor decisions are the oracle for taste, style, and editorial judgment, never for factual correctness.

Privacy is an egress boundary, not an identity boundary. Any authorized person may read a manuscript locally and Quality Signals may retain manuscript excerpts locally, but no automated path may carry a manuscript off the machine except a configured model call; repositories, hosted CI, runners, artifacts, and logs all stay closed.

No material may influence learned editorial behavior without Learning Lineage visible in the Learning Audit Log. Explicit inclusion/exclusion decisions outrank inferred Learning Eligibility Policy, and eligibility learning remains separate from editorial-preference learning.

Rules that grant or constrain product authority live in versioned, human-reviewable, machine-validatable Policy Documents rather than hidden prompts or code-only defaults. Production-run evidence may trigger AI-agent review and a Proposed Policy Revision, but historical versions remain immutable and no revision may expand its own scope or authority. Automatic activation is limited to evaluated, non-expansive calibration inside a user-approved envelope; semantic or authority changes require explicit user activation.

AI7 does not train or fine-tune an LLM. All model-facing design uses replaceable provided Foundation Models behind the AI7 Editorial Intelligence Layer. Preserve Professional Editorial Knowledge, provenance, memory, policies, and evaluations outside model weights, and judge changes by Editor-comparable Delivery Quality plus measurable workload reduction.

Compose the full Harness engine behind a narrow tool surface. An editorial Run never receives a generic shell, roaming filesystem, or arbitrary network tool; it receives domain-shaped AI7 Capabilities, including bounded import/export over a user-chosen file and provenance-bearing research. The intended user is a literature professional, not a computer expert, so a user who cannot assess whether an action is safe must never be asked to authorize it. Users still reach all their own material without filesystem literacy, and retrievability of every imported source and generated deliverable is a guarantee. The Agent Data Root remains the intended outer filesystem boundary, with Run Source Scope nested inside as the semantic boundary; however, no standing rule may call that OS boundary enforced until an accepted and verified mechanism exists on both Windows and macOS. The pinned Harness Windows ACL path is partial, and its macOS Seatbelt path governs file writes but not read, network, or process visibility. Until the Phase 0 platform decision closes this gap, AI7 capability and service facades are the only accepted enforceable product boundary. The Protected Secret Store sits outside the root, uses the supported operating system's protected credential facility behind one Credential Broker, and the root lives outside any repository working tree. The Editorial Capability Profile ships and the Developer Capability Profile does not, with no self-service escalation between them.

An agent may propose a revision to anything — Agent Behavior Assets, Policy Documents, or composition itself. A prompt may shape quality but may never grant authority: if changing text could widen what the system is permitted to do, it is a Policy Document. Activation is tiered, and capability expansion never self-activates. Behavior Assets may auto-activate only for non-expansive calibration inside an approved envelope; Policy Documents always require developer review; composition changes require developer review and ship in a release. Editorial users never see these assets, but every revision is versioned, lineage-bearing, diffable, rollback-able, and developer-reviewed — hidden is permitted, silent is not. Improvement claims require the two-sided evaluation gate: fixed-corpus replay for regression plus production metrics for real-world gain.

AI7 is TypeScript and Node throughout; no Python interpreter ships. The predecessor's Python carried zero third-party dependencies and handled DOCX with stdlib zip and XML, so nothing required it. A named capability with no adequate Node implementation may enter as a bounded native module or sidecar under its own ADR, never as a general-purpose embedded interpreter.

Windows retains two channels from one builder and one source: a **zip portable folder** and an **NSIS installer**. In the Windows portable channel the Agent Data Root lives inside the AI7 folder, with program files and user data separated so updates replace `app/` and preserve `data/`; an unwritable location falls back to `%LOCALAPPDATA%\AI7` with a plain notice, which is the Windows installer channel's normal path. The Protected Secret Store always stays outside a portable folder, since copied program data must never carry credentials. Detect placement beneath a known sync or backup root and warn clearly without blocking; every Agent Data Root stays outside any repository working tree. The macOS package/update channel, application-data location, architecture support, and signing/notarization policy are open Phase 0 platform decisions and must not be inferred from Windows. Windows code signing remains deferred, with unsigned SmartScreen cost recorded; that deferral grants no decision about Apple signing or notarization.

Consume Harness as exactly pinned public npm packages — no fork, no vendored source — and take only the subset AI7's composition needs. Never depend on the `@deepseek-ai/dsh` CLI aggregate: it transitively installs the generic shell, pwsh, terminal, and web tool packages that the editorial tool surface excludes, and absence from the dependency graph is a stronger guarantee than absence from the wiring. Pin exact versions with a committed lockfile and one coherent version across the selected subset; never use `^`, `~`, `latest`, or a GitHub release name. Registry dist-tags remain inconsistent: as verified on 2026-08-21, `latest` is still `0.0.1-rc.1` on most sampled AI7-relevant packages while `next` is `0.1.0-rc.8`; `dsh-agent-loop` is an exception with `latest = 0.1.0-rc.6`. The consumed baseline remains the explicitly accepted `0.1.0-rc.6`; `0.1.0-rc.5` is the audited but uninstallable reference and the two must never be conflated. Before implementation or bootstrap, Phase 0 must identify the candidate package subset and audit the rc.5-to-rc.6 delta across its exact closure and AI7 seams. Native installed-closure and ABI proof may use only a separately authorized disposable audit environment on each target platform; it does not authorize dependencies in this design repository. Upstream now publishes pre-release Git tags/releases for rc.7 and rc.8; both are evidence only and may enter solely through the pin-bump process. AI7 tracks GitHub tags/releases and commits together with npm versions and dist-tags, and none changes the accepted pin automatically. Pin bumps enter one at a time through a dedicated pull request verifying the composed Cordis config diff, capability exposure diff, session schema compatibility, AI7 journey replay, regenerated third-party notices, platform-installed closure, and Node/Electron ABI; compilation is never acceptance.

Harness owns the generic agent loop and AI7 never writes a second implementation of it. The rule is about implementations, not instances: parallel Runs across multiple Books, plus background analysis and learning work, are required behavior, and many instances of one loop are not a second loop. AI7 schedules and Harness converses — AI7 owns which Runs exist, workflow state, continuation, concurrency, budget, Effects, and model-free background jobs, while Harness owns turn structure, tool dispatch, in-turn retry, subagents, compaction, and Session events. AI7's business scheduling does not use Harness `schedule`, `jobs`, or workflow packages. Concurrency makes two things AI7's own: an instance-level concurrency and budget governor, and strict non-sharing of scratch and cache between concurrent Runs.

Learn the Harness framework; do not clone the product. Harness is built primarily for agentic coding while AI7 serves specialized Chinese literary publishing, so adopt its composition machinery — profiles, bundles, presets, plugins, context assembly, tool pipelines, policy seams, replay — and reject its coding-agent purpose, default presets and prompts, default tool set, and web surface. Adopting a framework is not adopting its defaults: every Harness default reaching an editorial Run must be justified for publishing work rather than inherited because it shipped, and AI7's Agent Behavior Assets are authored for editorial work rather than adapted from coding presets. "Full engine" means full composition capability, never the full package set.

Use DeepSeek Harness primarily as AI7's Agent Behavior Framework. Shape and evaluate how agents assemble context, plan, select tools, coordinate subagents, request approval, recover, and deliver evidence through versioned Harness compositions and documented extension seams. Keep Agent Behavior Improvement distinct from both Editorial Learning and Model Training. Do not fork the generic agent loop without an accepted seam-gap decision, and do not permit silent runtime self-modification.

Every production task binds an exact Task Intent and versioned Execution Plan to a machine-authoritative Plan Envelope. Its Plan Preview is only the human-readable projection; Run Authorization permits logged Plan Adaptations inside the unchanged envelope, while material changes to goal, scope, capabilities, providers, privacy category, budget, outcome, Effect class, or authority-bearing pins suspend work and require a Plan Revision plus renewed Run Authorization.

Run Authorization never grants Effect Approval, Proposal Decision, Review Decision, or Public Release Permission. Clarification Requests, pause/cancel, and Task Outcomes are durable and restart-safe; every outcome records actual-versus-planned work, evidence, unresolved matters, Effects/receipts, and a safe next action without silently becoming an authoritative manuscript, Editorial Artifact, factual resolution, or public release.

Use one logical causal graph with two authoritative ledgers. The AI7 Task Ledger owns Task Intents, Run Records, business commands, decisions, Effects, outcomes, workflow references, and provenance; the Harness Session Ledger alone owns model messages, turns, steps, tool calls/results, technical events, checkpoints, diagnostics, and attempt history. Join them through exact Execution Bindings and Harness Execution Spans without copying transcripts. Do not create active Operation Records, Operation Events, or `operationRuns`; legacy instances remain old-repository or offline evidence only and are not imported.

Resume continues the same unchanged Run from authoritative AI7 state, Retry creates a new safe execution attempt within that Run, Redo creates a newly authorized Run, and Replay performs no execution. A Harness success, tool result, Session event, or watermark is never an AI7 Effect Receipt or business completion proof.

Treat an AI7 Task Skill as an immutable declarative workflow package, never as a Cordis Plugin, Harness Tool, Model Provider, credential, or authority grant. Project each admitted Task Skill into a non-authoritative Harness instructional skill plus an AI7-owned per-Run Task Skill Activation; install code-bearing Capability Implementations separately through pinned, reviewed deployment composition.

Task Skill trust derives from installer/release provenance. Candidate, installed, validated, enabled, disabled, and retired are admission states, while enablement establishes only an Authority Ceiling. Effective Capability Grants are the per-Run intersection of that ceiling with the Task Intent, Plan Envelope, Run Source Scope, Provider Resolution Plan, active policies, and runtime constraints; enforce the same activation in both Harness tool guards and AI7 capability/service facades.

Task Skills declare Model Roles with hard requirements and soft preferences, never a provider, model, endpoint, or credential. Provider Preflight freezes the selected bindings, Approved Fallback Chain, Outbound Data Category, scope, and budget inside the Plan Envelope. Resolve secrets through opaque Credential References and an AI7 Credential Broker into an OS-protected store; never expose values to Task Skills, prompts, Session text, generic environments, tool results, or diagnostics.

Keep Provider Processing Policy, External Export Policy, and Public Release Permission separate. A configured model call is controlled processing, not public release; reading within a Run Source Scope does not by itself permit outbound transmission.

Verification retains two concise GitHub Actions workflows, `pr` and `release`, with no Ubuntu product or production lane. Required evidence must cover both Windows and macOS, but the smallest acceptable job/matrix topology and release artifacts are reopened Phase 0 decisions; do not create workflows until they are accepted. `pr` remains the sole required gate and carries no path filters. `release` remains tag-driven and fails closed without green required evidence for the same source SHA. Focused verification is local and has no workflow; Provider Rehearsal is local, opt-in, and never gating. Required CI remains provider-free: no live model call, no Model Provider API key, and no unpublished manuscript text. This does not pre-decide whether a future protected `release` environment may hold platform signing/notarization credentials. Keep the request-fingerprint guard so replay fails closed when the effective request drifts from its recorded fixture, regenerate the legacy public-synthetic corpus rather than byte-copying it, and retain the accepted five-field release-receipt core—source SHA, Harness pin/package set, lockfile hash, fixture-manifest digest, and package hash—while the per-platform versus combined receipt shape remains open.

A Ubuntu lane, a nightly tier, a machine-owned Test Catalog, a quarantine registry, and the wire-level fault server are deferred, each behind a trigger recorded in `kick-in/26-tiered-verification-and-mock-provider-evidence.md`. Add verification machinery when a concrete problem appears, not in advance.

Repository development uses three agent roles defined in `kick-in/27-repository-development-dispatch.md`: a Commander that decides dispatch and is the sole integrator and external-action authority; Workers that write only their own worktree and branch; and an independent Reviewer that never authored what it reviews. Every dispatched branch is reviewed at a task class at least equal to the work it reviews, cross-provider by default, disclosing `same-provider review — independence reduced` when that is impossible. Operating rules are provider-neutral and must never be conditioned on which model is running; a single binding table is the only provider-specific artifact, and fallback downgrades the provider, never the task class. This is repository-development tooling only, never shipped AI7 runtime behavior and never Harness product subagents. A Dispatch reviewer is not a Review Decision, and the Dispatch binding table is not a Provider Resolution Plan.

Legacy-data migration is allowlist-only. Do not import old production Books, manuscripts, indexes, embeddings, memory, task/run/operation history, workflows, proposals, decisions, Effects, receipts, or UI state. The only permitted legacy transfers are user-initiated API credential transfer directly into the new Protected Secret Store, reviewed mock-LLM-provider generators/fixtures/cassettes, and explicitly selected testing sample Books; secret values never enter files or logs, and test Books are excluded from production learning and publication by default.
