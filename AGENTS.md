# AI7 Harness Project

`AGENTS.md` is the mandatory entry point for every agent and human working in this repository. Root `CLAUDE.md` is exactly `@AGENTS.md`; shared rules never live there. A rule is owned by the linked runbook that states it; edit that owner and update this router only when routing changes.

## Lines and design truth

- `dev` is the long-lived integration line and the implementation-facing design baseline. Task branches start from and target `dev`. `main` is the protected release-promotion line and advances only by a separate exact Owner authorization. Frozen `design-doc@6895f02d2983865516d267809d8cdda77026f62c` is provenance only. See [development lines](docs/agents/development-lines.md).
- Design truth is the frozen design references (`docs/architecture-v2/`, `docs/ui-ux-v2/`, `kick-in/`, `docs/domain/*/CONTEXT.md`, `GLOSSARY.md`, `UBIQUITOUS_LANGUAGE.md`), the root ADRs, and the Policy Documents, read at the intended integration target. Implementation status lives only in [`PROGRESS.md`](PROGRESS.md) and [E2E journeys](docs/development/e2e-journeys.md). Delivery order lives only in the [development plan](docs/development/development-plan.md). [ADR 0064](docs/adr/0064-reweight-repository-development-toward-value-first-delivery.md) owns these ownership rules; [design authority](docs/agents/design-authority.md) resolves conflicts.
- An accepted design record does not by itself authorize dependency installation, a Provider call, fixture admission, export, publication, release, or promotion to `main`. Action authority comes from the Owner, the plan slice, and the Issue.

## Protected material

Never place a manuscript or manuscript derivative in any repository, working tree, hosted CI input, log, artifact, fixture, corpus, or distribution. The only exceptions are the Owner-designated **Public SampleBooks** under exact root `SampleBooks/` admitted by [ADR 0043](docs/adr/0043-allow-public-samplebooks-in-repository-and-ci.md) and exact `sample1`'s separately governed reviewed-fixture path under [ADR 0044](docs/adr/0044-use-sample1-as-compatibility-and-recording-baseline.md). Under [ADR 0065](docs/adr/0065-admit-a-developer-live-provider-processing-scope.md) only admitted Public SampleBooks may ever be transmitted to a model, and only under the human-attended `developer-live` scope on a developer host; CI and the Gate stay provider-free. Never place credentials or secret values in repository files, prompts, chats, environments, tool results, or diagnostics. The Owner's development credential file at the main checkout root (`*.key.txt`, untracked) is read only by the enrollment helper: never read, print, copy, or commit it, and run every live Provider test through the ledger and cache tooling of [ADR 0067](docs/adr/0067-authorize-the-opencode-go-development-credential-with-live-once-testing.md) so that a test item runs live at most once. The detailed constraints live in [project constraints](docs/agents/project-constraints.md); read only the sections the active slice implicates.

## Session entry

1. Record the exact `HEAD`, branch or detached state, worktree, and intended integration target.
2. Resolve the role. A **Commander** reads [`PROGRESS.md`](PROGRESS.md), the [development plan](docs/development/development-plan.md), and the [Dispatch Register](docs/agents/dispatch-register.md). A **Worker** or **Reviewer** reads this file, its GitHub Issue, and its Launch Receipt; a T3 Worker recomputes the Issue-body hash; every Worker verifies its exact base and every Reviewer its immutable `reviewed_head` before any controlled-file edit, and stops `needs-commander` on a mismatch.
3. Load only the read-by-task rows in the [agent document router](docs/agents/README.md).
4. Treat `docs/archive/` as excluded from ordinary reading.

## Development

- Every change follows the [incremental development lifecycle](docs/agents/incremental-development.md): one bounded outcome, one Issue, one branch, one pull request, one writable Worker; extend existing owners before adding new ones; a Worker stops when its brief is wrong rather than widening it.
- Dispatch follows [ADR 0061](docs/adr/0061-route-repository-dispatch-by-commander-harness.md) and [ADR 0063](docs/adr/0063-allow-cross-harness-dispatch-through-cli-launched-task-sessions.md) as amended by ADR 0064, with the operating detail in [Repository Development Dispatch](kick-in/27-repository-development-dispatch.md): the Commander selects each attempt's harness and launch mode, class bindings are fixed, receipts are schema v5, a Reviewer is optional, the Commander alone integrates and takes external actions, and the Commander may make mechanical documentation edits itself.
- Verification follows [ADR 0062](docs/adr/0062-adopt-a-local-verification-ladder-with-ci-as-delivery-gate.md): the Local Verification Ladder passes at the exact head before Ready, and the one provider-free E2E Functional Gate on Windows and macOS is the delivery gate ([CI and test boundaries](docs/agents/ci-test-boundaries.md)). Create no additional hosted gate unless the Owner reverses [ADR 0027](docs/adr/0027-concentrate-ci-on-e2e-functionality.md). Under [ADR 0058](docs/adr/0058-remove-actions-usage-observation-from-development-gating.md) do not query, estimate, or consider Actions usage.
- Git: [conventions](docs/agents/git-conventions.md). Issues: [tracker rules](docs/agents/issue-tracker.md) and the [one-page Change Brief](docs/agents/change-brief.md). Documents: [lifecycle and archiving](docs/agents/document-lifecycle.md).
- Domain work starts at [`CONTEXT-MAP.md`](CONTEXT-MAP.md); `GLOSSARY.md` is a bilingual index, not a definition owner ([domain rules](docs/agents/domain.md)).
