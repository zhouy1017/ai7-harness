### Conservative same-crate resolver

The resolver may resolve only use-tree leaves whose normalized target begins with `crate::`, `self::`, or one or more leading `super::` segments. It never invents a Cargo package-to-crate mapping. A leading `::`, `$crate`, or any first segment other than `crate`, `self`, or `super` is edge-local unresolved.

For every input, derive its crate source root only when its exact path has the form `codex-rs/<one-crate-directory>/src/<relative-rust-path>`. Derive the originating module segments mechanically:

- `lib.rs` or `main.rs` at the source root means the empty module path;
- `<segments>/mod.rs` means `<segments>`;
- `<segments>/<name>.rs` means `<segments>/<name>`.

Any other input shape is edge-local unresolved. `crate::` starts from the empty module path; `self::` starts from the originating module path; and a finite leading run of `super::` removes one originating-module segment per `super`. Underflow is edge-local unresolved. After applying the root prefix, require at least one remaining segment. The complete resulting segment sequence is the mechanical candidate-module path; this protocol performs no semantic item-resolution step and does not remove a final segment as an assumed item name.

Map that mechanical candidate-module path to source as follows:

- a candidate-module path `<p>` has candidates `<crate-source-root>/<p>.rs` and `<crate-source-root>/<p>/mod.rs`.

For example, `crate::foo` checks `foo.rs` and `foo/mod.rs`, while `crate::foo::bar` checks `foo/bar.rs` and `foo/bar/mod.rs`. Exactly one candidate must be a blob in the admitted exact tree. Zero or multiple candidates are edge-local unresolved. The result is a mechanical path candidate only, not proof that the module is selected or behaviorally relevant. This resolver does not interpret items, re-exports, or associated items and does not resolve external crates, inline modules, `#[path]`, generated or macro-expanded modules, `include!`, aliases, globs, or any mapping needing Cargo metadata or new source content. A use declaration inside a lexically identified inline-module body is edge-local unresolved.

### Canonical use-tree and edge records

Within an eligible exact `use` or exact `pub use` declaration, expand nested brace trees by left-to-right depth-first traversal. An ordinary path segment is a case-sensitive non-raw Rust identifier token. In addition, admit the exact Rust path-keyword tokens only in these positions: `crate` or `self` as the root prefix; one or more `super` tokens as the complete root-prefix run; and `self` as a brace-tree leaf denoting its accumulated prefix. A leading `::` may precede an ordinary external-root identifier. After an admitted keyword root, every non-`self`-leaf segment must be an ordinary path segment. Thus external ordinary-identifier roots and leading `::` remain eligible lexical edges but are classified only by `EDGE-RESOLUTIONS`; `$crate`, a keyword in any other position, or any other unsupported use-tree form creates a no-edge unresolved record. Raw identifiers, restricted visibility forms, glob leaves, aliases, empty targets, and unsupported syntax likewise create no-edge unresolved records. Attributes, macro input, comments, literals, and tokens outside a recognized declaration create no record.

For each eligible anchor occurrence in each expanded leaf:

- expand the leaf to its complete path;
- remove whitespace and comments between path tokens;
- preserve exact case-sensitive identifier spelling;
- join normalized segments with `::` as `target-token`, preserving one exact leading `::` when the leaf had it and otherwise adding no root marker;
- record the one-based line containing the anchor's first byte;
- record the zero-based UTF-8 byte offset of that first byte in the verified raw file;
- record the zero-based left-to-right depth-first leaf ordinal within its declaration; and
- classify exact `use` as `import` and exact `pub use` as `re-export`.

The canonical lexical-edge row is:

`source-path<TAB>line-20<TAB>byte-offset-20<TAB>leaf-ordinal-20<TAB>anchor<TAB>edge-kind<TAB>target-token<LF>`

Every field whose schema name ends in `-20`, and the numeric branch of any field named `*-20-or-<NONE>`, is an unsigned decimal integer encoded as exactly 20 ASCII digits with leading zeroes. This rule applies to line, byte offset, leaf ordinal, declaration ordinal, byte size, and every count; a negative value, non-integer, or value above `99999999999999999999` is a global malformed-manifest failure. Paths, anchors, edge kinds, and normalized targets may contain no tab, CR, or LF. Serialize as UTF-8 without BOM and LF only. Remove exact duplicate tuples, then sort complete serialized rows by unsigned UTF-8 byte lexicographic order. Repeated source occurrences remain distinct through offset or ordinal.

After canonical sorting, assign `EDGE-000001`, `EDGE-000002`, and so on in row order. Keep one discovery-edge row per eligible canonical edge, including eligible edges whose path mapping is unresolved. A novel target path appears once in the novel-path manifest, keyed by exact path/blob/byte-size tuple, with every associated edge ID in ascending order and the unique set of associated link-family IDs in unsigned UTF-8 byte order. Unsupported syntax without an eligible normalized target has no edge ID and appears only in the unresolved/excluded report.

- an allowed request is unavailable or rate-limited, uses a non-official final host, or returns an unexpected status;
- commit, tree, truncation, decompressed-body size, JSON parsing, tree-index, path, type, blob, byte-size, aggregate, UTF-8, or NUL predicate fails;
- the canonical extractor-source bytes, byte size, SHA-256, or single-line Base64 are not fixed before the first input or do not reproduce one another; either full-pipeline execution fails; any manifest is malformed; or the two complete-result envelopes, component manifests, or fingerprints differ;
- the original/fixed/novel sets are not pairwise disjoint, one path has conflicting blob/size identity, or a path/byte/request ceiling is exceeded;
- the Worker performs an unauthorized current-doc, other-ref, code-search, GraphQL, search-engine, clone, archive, package, binary, schema, runtime, model, MCP, new-source-content, external-write, or new-authority action.

These cases are always edge-local and override no global predicate: external/unbound crate prefixes; leading `::` or `$crate`; inline modules; `#[path]`; generated, macro, or include resolution; aliases or globs; unsupported or ambiguous use-tree syntax; root underflow; zero or multiple resolver candidates; and any edge needing semantic interpretation, filename guessing, proximity/convention inference, Cargo mapping, new retrieval, or a widened discovery method. Record the applicable exact unresolved code and continue independent edges without performing the prohibited action. If the Worker actually performs a prohibited action, the global-stop rule applies.

An anchored coverage key with only unresolved records is `SEARCHED-ALL-EDGES-UNRESOLVED`; one with no eligible edge or unresolved record is `SEARCHED-NO-ELIGIBLE-EDGE`. Neither implies absence or completeness. If every edge is unresolved or yields no novel path, return only the three fixed leads and the exact unresolved/search record.

Failure or partial discovery is not evidence that a path or capability is absent and is not a Codex Capability Gap.
