# E2E journeys: what each admitted runner proves

This file records, per admitted Journey, the exact behavior the runner under `e2e/` exercises and asserts. It is one of the two implementation-status records under [ADR 0064](../adr/0064-reweight-repository-development-toward-value-first-delivery.md); the other is root [`PROGRESS.md`](../../PROGRESS.md). The design of every Journey lives in [`docs/ui-ux-v2/journeys.md`](../ui-ux-v2/journeys.md); a design row is never evidence that its branches are implemented. Update this file in the same pull request that changes a runner.

Every runner installs the built Node egress guard before third-party controller imports, preflights its disposable Agent Data Root, launches the exact Electron carrier, and drives it only over inherited Chromium `--remote-debugging-pipe` descriptors: no debug port, inspector, WebSocket endpoint, TCP listener, or dev server exists. No runner reads the product database as a result oracle, and none retains, uploads, or logs a manuscript payload, credential, screenshot, trace, or video.
