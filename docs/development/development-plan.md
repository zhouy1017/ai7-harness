## The mainline every slice serves

AI7 is the local workbench of a literary publishing house's editor: the manuscript is the center, an agent harness takes on the complex reading, checking and drafting labour, and every manuscript change and every 发稿 is the editor's decision with an exact record. The service mainline is: import with revisions, comments and recognized structure → the editor starts a procedure (工序) with one action, with their own instructions and the house's preferences → the harness reads the whole book with a ledger, reviews chunks in parallel, extracts and verifies claims, reconciles across chapters, synthesizes, uses tools to look back, and runs non-urgent parts in idle time → results return as exactly anchored cards with their evidence, reports being derived views → the editor reviews card by card → milestones, 发稿版本, Production Documents, DOCX export and the 图书交付包 → decisions, rewrites and Word revision samples become house memory, the learning agent asks why when useful, and procedures are captured and reused. Value accrues in three layers: daily review work saved, deliverables and workflow, and the house's growing assets (procedure library, memory and preferences, exemplars, Series knowledge).

## Tracker and evidence discipline

Feature Issues retain predecessor links and closure evidence; [#1065](https://github.com/zhouy1017/ai7-harness/issues/1065) owns the R2 tracker alignment. Supersession changes ownership, not delivery status.

Use provider-free protocol fixtures and existing admitted development evidence first. Repository dispatch follows [Orca dispatch](../agents/orca-dispatch.md): the Owner may manually dispatch coding tasks one Issue at a time to a single coding agent, or dispatch via an Orca wave coordinator. **Mandatory cross-provider review is permanently retired**: review/repair is triggered **only when E2E tests or CI tests fail**. All slices enforce the anti-defensive coding and test-proportionality rules in [incremental development](../agents/incremental-development.md) (no startup full-database JSON/hash scans, no empty schema bumps, no policy-version churn, and focused public-API behavioral tests instead of raw SQL/corruption test bloat). Live-test reuse follows ADR 0089/0067; new business tasks perform their real model steps, while product continuation and reuse keep their own semantics.

Every product slice follows [CI and test boundaries](../agents/ci-test-boundaries.md), including the attested ladder and Electron Journeys on background guests, exact current head/base and synchronized runner deltas. Keep the existing provider-free Gate. Documentation-only slices use local links, root wrappers, directive consistency, scenario walkthroughs, `pnpm run docs:check` and `git diff --check`; no unrelated build, model call or hosted Gate is added.

**Windows is the only delivery platform.** Under [ADR 0097](../adr/0097-defer-the-macos-platform-indefinitely-and-deliver-windows-only.md) every macOS gate and target — the macOS job of the full Gate and of each nightly candidate, the nightly macOS inspection package, macOS releases and the consolidated Windows/macOS re-entry — is deferred indefinitely with no scheduled date; only a new explicit Owner request recorded as an ADR resumes any of it. The full Gate, the nightly queue and native packaging run on Windows Server 2025 only, and the macOS code paths stay in the tree unverified. Signing, publication, version tags and `main` promotion retain their distinct authorizations. A slice merged into a wave is not integrated into dev; the Commander accepts cumulative behavior and updates PROGRESS at final integration.
