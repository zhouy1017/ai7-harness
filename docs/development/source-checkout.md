This is the operational routing document for the provider-free J-01 local DOCX import workspace, complete J-02 long-manuscript module, cohesive J-08 interrupted-manuscript recovery module, J-12 Book/Revision, Product Data Location, and Model Service credential slice, J-15 fixed native carrier and authority-sidecar lifecycle, J-03 provider-denied Task authorization record, and J-04 covered baseline manuscript analysis over the local deterministic model route. The governing contract remains [`docs/agents/source-checkout-buildability.md`](../agents/source-checkout-buildability.md); this file records their concrete implementation.

`check` runs the exact TypeScript check that `build` performs, with full diagnostics for the developer host; `test` runs the vitest unit suites under `tests/unit`; `test:service` runs the vitest service-integration suites under `tests/service`, which open the real service stores on a disposable Agent Data Root outside this checkout and need no Electron, no Provider, and no network; its baseline-analysis suite drives the real single-slot scheduler, harness, egress gate, and `ai7-local-deterministic` adapter over the hand-written synthetic fixtures under `tests/fixtures/model/`. All three are Local Verification Ladder layers under ADR 0062: developer-run surfaces that never become hosted gates and never appear in the workflow.

`e2e:debug` runs one admitted Journey with the controller-only `AI7_E2E_LOCAL_DEBUG` switch: the runner's stdout/stderr, the product process output that Playwright logs for the launched browser (`playwright-browser.log`), the complete failure error with its `cause` chain and stack, and a screenshot of every open renderer page taken before the runner's cleanup are written only under ignored `test-results/e2e/<journey>/<timestamp>/`. `e2e:repeat` runs the same Journey up to `n` times through that mode, stops at the first failure, and deletes the artifacts of passing runs. Both refuse to run under `CI`, `GITHUB_ACTIONS`, or the Windows CI marker, never forward the switch to the product process, and leave `e2e`, `e2e:all`, and `e2e:diagnose` output byte-identical (ADR 0062).

The pnpm SRI-bearing `packageManager` declaration is the pnpm selection authority. `doctor` reports the OS/CPU, exact runtime pins, canonical native adapter, official npm registry, host Node distribution identity/URL/SHA-256, lock/config hashes, and host Electron artifact identity/URL/SHA-256. The Node runtime executing the command must itself be exactly 24.18.1; CI selects it with the full-SHA-pinned `actions/setup-node` action and the repository records the official distribution digest.

`bootstrap` performs the host check before changing generated state. It then proves generated dependency, store, cache, and runtime roots are exact canonical children of this checkout; rejects redirected junctions or symlinks; removes only the exact checkout-local `node_modules`; and runs a frozen pnpm install. After that install it verifies the installed closure before acquiring the Electron runtime: every package directory the virtual store resolved for this host must be non-empty and no `node_modules` symlink may dangle. An incomplete closure fails the command with one payload-safe marker that names only the incomplete and inspected counts, never a package name or path; the recovery is to remove `node_modules` and re-run `bootstrap`. A complete install produces the same output as before. The child has a closed PATH and fresh task-local pnpm/npm user, global, structured, and auth config files. The official unauthenticated npm registry is fixed. Recognized identity/path/output and preload overrides fail in `doctor`; Node's environment-proxy, extra-CA, disabled-TLS-verification, and SSL certificate selectors also fail before parent-process Electron acquisition. Other ambient proxy variables are not enabled for Node fetch and are not forwarded to acquisition children.

The hosted runner explicitly supplies `NPM_CONFIG_PREFIX` as an empty string for every exact root command, neutralizing the runner image's otherwise ambient npm prefix before pnpm starts. `doctor` treats only that exact empty value as non-influential and rejects every nonempty value; bootstrap children never inherit the selector.

The Electron runtime is not an npm dependency. Bootstrap downloads or reuses only the host artifact declared in [`config/dependency-artifacts.json`](../../config/dependency-artifacts.json), verifies its SHA-256, extracts to a new checkout-local staging directory with the fixed OS adapter, and proves Electron 43.4.1, embedded Node 24.18.1, ABI 148, `node:sqlite`, FTS5, and the archive-root `LICENSE` and `LICENSES.chromium.html` carriers. Permanent locks, other launch errors, failed child exits and invalid runtime evidence still fail bootstrap; this does not retry a hosted Gate.

## J-04 covered baseline analysis

The baseline manuscript analysis is one exact-versioned covered Task kind over the J-03 authority: it reuses the Task Input checkpoint owner, the Revision 2 artifact pin, the fixed missing-credential DeepSeek binding, and the verified development-ci Provider Processing v1 denial. Preparation derives a deterministic Coverage Manifest from the pinned Revision (title/heading blocks start a structural section; each section is split greedily into units of at most 1,200 graphemes with one overlap block carried from the previous unit; own ranges partition every block exactly once) and freezes it with the Provider Resolution plan, Execution plan, and Plan Envelope. The Plan Envelope carries the prompt-contract digest and the behavior-composition digest so a later attempt with a changed prompt or harness composition cannot reuse it.

Main accepts `--j04-picker-path <sample1.docx>` and `--j04-model-adapter <fixture identity>` only under `AI7_E2E_JOURNEY=J-04` — the adapter control also under `AI7_E2E_JOURNEY=J-09` (Issue #424), with the service child told which of the two it serves — mutually exclusive with the other Journey controls. The service loads the named fixture from `tests/fixtures/model/` before the store opens and binds the in-process `ai7-local-deterministic` route to it; the route pins the fixture identity, its lineage digest, the route, and the model name into the plan, the Execution Binding, and the Result Set Revision. Without the control the Run Authorization is still recorded, but the Run settles `blocked-before-dispatch` with its three visible reasons and creates no Session, payload, or network activity. The remote DeepSeek adapter exists as an assembled-request/parsed-response owner only; its transport is denied under Provider Processing v1 and the egress gate refuses every remote route.

Connectivity Wait (Issue #502) is schema revision 30, on service protocol version 43. It widens `analysis_run_states` with two Run states — `awaiting-connectivity`, a Run authorized by `联网后开始任务` that waits until Reconnect Preflight admits it, and `cancelled`, a waiting Run the editor cancelled before it ever dispatched — rebuilt once, shape-detected, with every row copied byte for byte; nothing else moves. Whether the device is online is a local reading, never a probe: an interface carrying an address that is neither internal nor link-local (`src/service/connectivity.ts`). Reconnect Preflight (`src/service/reconnect-preflight.ts`) runs when the service starts, every fifteen seconds while it runs, after a credential changes, and from the drawer every two seconds while it shows a waiting Run: it leaves the Run waiting for the network, for a missing credential or for a place of the governor, blocks it naming what moved when the plan it bound no longer stands, and otherwise admits it through the execution owner, which accepts a waiting Run only on that word. Since service protocol version 58 (Issue #536) the blocked state's canonical detail also keeps why, `cause`: `plan-moved`, or `launch` when the execution owner refused the admission, and a record without it reads as `launch`. A Run blocked because its plan moved reads `需要重新确认计划` in the drawer, ②A and 待我处理, where it sits with the plan decisions, and the drawer's `重新准备` prepares the same goal and range as a new Task and opens its plan. Any other block keeps `派发前已阻止`. ## Closed product interval

After bootstrap, the E2E controller, Electron main, isolated renderer, and service deny outbound HTTP(S), WebSocket, DNS, and socket primitives appropriate to their process. The product receives no repository token, registry credential, provider credential, debug selector, or ambient payload path. Renderer checks return booleans only; ordinary scenarios emit a fixed failure location, the diagnostic wrapper re-emits only a bounded allowlisted tuple, and neither creates a screenshot, trace, video, artifact, log payload, database assertion, or tracked DOCX.

Generated `node_modules/`, `.pnpm-store/`, `.cache/`, `.runtime/`, `dist/`, E2E temp roots, and Agent Data Roots are reconstructable or disposable outputs. None is a source input. Hosted CI may restore only `.cache/bootstrap/electron` through the exact full-SHA-pinned cache action, keyed by operating system, architecture, and the complete `config/dependency-artifacts.json` hash. A miss follows the same bootstrap path, and bootstrap revalidates the canonical path and declared SHA-256 before use. After successful bootstrap, the verified download may be saved immediately so later build/Journey failure does not prevent a same-pull-request retry from using it; GitHub pull-request cache scoping means cross-pull-request reuse is not assumed. The cache never includes `.pnpm-store`, `node_modules`, `.runtime`, `dist`, Agent Data Roots, databases, product runtime state, logs, credentials, manuscript-shaped data, screenshots, traces, videos, or test artifacts; a hit has no success meaning.

Proposal material versions include the monotonic immutable reason-feedback revision count. Reverting a reason to earlier wording still requires a new eligibility decision; stable material identity and paging order do not move. Review Task provenance uses the frozen Run/category state without allocating the complete findings collection.

Feedback History filters by Book, source/result kind, disposition or judgment, historic author/editor, Editorial Dimension and an inclusive local calendar-day range before selecting its bounded page. It groups the retained page by Book, source, day or dimension without changing the filtered cursor. Date endpoints resolve the following local midnight independently, including a skipped-midnight DST transition. History remains passive; exact history and learning source routes both preserve their Book bindings.

A manuscript Book's Series Knowledge proposal selector pages every current member Series through inspectBookSeries's optional membershipsAfter cursor and membershipsNext response. Each page retains at most fifty names within the existing byte budget; complete membership chains and current Series identities validate independently of the cursor. Next/reset/retry replace one page, retain it on read failure and ignore replies after closure. The exact settled selection stays pinned across paging and composition; submission still verifies current membership and exact manuscript provenance.

Before a database package manifest is written, every frozen content-object, recovery snapshot, library original and retained native-artifact reference is compared with the paths, lengths and digests of bytes actually packed. Complete reference rows stream with cancellation and bounded yielding. A reference the live store no longer holds was removed while the package was made, so it refuses DATABASE_PACKAGE_INCOMPLETE and a retry makes a whole package; a reference the live store still holds was missing or changed before the export began, so it refuses DATABASE_SOURCE_DAMAGED, naming how many 稿件文件, 恢复快照, 资料库原件 or 编辑工作区方案 files are damaged instead of asking for a retry that would fail the same way. Disabling scheduled backups withdraws publication authority from staging only after the preference record succeeds. Each old attempt keeps its permanently aborted signal. Re-enabling during cleanup queues a fresh check bound to that exact enabled preference ordinal; a later decision or shutdown cancels the queued restart. Settings still answer immediately, and cancellation leaves no new package, record or failure notice while completed backups remain retained. The pins live in the `writing_tasks` row's canonical JSON, which no CHECK constrains.

- **What is offered.** `WritingTaskProjection.references.materials` lists, latest arrival first and at most 50, every 资料库 item this Book's Tasks may list — the rule `pinMaterialReference` enforces: attributed to this Book or the house, its Learning Eligibility decided and not 稍后决定 — whose Material Index is `complete`. Each carries its title, its extracted characters as its card states them, whose it is, and whether it may be ticked; one over the per-item bound is shown disabled with 「这份资料已提取 N 字，超过每份 3,000 字的上限，不能列进「允许参考」。」. 新建文档 · 写作任务 shows them as a 资料库 row of boxes, none ticked, after 范例; `prepareWritingTask` takes the ticked identities as `materialIds` (optional in the frame and in main, at most 16 there; the store's bounds below).
- **The bounds.** At most 4 items, each at most 3,000 characters and all at most 6,000 together, counted in the index's extracted characters (`metadata.characters`, the card's 「已提取 N 字」). An item is taken whole or not at all: over a bound, 先看计划 is refused in words (`WRITING_MATERIAL_OVER_BOUND`, `WRITING_MATERIALS_INVALID`) and nothing is recorded. An item that is not listable, not indexed, or has no text is refused with the Material Index's own words, prefixed with its title.
- **The pin.** Each ticked item is pinned by `pinMaterialReference` at its current build and read whole through `readMaterialIndexForTask` under a boundary of that one pin, a page at a time; `MaterialTaskReading` segments now carry their paragraph `text`. Each paragraph is taken as the Book's own words are (`writingWords`, never cut) and the contract freezes it. The row records `materialSources` — item, index digest, title, characters and the digest of the paragraphs taken (`ai7.writing-material/1`) — and an input whose `materials` is `[]`: the item's words are never stored in the Task's rows. Every later read of the Task — its plan, 交付物, authorization, the ledger the Run executes on, a restart — reads the items again through the same seam at the pins and checks the digest. Reading writes nothing (the suite's `data_version` and index-row checks).
- **Contract `/3`.** `ai7.writing.prompt-contract/3` is `/2` with `input.materials` (one to four `{ title, paragraphs }`) and, in the synthesis instruction only, the line 「参照资料库的 N 份资料（只参照，不照抄）：…」 with the copy rules said of each item, then one line per paragraph `《标题》第 n 段：…`. Only a Task that lists an item is `/3`; any other has no `materials` key and is `/2` byte for byte, and a `/1` or `/2` Task keeps its contract and digest (pinned against dev@799e73a0 in the unit suite). `/3` judges under `/2`'s sizes and is never composed under `/1`.
- **Copy rules over 资料库 text.** `referenceCopied` judges the exemplars exactly as before, then each item alone as the one exemplar under the same rules and sizes: the Book's own reference words exempt a run, but two items sharing words exempt nothing (the house-phrasing exemption is two other Books' exemplars). No number changes. A copy is refused whole as `material-copied`, a gap that reads 「全书综合写出的草稿被拒绝（material-copied），AI7 没有写出可以打开的草稿：草稿与资料库资料《…》有连续 12 个字以上相同；资料只参照，不复制，这份草稿不予采用。」. The plan's 不会做 gains 「不照抄资料库资料：…」 only when it lists an item.
- **A build that is gone.** A pinned build this data no longer holds (data replaced or merged from elsewhere, whose index is rebuilt: `derived`), or an item this Book's Tasks may no longer list, keeps a never-started Task from starting: the plan reads 「不能开始 · 参考资料已不在本机」 with the item's 参考 line saying why, the bar is `unavailable`, and `authorizeWriting` refuses `MATERIAL_INDEX_MOVED` (or `MATERIAL_REFERENCE_UNAVAILABLE`) with 「这次起草参考的资料《…》，计划冻结的索引版本已不在本机，不能开始；请改计划重做：在「交付物」的新建文档 · 写作任务里重新准备计划。」. The writing kind takes no drawer redo, so 改计划重做 is the re-preparation in 交付物, which pins the item at its build now. Because the pins are no words of the contract, a preparation whose pins differ from the latest prepared Task's is a new Task Intent (`BaselineAnalysisPrepareInput.newTask`), never the old Task revised in place with its old row.
- **Developer-live.** No Provider Processing policy admits 资料库 text: developer-live (provider-processing-policy v7) transmits only the Owner-designated Public SampleBooks, and a 资料库 item is the editor's own material. The writing kind was already refused under any live scope (`WRITING_LIVE_UNAVAILABLE`); a plan that lists an item is now refused there in its own words first (`WRITING_MATERIAL_LIVE_UNAVAILABLE`, at preparation and at authorization), and the sheet's 资料库 row offers nothing to tick there. The development-ci fixture route proves the path.
- **默认执行规则.** A writing rule binds no 资料库 item (TASK-023, TASK-026): a plan that lists one cannot set a rule (「列了资料库资料的写作计划不能设为快速开始默认…」), and 快速开始 with an item ticked prepares the Task and stops at its plan (「这次勾选了资料库资料：默认执行规则不带参考资料…」).
- **Fixture and Journey.** `sample1-writing-authored` gains J-07's 评论文章 that lists `青铜器保护笔记` (its 8 unit requests and one synthesis under `/3`; the reflection request is the 宣传文章 Run's, whose accounting it shares), regenerated through `tests/service/writing-fixture-generator.test.ts`; the 宣传文章 entries are byte for byte as before. J-07 gains `writing-library-material`, `writing-library-plan` and `writing-library-draft`. `GATE_JOURNEYS` is unchanged, and no `window.ai7` member was added.

## 资料索引：HTML、EPUB、ODT 与 RTF

Extracted text for the four formats S80a left at 「AI7 还不能提取这种格式的文字」 (Issue #428; V2-UX-KB-009) is service protocol version **121** and no schema revision: it follows protocol 120 (#757; #760 holds 119; #742 holds 118) and keeps schema revision 67. No CHECK lists formats (`material_index_builds` constrains only its state), and no dependency was added.

- **The readers.** `src/service/material-formats.ts` reads each format into the paragraphs every other format's index is made of — lines, and a heading style where the format names one — which the Material Index packages with the intake's `buildManuscriptPackage` and reads through `parseDocx` from its working copy, exactly as a converted `.txt`; the segments, the 第 n 段第 m 句 anchors, the digests and 「已提取 N 字」 (and so #758's 允许参考 bounds) are the same model. **HTML**: a small tokenizer in the encoding the byte-order mark or the page's own `<meta>` names (GBK included, through `TextDecoder`), block elements as paragraphs, `h1`–`h6` as headings, `pre` keeping its lines; a `<br>` inside a paragraph, list item, cell, heading or caption breaks a line of that paragraph, two in a row end it, and one straight in `body`, a `div` or a `section` ends it — so a converted web novel written as one `div` of `<br>` lines reads as its paragraphs, not as one paragraph past the block bound; character references decoded, numeric ones with any leading zeros, 128–159 as windows-1252 reads them, and an unknown name left as written; scripts, styles, comments, `template`, `noscript`, `svg`, `math`, form controls and any element with `hidden` or an inline `display: none` are not read — the next `<p>`, `<li>` or `<td>` still closes a hidden one, as HTML's parser does, so the visible text after it is read; the page's `<title>` is its own title. **EPUB**: the ZIP read with `fflate` and its container, package and encryption parts with `saxes`; the spine's chapters in reading order through the HTML reader, each once however often the spine or the manifest names it, the navigation document left out, `dc:title` its own title. Paths inside the archive and the container's `full-path` are read as they are meant (`./x` as `x`, `a//b` as `a/b`); one that is absolute, uses a backslash or leaves the archive is refused. **ODT**: `content.xml`'s `text:p` and `text:h` (the outline level its heading), `text:s`, `text:tab` and `text:line-break` as what they stand for; notes, comments, tracked deletions, frames, `text:hidden-text`, a paragraph whose `text:hidden-paragraph` records `text:is-hidden="true"` (ODF's default is `false`, so one that records nothing is read), a `text:section` with `text:display="none"`, and text in a character or paragraph style that hides it — `<style:text-properties text:display="none"/>`, LibreOffice's Format › Character › Hidden, resolved from `styles.xml` and the automatic styles through at most 32 parents, at most 10,000 styles — are not read; `meta.xml`'s `dc:title` its own title. **RTF**: a tokenizer for groups and control words; `\uN` as its code unit (a surrogate pair joined) with the `\ucN` stand-ins passed over, `\'hh` and 8-bit bytes in the code page of the current font's `\fcharset` (or `\cpg`) or the document's `\ansicpg` through `TextDecoder` (GB2312 as GBK), `\par`, `\sect`, `\page` and `\row` ending a paragraph, `\line` a line, `\outlinelevelN` a heading; hidden text (`\v`), tracked deletions (`\deleted`), field codes, pictures, objects, headers, footers, notes, comments and the file's own tables are not read, and a `\ud` is read only as the Unicode alternative of the `\upr` group it belongs to, in that group's destination; the information group's `\title` is its own title. The metadata layer shows a format's own title as it does a DOCX's.
- **Bounds and refusals.** The DOCX parser's bounds, with the archive entry count raised from 256 to 4,096 for books (`MATERIAL_FORMAT_BOUNDS`): each archive entry at most 64 MiB expanded and all of them 96 MiB, the ratio 2,000 once a mebibyte is expanded, every entry expanded and counted whether it is kept or not, the central directory read before anything is expanded; 128 open elements or RTF groups; one tag or declaration 32,768 code units; 10,000,000 code units of text and 100,000 paragraphs, each paragraph still within `parseDocx`'s block bound. What crosses one is a `failed` build with `over-bound`, never cut. Every step is linear in what is read: a run of line breaks adds nothing past the first (the review of #761 measured 80,000 `<br>` at 15 s before), and the EPUB chapters read together are held to the expanded bound. A document declaring entities, element or attribute lists, or a DOCTYPE with an internal subset — an XHTML chapter, an HTML page, any XML part — is `failed` with the new reason `external-entity` (「文件声明了实体或内部文档类型定义，AI7 为安全起见不读取」): nothing is ever expanded or fetched, and a DOCTYPE that only names an external DTD (an EPUB 2 chapter's) is passed over unfetched; the container, package, encryption, manifest, content and meta parts admit no DOCTYPE at all. An EPUB with Adobe's `rights.xml` or Apple's `sinf.xml`, an encryption part naming anything other than the two font obfuscations, an archive entry flagged encrypted, or an ODT whose manifest names encryption data is `failed` with the new reason `encrypted` (「文件已加密或带有版权保护（DRM），AI7 不读取其中的文字」). The two reasons are what moves the wire: `MaterialIndexReason` gains them.
- **The indexer.** `MATERIAL_INDEXER_IDENTITY` is `ai7-material-index/2+ai7-docx-fflate-saxes/3`, and each build records its reader (`ai7-html-text/1`, `ai7-epub-text/1`, `ai7-odt-text/1`, `ai7-rtf-text/1`, each `+` the parser). A `/1` build stands for `/2` — it is what `/2` would build — except one refused as `format-unsupported`, so at the next start exactly the HTML, EPUB, ODT and RTF items are built again beside their `/1` refusals, and no other item's build, digest or 写作任务 pin moves; 最近完成 lists the standing builds.
- **Not provided.** PDF text, text recognition, machine 来源译文 and similarity vectors stay deferred under the Owner's option 乙 (S80a). The readers run synchronously on the service's thread, as the DOC and text converters do: a 32 MB RTF of Unicode escapes took about 0.2 s on the developer host, and a 12 MB page about 0.01 s.
- **Tests and J-15.** `tests/unit/material-formats.test.ts` holds each format's paragraphs, Chinese in each encoding, nested structure, and the bomb, ratio, entry-count, nesting, tag, text, paragraph, entity, DRM and password refusals; `tests/unit/material-index.test.ts` the `/1` builds that stand and the ones built again; `tests/service/material-index.test.ts` one imported item of each format yielding its segments, and a DRM EPUB and an entity-declaring page refused with their reasons. J-15 gains `knowledge-library-index-formats`: the runner's synthetic EPUB arrives through the real picker and its card reads `中文 · 3 段 · 1 个标题 · 文件自带标题「合成电子书」`, `已提取 30 字`, and three paragraphs of anchors in spine order. `GATE_JOURNEYS` is unchanged, and no `window.ai7` member was added.
