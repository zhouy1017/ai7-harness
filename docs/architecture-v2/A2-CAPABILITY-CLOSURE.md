# A2 Harness Capability Closure matrix

Status: **Issue #4 noncanonical A2 exact-artifact result — verdict: `Closure not proven`. Stable `0.149.0` x64 App Server is the sole closure subject; no production dependency, maintenance form, or implementation is selected. No Codex Capability Gap is asserted.**

This document answers the A2 question: *does one exact open-source Codex surface, together with narrowly named AI7-owned adapters that do not reproduce a second generic loop, satisfy every load-bearing row of Harness Capability Closure for AI7?*

The answer is **no, not on the admitted evidence** — and, critically, **not because Codex was shown to lack anything**. Twenty-four load-bearing rows are Unknown, two are Experimental by official statement, and seventeen are Candidate. Zero rows are Proven. Zero are Verified Codex Capability Gaps.

Every source ID resolves in the [A2 Evidence Register](./A2-EVIDENCE-REGISTER.md). Every row with one of the four gap-register dispositions — Unknown, Experimental, Gap claim, or Verified Codex Capability Gap — is classified in the [A2 Gap Register](./A2-GAP-REGISTER.md); Candidate rows keep their exit tests in this matrix. The module and adapters named in the `Required AI7 adapter` column are designed in [A2 Codex Seam](./A2-CODEX-SEAM.md).

## Rules that govern this matrix

1. **The row set was re-opened, re-derived, and then frozen before re-scoring.** The first exact-head review disproved the claimed completeness of the previous set: four load-bearing requirements stated in the exact owner direction and dispatch had no distinct row. A correction may not preserve a known-incomplete set merely to preserve its old count. `CC-41`–`CC-44` were therefore added for subagents, provider fallback, Windows junction/reparse-point confinement, and offline startup; the corrected forty-four-row set was then frozen before any row was re-scored. No row was added or removed after that freeze to change the verdict.
2. **Allowed dispositions** are exactly **Proven**, **Candidate**, **Experimental**, **Unknown**, **Gap claim**, **Verified Codex Capability Gap**, and **Not applicable**. No other value appears.
3. **Missing documentation, an undiscovered seam, or an unrun test is never a verified gap** (`S-A2-06`). It is Unknown.
4. **A closure pass requires every load-bearing row Proven against one coherent exact surface.** Candidate, Experimental, Unknown, or Gap claim fails the pass **without** thereby proving a Codex gap.
5. **A maturity ceiling applies.** Because `S-A2-02` states that "The app-server command and WebSocket transport are experimental and aren't supported for production workloads," no row scored against the app-server surface may exceed **Candidate** for a production role, whatever its documentation quality. U2 (`S-A2-12`) accepts that unsupported status as bounded risk for the exact subject but does not change the vendor fact or raise any evidence disposition. `CC-02` and `CC-03` remain Experimental.
6. **Static evidence is not runtime evidence.** The two version/help observations (`P-A2-01`, `P-A2-02`) concern a different installed `0.147.0` binary. The corrected selected-package observation (`P-A2-03`) matched official `0.149.0` bytes and recorded bounded archive/trust/legal facts without executing a downloaded binary. No protocol/schema generation, startup, handshake, runtime-behavior, or closure probe ran.

## Original blocker transitions and remaining blocker

**BLK-A2-01 — resolved prerequisite, not erased history.** X2 (`S-A2-13`) selects stable tag `rust-v0.149.0`, annotated tag object `a4e15bf371341b067c8278d3b70b1a8c7b3d793e`, source commit `758ef40f50c1a458425c7cfbf1eb12cbc07af0b0`, and asset `codex-app-server-package-x86_64-pc-windows-msvc.tar.gz` at SHA-256 `580207baa5ecabb8e42fd734bdb774ffcd82709ccd60bff8fa812b1b83962e28` as the sole closure subject. `S-A2-14` and `P-A2-03` verify the official channel and matching bytes. The former two-surface mismatch remains preserved evidence, especially for the missing exact-version support link, but it no longer means no artifact exists. `CC-01` is Candidate, not Proven: the rest of the matrix has not closed and U2 imposes the Candidate ceiling.

**BLK-A2-02 — owner-risk prerequisite resolved as U2; maturity remains Experimental.** `S-A2-01` recommends app-server precisely for AI7's shape, while `S-A2-02` says the App Server command and WebSocket transport are experimental and unsupported for production. These remain simultaneous facts. U2 (`S-A2-12`) records **Accepted Unsupported Dependency Risk** for the exact subject under fail-closed controls, suspension conditions, and an exit plan. It does not turn either `CC-02` or `CC-03` into Candidate or Proven, map the moving warning to exact release `0.149.0` as vendor evidence, or select the dependency for production.

**BLK-A2-03 — The narrow-tool-surface requirement is unproven, in the direction AI7 defined as decisive.** `S-A2-09` requires that an editorial Run receive no generic shell, roaming filesystem, or arbitrary network tool, and states the standard explicitly: *absence from the dependency graph is a stronger guarantee than absence from the wiring.* The admitted evidence shows the opposite shape. `S-A2-02` and `S-A2-03` document `thread/shellCommand`, which "runs outside the sandbox with full access"; `process/spawn`, which starts a process "outside sandbox"; `command/exec`; a full `fs/*` family operating on absolute paths; `marketplace/*` and `plugin/install`; and agent-produced item types `commandExecution`, `fileChange`, and `webSearch`. Sandbox policies and approval policies **constrain** these; nothing in the admitted evidence shows they can be made **absent**. That is a genuine Unknown of the most load-bearing kind — and it is explicitly *not* a gap, because the tool-registration surface in the exact source was not inspected (`S-A2-10`).

## What the evidence does support

Non-closure is not a negative result about Codex. The admitted evidence supports a **strong Codex-first architecture candidate**:

- The official integration recommendation matches AI7's shape exactly — an agent embedded in a product, with persistent conversations, streamed events, interruption, host-exposed tools, and host-answered approvals (`S-A2-01`).
- The ownership split OpenAI documents matches the split AI7 already requires: the host keeps "the interface," "context and tools," and "operational boundaries," while the harness owns "the agent loop, conversation state, streamed activity, and tool interaction" (`S-A2-01`). AI7 does not have to argue for its own authority boundary against the vendor's model; the two agree.
- The documented default transport — stdio JSONL over JSON-RPC 2.0 (`S-A2-02`, `S-A2-03`) — is the **only** transport compatible with AI7's accepted IPC rule, which permits stdio or a Windows named pipe and forbids a TCP listener (`S-A2-09`, ADR 0024). WebSocket is excluded as a TCP listener; Unix socket is not a Windows target. The default and the only admissible choice coincide, which removes a design argument rather than creating one.
- Seventeen load-bearing rows now sit at Candidate. `CC-01` and `CC-39` join the original fifteen because X2 plus the matched official acquisition makes the exact closure subject concrete and obtainable; neither transition proves runtime behavior or relaxes U2's Candidate ceiling.

The former surface-identity and risk-appetite prerequisites are resolved as X2 and U2 without erasing their evidence history. Closure remains blocked by the two Experimental maturity rows and twenty-four Unknowns, with tool-surface exclusion (`CC-16`–`CC-19`) still the highest-leverage remaining evidence area. None is a demonstrated Codex limitation.
