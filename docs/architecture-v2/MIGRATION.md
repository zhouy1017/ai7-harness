# V2 migration direction

Status: **frozen design reference as of `dev@4c50ce31b0f15ff2bfadd2af17fc914c317e0f22` under [ADR 0064](../adr/0064-reweight-repository-development-toward-value-first-delivery.md); design-to-implementation direction executed only through plan slices**

Migration preserves AI7's product and domain model, **preserves and reshapes the DeepSeek Harness baseline** rather than removing it, adds the accepted Model Role bindings and provider boundary, keeps Codex material as non-runtime reference, and removes proof machinery and legacy runtime/UI assumptions. This is selective reuse, not a history merge or wholesale source copy.

## Retain

- One Chinese-first Standalone AI7 product on Windows and macOS, the exact AI7 name, professional publishing audience, Word exclusion, and the two existing Windows-specific channels.
- Book, explicit Source Version acquisition and Source Acquisition Records, Series Knowledge candidate/item/promotion/revision and versioned exclusion semantics, manuscript, revision, branch, journal, checkpoint, recovery, projection, retrieval, and Exact Fetch semantics.
- Deliverable-owned workflows and immutable Editorial Deliverable Revisions, artifacts, gates, decisions, signoffs, Milestone/Publication Versions, destination-independent delivery packages, Local Export Preparations and per-file receipts, versioned Maintenance Cases, and the seven shared phases.
- Task Intent, Execution Plan, Plan Envelope, Run Record, Task Ledger, Execution Binding, Harness Execution Span, and Resume/Retry/Redo/Replay meanings.
- Named authority, proposal-first mutation, the single-use exact AI7 Apply boundary, Effects, receipts, ambiguity handling, privacy, credentials, provider resolution, capabilities, policies, learning lineage, and factual-verification behavior.
- **DeepSeek Harness as the one production Primary Agent Harness**, composed inside the AI7 Node service: the full composition machinery behind a narrow tool surface, the pinned exact package subset with a committed lockfile, no `@deepseek-ai/dsh` CLI aggregate, AI7-owned scheduling and concurrency, the AI7 Capability Facade, dual grant enforcement, the two ledgers, and the exclusion of generic shell, roaming filesystem, and arbitrary network tools.
- Provider-neutral Model Roles declared by Task Intents, native DSH artifacts, DSH Analysis Contracts, and AI7 services, with the accepted DeepSeek defaults and an explicitly configurable alternative frontier binding.
- Native DSH Skill, Plugin, Bundle, Profile, and Agent Preset carrier identities; AI7-owned provenance/compatibility/scope/Authority Ceiling/audit/rollback overlay; immutable Source Skill Snapshots and derived imported-Skill working revisions; inert update candidates; and distinct acquisition, validation, scoped enablement, exact Run activation, and Apply boundaries.
- Ranked retrieval plus Exact Fetch for targeted context, alongside deterministic Coverage Manifests/Analysis Units, typed provenance-preserving reduction, durable immutable Manuscript Analysis Result Set Revisions, independent coverage/closure/freshness/assurance state, Background Analysis Enrollment, and analysis feedback/metrics for comprehensive work.
- The Electron main/renderer/Node-service topology, ProseMirror bounded editor, Agent Data Root outcomes, and one provider-free E2E journey surface executed on Windows and macOS.
- Exact `SampleBooks/sample1.docx` as the standing cross-Issue compatibility baseline for manuscript-dependent supported journeys. Its discovered fidelity signals resolve truthfully through preserve or explicit initially-unselected degrade behavior; downstream modules consume imported state rather than each reparsing DOCX.
- Surface-neutral user outcomes in the A1 product-consistency and evidence-crosswalk documents. The crosswalk is historical design reference, not a gate.
- Codex material as the non-runtime **Codex Interaction Model Reference** for interaction, host-boundary, and extension-design ideas.
- Authorized predecessor code, documentation, tests, and fixtures only when an implementation task selects an asset and records its provenance, sanitization, and applicable third-party/provider obligations.

- The parallel AI7 Task Skill Manifest/Package/Candidate/Installed Version/Harness Skill Projection runtime model and monolithic Admission State as current owners; their responsibilities move to native DSH artifacts plus separate AI7 seams.
- The development-only rare-Plugin/threshold/static-Local-Plugin-Pin product lifecycle from superseded ADR 0042. Core DSH dependencies remain exactly pinned, but supported native product artifacts use the governed acquire/validate/enable/update/rollback lifecycle.
- The old Standalone and Word UI implementations, layouts, editors, monolithic renderer, and component model.
- The predecessor Python runtime, active Operation/Operation Event/`operationRuns` model, and non-allowlisted legacy production data.

- Separate validation machinery: tiered/nightly workflows, exact-head review gates, unit/contract/property/coverage gates, request fingerprints, performance/security/provider/package/plugin/provenance/release-proof gates, and release receipts.
- Codex branding, Codex Desktop GUI source/layout/assets, coding presets, and generic terminal/chat surfaces.

## Current authorized sequence

These are sequencing directions, not validation gates.

1. **Keep the normalized `dev` baseline.** Issue #20 promoted root authority, repaired routing and status, and recorded the exact frozen-source allowlist without merging `design-doc` history.
2. **Preserve immutable policy history and add only the scoped successor selection.** Provider v1 remains the byte-identical no-transmission development/CI record. Provider v2 remains byte-identical and makes only exact `sample1` fixture recording policy-eligible under ADR 0044. New Provider v3 is the ordinary-production default-deny record. Active-set v3 pins the closed trusted development/CI→v1, fixture-recording→v2, ordinary-production→v3 map plus unchanged External Export v1. It makes no selector, Provider, adapter, credential or dispatch implementation claim and is repository-current only in an exact integrated `dev` commit containing it.
3. **Keep the integrated provider-free behavior as current implementation.** J-01 begins from a fresh checkout and exact `SampleBooks/sample1.docx`, supports standalone empty-Book creation plus new-Book and first-Manuscript existing-empty-Book import, presents relationship-specific Review Before Import with its full server-derived fidelity projection and initially-unselected complete-set degradation acceptance, preserves exact Book/dimension identity on first-Manuscript import, atomically creates the applicable source/manuscript/workflow/import record graph, opens the first bounded 32-block manuscript window, confirms a durable Edit Journal, and includes exact identity disclosure plus interrupted-import continuity/reconciliation. The built-in native Profile and separate AI7 projection are validated and durably pinned through exact schema-v8 legacy migration. Complete provider-free J-02 supplies 10M bounded editing, and complete provider-free J-08 supplies the Recovery Workspace. These journeys use the production-shaped Electron main, renderer and separate Node service with a dormant composed Harness boundary and one root bootstrap/build/launch/E2E command surface. The implementation remains neither full J-01 nor the broader Book Workspace; it has zero configured Providers, Agents, Sessions, retrieval/Exact Fetch, covered analysis/results, Enrollment/analysis metrics, Proposal/Effect, or AI7 Apply behavior. `r1` and first-window-only import projection remain bounded J-01 limits rather than the production design. It does not claim every accepted branch or full J-01.
4. **Keep sample1 as the standing compatibility baseline.** Issue #36 extends the existing provider-free journey to import exact `sample1` and truthfully disclose its current `inline-styles:266` and `sections:1` degradation signals through one explicit decision. This remains a cross-Issue invariant, not one giant scenario or full-J-01 claim.
5. **Defer real recording until the model-dependent product path exists.** Immediately before any future transmission, the Commander requests human intervention to freeze the exact Provider/model/endpoint/adapter/role/prompt/budget/Credential Reference and then-current terms. Recording remains local-only, human-attended, one-call and no-fallback through the actual Harness/provider/final-egress path. Raw material stays protected outside repositories; a reviewed fixture needs another Issue and pull request.
6. **Keep Issue #86 as documentation normalization only.** Native artifact lifecycle, Provider v3 selection, covered analysis/results, Enrollment/metrics, Agent Workspace and AI7 Apply are accepted design seams, not product code. Do not install a dependency/artifact, call a Provider, add manuscript material, decompose implementation Issues, or create/integrate a pull request under this authority.
7. **Continue only through later separately accepted vertical outcomes.** Task/Run/provider/model/export behavior, artifact/catalog management, analysis/results, Background Analysis Enrollment, Agent Workspace, additional journeys, packaging and launch selectors each require their own current authority and bounded Issue. Provider policy eligibility grants no implementation or dispatch authority, External Export v1 grants no implementation authority, and no network export is admitted by this document.

The single logical standing E2E suite runs on Windows and macOS and grows with these complete user journeys and with regressions for observed bugs. Each platform execution starts from a fresh checkout, uses the same documented root build path, and enters its no-network product interval only after exact dependency restoration. Ordinary implementation diagnostics stop when the bug is understood; they do not become new permanent gates by default.
