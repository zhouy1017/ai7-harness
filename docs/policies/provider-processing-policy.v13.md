# Provider Processing Policy v13

This is the human projection of [the immutable v13 JSON](provider-processing-policy.v13.json), validated by [its schema](provider-processing-policy.v13.schema.json). It is the first document for the `ordinary-production` scope since [v6](provider-processing-policy.v6.json), which it directly succeeds, and it is written in the same schema family as developer-live [v12](provider-processing-policy.v12.md) so the launch resolver reads both the same way. Activation requires the exact [active-set v10](active-policy-set.v10.json) pin and a trusted launch that names the scope with `--trusted-operational-scope ordinary-production`; an internal active label grants no dispatch authority. Authority: [ADR 0046](../adr/0046-separate-provider-processing-by-operational-scope.md), [ADR 0089](../adr/0089-adopt-orca-dispatch-and-value-first-live-model-delivery.md) and the Owner's 1.0.0 scope ([milestone scope](../development/milestone-1.0.0-scope.md)).

## In plain words

This policy lets the editor use AI7 on their own manuscripts on their own computer, with their own model-service account. Nothing runs by itself.

- **The editor's own credential.** The credential is the editor's own key for the model service they chose. It lives in the protected secret store on their computer and is released only to the final request adapter. The development key file, the development enrollment helper, and everything that belongs to developer testing are never read.
- **The editor's own data location.** The manuscripts, house knowledge, results and records stay in the data location the editor's installation uses. The policy allows the text of their own manuscripts, 资料库 material and finished deliverables to be sent to the model service they configured, and nothing else. Notes, internal remarks and the names and roles of the house's people are stripped first; the author's information and the house name may be sent.
- **The kinds of work admitted.** Seven rules, the same kinds as developer-live v12: baseline manuscript analysis; editorial dialogue (ask, continue, regenerate on a passage the editor selected); review, including 跨交付物一致性 (cross-deliverable consistency); writing; the three evaluation contracts (AI7 初评, 审稿意见, 按我的评分重写评语); 润色这段; and 稿件冲突 › 基于当前稿件重新生成建议. Every rule is eligibility only: it authorizes no Run, no Apply, no export and no publication, and a result is a Suggestion or a record until the editor applies it as a separate act.
- **What starts work.** Only a new Task the editor starts, authorized directly for a Run, or one foreground action (a question, a polish, a conflict regeneration). Planned kinds need a Plan Envelope and Run Authorization first.
- **Refused origins.** Background analysis enrollment, idle, scheduled, import-triggered and cross-Run dispatch are refused (there is no background rule in this document, by the Owner's decision of 2026-10-09, until background enrollment can transmit); a matching active Default Execution Rule is refused as an origin, including for writing quick start; hosted and CI execution are refused. Web search and every web tool are refused (`webSearchToolAllowed: false` everywhere), as are 事实核查, 学术道德与引用, 出版政策与风险 and 书系一致性 (Series Knowledge).
- **The two routes the editor can choose.** Opening the model-service settings, the editor may connect OpenCode Go (`opencode-go`, `deepseek-v4.1-flash`, slot `opencode-go`, `https://opencode.ai/zen/go/v1/chat/completions`) or the official DeepSeek platform (`deepseek-open-platform`, `deepseek-flash`, slot `deepseek-api-key`, `https://api.deepseek.com/chat/completions`). OpenCode Go is the default. One chosen route serves both bound roles. Every other declared provider document stays declared only (尚未支持) and cannot be selected.
- **Never the development key, cache or ledger.** An ordinary-production request never consults the Provider Result Cache or the Provider Test Ledger, never replays an earlier answer for an identical request, and never emits a fixture. Each new Task the editor starts performs its own real model work, including a deliberate repeated question.
- **If the account runs out.** The model service's account or quota limit ends the Run or attempt as 模型服务账户限额. There is no retry, no fallback to another Provider or spending source, and no second model.

## How the rules are shaped

Each rule is written like a v12 rule, with these production terms. Every term of the schema is required and the schema is closed, so an unknown or missing term makes the whole document unreadable and the launch denies.

| Term | Meaning in v13 |
| --- | --- |
| `purpose` | `ordinary-production-model-processing` for every rule. |
| `authorityOrigin` | The newly user-initiated Task (`newlyUserInitiatedTaskRequired`) with direct Run authorization for planned kinds; the foreground terms for dialogue, 润色 and conflict regeneration. `matchingActiveDefaultExecutionRuleAllowed`, `backgroundAnalysisEnrollmentAllowed` and `idleScheduledImportTriggeredOrCrossRunDispatchAllowed` are `false` on every rule. |
| `executionMode` | `humanAttended: true` (the editor is at the computer); `developerHostOnly`, `ciAllowed`, `hostedAllowed`, `scheduledAllowed` and `backgroundAllowed` are `false`. |
| `source.admittedInputs` | `user-owned-manuscripts-and-house-knowledge`: the editor's own manuscripts and the house's knowledge, with `privateManuscriptAllowed: true`. `materialReferencesAllowed` is `true` for review, writing and evaluation only; `editorialDeliverablesAllowed` is `true` for review only; `seriesKnowledgeAllowed` is `false` everywhere. |
| `allowedOutboundDataCategories` | v12's categories for the rule, plus the three production classes `unpublished-metadata`, `unpublished-excerpts` and `unpublished-full-content`. The launch projection retains every category so the production Egress Gate can check each binding against its rule. |
| `providerBinding` | `bindingSource: "user-configured-role-binding"` and `allowedRoutes: ["opencode-go", "deepseek-open-platform"]` instead of one fixed route, endpoint and model. `exactProviderBindingRequired: true`: the editor's configured binding is frozen into the plan and the Egress Gate checks it exactly. `fallbackAllowed: false`, `secondModelAllowed: false`. |
| `authorizationPreconditions` | For planned kinds: `unsetRunBudgetCeilingAllowed: true` (the editor may leave the ceiling unset); when a ceiling is applied the default is 30,000 tokens per frozen unit, computed after the Coverage Manifest freezes, as in v6. Foreground rules have no Run ceiling. |
| `transmissions` | The same bounds as v12 for the kind, with `identicalRequestReplaysFromProviderResultCache: false`; the development-test term `repeatedTestItemIdentifierAllowed` does not exist here. |
| `capture` | `providerResultCacheAllowed: false`, `fixtureEmissionAllowed: false`, `uploadAllowed: false`, and the new `developmentCredentialCacheAndLedgerConsulted: false`. |
| `providerAccountLimit` | `quota-exhausted` ends the Run or attempt; no retry, fallback or second model. |

Role bindings: the Main Editorial Role and the Fast Interaction Role are `bindingState: "user-configurable"` with `defaultBinding: "opencode-go"` and `allowedBindings` listing the two routes above. The Difficult Escalation Role and the Frontier Model Role are `unbound-by-default`, user-configurable among the same two bindings, and named by no rule. A configured binding never authorizes a transmission on its own (`userConfiguredBindingAuthorizesTransmission: false`) and never opens a fallback (`fallbackAllowed: false`). The credential boundary adds `credentialOwnedByTheEditor: true` and `developmentCredentialFileReadAllowed: false`.

## How a launch uses it

The launch resolver verifies this document byte for byte against the active-set pin. If the editor has not yet configured a model service, the projection reports `bindingState: "setup-required"` and admits no rule, so nothing can be sent. Once the launch supplies the editor's configured binding, and only if it is exactly one of the two allowed bindings, every admitted rule is filled with that route, endpoint, model and credential slot (`bindingState: "configured"`). Any other binding is a denial. Provider eligibility is not Run Authorization, Apply, export, learning, publication or public release permission.
