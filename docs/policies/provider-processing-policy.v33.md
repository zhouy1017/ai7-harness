# Provider Processing v33

Wave 23 Stage 1 / #1281, under the Owner intent in #1279, replaces per-model admission with channels. The [canonical JSON](provider-processing-policy.v33.json) and [closed schema](provider-processing-policy.v33.schema.json) are selected by [active set v24](active-policy-set.v24.json). [v32](provider-processing-policy.v32.json) and set v23 retain their exact bytes and remain readable historical identities.

Each role and the explicit connection test declares `allowedChannels`: route, endpointHost, protocolFamily and credentialSlot. The runtime resolves the exact route endpoint and admits arbitrary selected model IDs within that channel. Chat Completions, Responses, Messages and generateContent inherit implemented text, streaming and function tools. Catalogue rows retain optional context/reasoning/structured-output settings and historical evidence; neither a catalogue entry nor a per-model live test is required for runtime text, stream or tool admission. Explicit connection tests remain diagnostics.

Each Run retains its exact model, route, endpoint, credential reference and policy identity. Egress compares requests with that frozen binding; changing settings does not retarget an existing Run. Credential release remains slot-bound. Existing source scopes, research declarations, local tools, Global Agent tools, search backend/fallback bindings and budget semantics remain unchanged. This policy grants no Apply, export or release authority. Failed factual-recheck readiness leaves onceKey unused; missing model/search setup is explained directly in Chinese.

Provider-free tests establish adapter and admission behavior. They do not establish live account availability or successful live validation where credentials are absent. Live model discovery and independent role selection are #1282. The prior policy's search fallback, original-field processing, background enrollment and source/recipient limits carry forward unchanged.
