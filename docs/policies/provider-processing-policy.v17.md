# Provider Processing Policy v17

This is the human projection of [the immutable v17 JSON](provider-processing-policy.v17.json), validated by [its schema](provider-processing-policy.v17.schema.json). It directly succeeds the `ordinary-production` document [v15](provider-processing-policy.v15.md) and is written in the same schema family as developer-live [v16](provider-processing-policy.v16.md), so the launch resolver reads both the same way. Activation requires the exact [active-set v12](active-policy-set.v12.json) pin and a trusted launch that names the scope with `--trusted-operational-scope ordinary-production`; an internal active label grants no dispatch authority. Authority: [ADR 0046](../adr/0046-separate-provider-processing-by-operational-scope.md), [ADR 0074](../adr/0074-admit-a-bounded-research-egress-and-a-runtime-factual-verification-policy.md), [ADR 0080](../adr/0080-assign-a-provider-route-and-model-to-every-task-that-transmits.md) §5 and §7, [ADR 0089](../adr/0089-adopt-orca-dispatch-and-value-first-live-model-delivery.md) and the Owner's decisions on web search (Issue #473, #883).

## In plain words

Everything v15 let the editor do with their own manuscripts, on their own computer, with their own model-service account, v17 still lets them do — the same eight rules, the same two model routes, the same redaction, ceilings and account-limit stop (see [the v15 projection](provider-processing-policy.v15.md)). The one change: review, writing, evaluation and the editorial dialogue may look things up on the public web through AI7's **websearch** and **webfetch**, using a search service the editor connects with **their own key**.

## What is newly allowed

1. **Who may search and fetch.** The same four rules as developer-live v16 turn the web switch on (`transmissions.webSearchToolAllowed: true`) and carry a `platformTools` block: **review** (its existing kinds plus **事实核查** and **学术道德与引用**), **writing**, the three **evaluation** contracts and the **editorial dialogue**. Baseline analysis, 润色这段, 稿件冲突 › 基于当前稿件重新生成建议 and enrolled background analysis stay without web.
2. **The editor chooses the backend and brings the key.** `websearch.selection` is `user-configured` among the five shipped backends in their recorded ranking order — TinyFish (the default), DeepSeek server-side search, Brave, Parallel and 博查. Each entry names the backend's id, host, endpoint and its search-connection slot (`search-tinyfish`, …), where the editor's own key is stored like a model-service connection; no development credential is ever named or read. A backend without the editor's configured key **cannot be selected for a Run** (`selectionRequiresCredential: true`), and configuring a backend alone authorizes no transmission (`userConfiguredBackendAuthorizesTransmission: false`).
3. **What leaves the editor's computer.** Only the model's own search query goes to the selected search host (`web-search-query`), never the manuscript's words as a query; webfetch requests only a public `https` page the model cited (`public-source-fetch`), at most **5,242,880 bytes** and **30 seconds** per page. Tool results are treated as public material (`toolResultCategory: "public-or-synthetic"`).
4. **Bounds.** One search query per Run unit; a unit that reaches **128** consecutive tool round trips ends as **联网核查未完成**. The Run Budget Ceiling, when the editor sets one, remains the only budget.

## What stays refused

The default is deny. Still refused: **出版政策与风险** (in no rule this wave), **书系一致性** (Series Knowledge), web search or fetch in background Runs and in the rules named above as without web, any backend the evaluation did not ship, hosted and CI execution (`hostedAllowed: false`, `ciAllowed: false`), the Provider Result Cache, the Provider Test Ledger and the development credential, scheduled, import-triggered or cross-Run dispatch outside an active matching enrollment, and every other task kind.

## How a launch uses it

The launch resolver verifies this document byte for byte against the active-set pin and reads every rule whole, the `platformTools` block included: its backend list must be exactly the search backend registry's shipped set. Until a model service is configured the projection admits no rule (`bindingState: "setup-required"`); once the launch supplies an allowed binding, each admitted rule also carries `webSearchToolAllowed` and `platformTools` (selectable backends with id, host and slot, `selectionRequiresCredential: true`, the webfetch bounds and the breaker), or `null` without web. Provider eligibility is not Run Authorization, Apply, export, learning, publication or public release permission.
