# AI7 policy documents

Versioned JSON policies, their schemas and their human projections are immutable runtime artifacts. An active-policy-set selects exact paths and SHA-256 digests; a document's internal `lifecycleStatus: active` does not activate it for a repository target. Trusted build/launch authority binds one operational scope. Missing, unmatched or unknown pins deny processing.

[ADR 0089](../adr/0089-adopt-orca-dispatch-and-value-first-live-model-delivery.md) owns the newly approved product target and development/business boundary; [Orca dispatch](../agents/orca-dispatch.md) owns repository agents. Those operating rules do not mutate a runtime policy or make a target model callable.

The ten rules:

- **Baseline manuscript analysis**, exactly as v9 admitted it, under the required Run ceiling.
- **Enrolled background analysis** (since v14): baseline analysis dispatched by an active matching Background Analysis Enrollment in idle or quiet time, one exact Run per dispatch, only within the enrollment's mandatory tokens ceiling (split equally across a Series or all-Books enrollment's Books, remainder to the first) and at most the governor's capacity minus one background slots. It is the only rule that admits a background origin.
- **Editorial dialogue**: ask, 继续回答 and 重新生成 on a passage the editor selected. Each is one foreground attempt with one bounded payload of category `editor-selected-manuscript-excerpt`, on the Fast Interaction Role; it has no Run, so no Run ceiling. It keeps `webSearchToolAllowed: false`, no platform tools and its 未联网核查 state.
- **Review** of 错别字与规范用语, 体例与格式 and 文学性与表达改进, run like baseline analysis under the same Run ceiling, and since v12 also **跨交付物一致性** (cross-deliverable consistency) over frozen Material Reference excerpts and the Book's finalized editorial deliverables; since v14 a review Task may also start under its matching active Default Execution Rule (审阅 快速开始); since v16 the review rule also lists **事实核查** (`editorial-review/factual-review` and its executor `factual-review`) and **学术道德与引用** as its kinds and may use the platform tools below; since v22 / v23 it also lists **书系一致性** (`editorial-review/series-consistency`) over Series Knowledge (see below). 出版政策与风险 stays refused under developer-live; ordinary-production v26 declares its eligibility without web, as described below.
- **Writing** (`writing`, 写作任务): a Production Document drafted from the Book's units, its frozen metadata and synopsis, the house's 范例 and the editor's own brief, with one book-level synthesis turn, on the Main Editorial Role under the same Run ceiling. Writing also admits quick start under a matching active Default Execution Rule; background origins remain refused. Since v12 writing may also carry frozen Material Reference excerpts, sent only after the consuming service's consumption re-check. Since v16 it may also use the platform tools below.
- **Evaluation**: the three implemented contracts — AI7 初评 scores (`evaluation`), 审稿意见 (`readers-report`) and 按我的评分重写评语 (`evaluation-rewrite`) — on the Main Editorial Role, planned like writing; since v12 they may carry frozen Material Reference excerpts under the same re-check, and since v16 they may use the platform tools below (评估 · 市场 needs the web).
- **润色这段 and 稿件冲突 › 基于当前稿件重新生成建议** (`editorial-polish`, `conflict-regenerate`): one foreground editor action each on the editor's own manuscript words (a selected passage, or a conflict region and its competing draft), on the Fast Interaction Role, with separate rules: polish uses `editor-selected-manuscript-excerpt`; conflict regeneration uses `manuscript-conflict-region-excerpt` (base, current and proposal text of one conflict unit). Each allows one request per invocation, no synthesis, reflection or assurance sample, and no applicable Run ceiling. Their output is a Suggestion only and applies nothing.

**Model-initiated clarification (since v14).** Every rule that admits a Run — baseline analysis, review, writing, the three evaluation contracts, background analysis and custom analysis — lets the model ask the editor at most one question per unit: that unit waits while the others continue, the answer turn is counted in the rule's transmission bound (`plusClarificationAnswerTurns`), and after 24 hours without an answer the question is unanswered, the Run continues and the Run Report discloses it. Editorial dialogue, 润色 and conflict regeneration declare no model question.

**Platform tools (since v16).** Review, writing and the three evaluation contracts turn the web switch on (`webSearchToolAllowed: true`) and name AI7's own **websearch** and **webfetch** in a `platformTools` block; dialogue, baseline analysis, 润色, conflict regeneration and enrolled background analysis stay without web. websearch goes through the one backend the user selects among the five the search backend evaluation shipped (#883), in its recorded ranking order — TinyFish (default), DeepSeek server-side search, Brave, Parallel, 博查 — each named by id, host, endpoint and broker slot; the launch checks that list against the search backend registry. Only the model's own query reaches the search host (`web-search-query`); webfetch fetches only a public page the model cited (`public-source-fetch`), at most 5,242,880 bytes and 30 seconds per page; one query per Run unit; a unit ends as 联网核查未完成 after 128 consecutive tool round trips. Executing the tools, selection, the per-Run freeze and host admission belong to the platform-tools product slice.

**House review preference (since v20 / v21).** The review rule of each scope (`developer-live-public-samplebook-reference-free-review`, `ordinary-production-review`) alone names the outbound data category `house-review-preference-excerpt` (本社审阅偏好摘录) and a `houseReviewPreference` declaration: derived only from the same house's judged review decisions, at most 12 lines and 200 graphemes in total per request, attributed to a record version, never manuscript text and never author or editor names, and only from admitted public-or-synthetic Books under developer-live or ordinary-production sources under ordinary-production. It is eligibility only; no rule composes the block.

**Custom analysis (since v22 / v23).** v22 and v23 add a tenth rule per scope, `developer-live-public-samplebook-custom-analysis` and `ordinary-production-custom-analysis`, for the editor's own custom analysis dimensions (ADR 0090 §4): the analysis kind family `custom-analysis/<dimension-id>` on the Main Editorial Role, planned like the baseline (a newly user-initiated Task with a plan envelope and a Run Authorization, bound to the Coverage Manifest's units, one model question per unit), with no cross-unit reduction or synthesis, no web, no platform tool and no local retrieval. The rule's `allowedTaskKinds` is the single literal entry `custom-analysis/*`, which admits every kind of that one family (one non-empty segment after `custom-analysis/`); it is the only family entry in any policy, and the launch resolver and `liveKindRule` read it through one shared `taskKindListed` helper. The rule names the outbound data category `editor-authored-question-template` (编辑自拟的单元提问模板) beside `public-or-synthetic` and states an `editorAuthoredQuestionTemplate` declaration: an editor-authored per-unit question from a 工序与规则 document, at most 400 graphemes, attributed to the dimension version, never manuscript text and never author or editor names, and never an override of AI7's contract framing. It is eligibility only; slice 7f composes the payload.

**Series Knowledge excerpts (since v22 / v23).** The review rule of each scope now states `source.seriesKnowledgeAllowed: true` (it is `false` on every other rule), names the outbound data category `series-knowledge-excerpt` (书系知识摘录) and a `seriesKnowledgeExcerpt` declaration: Series Knowledge item revisions pinned by the Run's frozen Series scope, at most 40 clauses of at most 300 graphemes each as 书系一致性 already bounds them, only items of the pinned Series, every frozen Series Retrieval Exclusion honoured, attributed to the item revisions, and only from admitted public-or-synthetic Books under developer-live or ordinary-production sources under ordinary-production. The review rule's last kind is `editorial-review/series-consistency`. It is eligibility only; slice 7b composes the clauses.

**Local tools (since v18).** Every rule that admits a model task kind names AI7's own **targeted retrieval** in a `localTools` block beside `platformTools`: the model may search, and Exact Fetch from, only the sources the Run was authorized to read — the pinned Manuscript Revision, the 允许参考 items at their frozen index version and the retained sources — and the tool sends nothing outside the process (`scope: "no-egress"`: no Egress Gate ticket, no host). A call returns at most 8 ranked candidates with anchors, a unit may make at most 5 calls, and a quotation or citation needs an Exact Fetch of the pinned revision (candidates are pointers, never certified wording, and never prove coverage); a unit that reaches 128 consecutive tool round trips ends as 检索未完成. Calls and tokens count into the Run Budget Ceiling, and the tool's results enter the model's context under the rule's existing outbound categories. Enrolled background analysis, the 来源译文 rule and custom analysis state the same block with `allowed: false`: no model-initiated retrieval in the background, nothing to search in a bounded translation, and no tools for a custom analysis dimension. Executing the tool, its candidates and Exact Fetch belong to the retrieval product slice (ADR 0026, ADR 0047).

**来源译文 (since v18).** v18 and v19 add a ninth rule per scope, `developer-live-public-samplebook-material-translation` and `ordinary-production-material-translation` (kind `material-translation`): one foreground editor action on the Fast Interaction Role, one session and one bounded payload over a frozen 资料库 excerpt — outbound category `public-or-synthetic` under developer-live (an admitted public text) and `frozen-material-reference-excerpt` under production — with no Run ceiling, no web, no question and no retrieval; the output is a labelled machine translation that replaces nothing. The research review rule of both versions also states `sourceTranslationAllowed: true`, the term that admits translating a retained external source's passage (the product acts on it under developer-live); no other rule states it.

## Operational boundaries

- Development agents may autonomously execute necessary new validation within the approved rules, existing product Run budget semantics and subscription limits. [ADR 0067](../adr/0067-authorize-the-opencode-go-development-credential-with-live-once-testing.md) owns protected credential handling, exact response replay, similar validation-family evidence reuse, unknown outcomes and original capture provenance. No per-item attendance, new batch approval, daily quota or fixed call-count cap is introduced.
- Development captures remain outside every repository. Only reviewed, sanitized fixtures enter Git. The development key and cache are never inherited by ordinary production.
- Each new actual user Task performs its own model-dependent work, including deliberate repeated questions. Development live-once rules and similar-test fixtures never answer or refuse those business Tasks. Product Resume, incremental analysis and explicitly reusable completed steps retain their own semantics.
- CI, the hosted Gate and ordinary automated regressions call no LLM and receive no product Provider credential.
- Provider Processing never grants Apply, external export, publication or public release. Export still requires the exact user-selected local destination, payload and Effect Approval, with a receipt or classified outcome. Notes remain default-off; retained external sources and Evidence Links do not export. Cloud, email and network destinations remain outside the local export policy.

## Immutable history and activation

Preserve every predecessor policy JSON, schema, Markdown projection and active-set manifest byte for byte.
