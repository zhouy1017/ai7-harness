# Policy documents

[ADR 0102](../adr/0102-retire-runtime-policy-locks-and-frozen-fixture-admission.md) implements the Owner's D2 and 2026-11-14 decisions: Provider Processing JSON, schemas, human projections and active-policy-set manifests are historical records. No policy document is selected or read by model launch, model egress, deterministic fixture admission or retained-analysis reading. Missing or changed historical bytes cannot refuse model processing. No policy JSON is bundled into the product.

`config/runtime-execution-defaults.json` supplies the existing task recipes, tool registrations, execution governor defaults, deadlines, search retry terms and budgets. Provider channel configuration owns wire protocols, endpoints and credential slots. The defaults are bundled and not editor-overridable: they are the v35/v24 task-composition projection, still consumed to register task kinds/origins, material flags, source envelopes, synthesis, clarification and tool schemas. Missing or mismatched compositions refuse; these checks and the execution safety limits stay. A missing flag must not close an otherwise implemented content path: ordinary-production 初评 accepts selected Series knowledge through its existing frozen read-only contract, and its unit/synthesis requests carry that context. Ordinary-production procedures carry their editor instructions under the existing frozen contract; task-profile readers unwrap the procedure envelope using its recorded base digest (#1476). Source pins, exclusions, exact prompt derivation and budgets remain required. They do not select a policy or restrict the words or configured model accepted by an implemented task. Tests keep their search-backend declarations equal to the backend registry. The existing exact-byte/SHA-256 Public SampleBook guard remains for developer-live and repository source admission; local development-ci fixture analysis has no such source restriction. Historical identity readers remain for old records; new records use the fixed `no-policy-lock` marker.

The `transport` record of the same file bounds every model request by what it waits for, not by how long its answer is (#1599). `firstByteSeconds` (600) runs from the send to the response headers; a whole-answer request (a Review, analysis or writing unit) is not streamed, so this is the longest generation tolerated, a dense chapter at a high reasoning effort included. `idleSeconds` (90) is the silence allowed between received bytes once the headers are in: any byte restarts it, reasoning frames and keep-alive comments too, so a streamed answer is never cut while it keeps arriving. `totalCeilingSeconds` (3600) is the safety net over both, so that one request cannot hold an execution slot or a Run for ever; it is far larger than any answer observed (unit answers typically took 40–75 s; two of 147 measured calls were still running at 180 s). A request that reaches a bound after it was sent ends as an unknown outcome and is never resent on its own. Developer-live and any caller without a projection read the same record. Predecessor policy documents v26–v35 still state `requestDeadlineSeconds: 180`; that is history, not read at runtime. Model discovery (10 s), public-page fetches (30 s), search calls and platform tools each keep their own deadline, which covers the whole exchange, so no request through the model-service transport relies on a hidden default timer.

External Export v1/v2 are retained history. Export remains a separate product effect: its existing preparation, approval, atomic write and outcome receipt owners keep enforcing the same eligibility and effect authority. The former export fingerprint no longer gates model processing; see ADR 0102 clause 4.

[Learning eligibility](learning-eligibility-policy.md) and [factual verification](factual-verification-policy.md) retain their domain design role. They are not selected runtime policy locks. Repository protected-material admission, development capture and record/reuse, credential isolation, provider-free CI and public-fetch network denial retain their own owners in [AGENTS](../../AGENTS.md) and the [CI boundaries](../agents/ci-test-boundaries.md).

All predecessor policy files are kept unchanged for named historical questions and persisted record interpretation. `node tools/validate-policies.mjs` can still inspect historical document/schema consistency locally; it grants no runtime permission and creates no gate.
