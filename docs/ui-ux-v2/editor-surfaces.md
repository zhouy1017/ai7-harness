# AI7 编辑面规范（执行标准）

Status: **frozen design reference under [ADR 0064](../adr/0064-reweight-repository-development-toward-value-first-delivery.md), adopted as the execution standard for every editor-facing surface by [ADR 0077](../adr/0077-adopt-the-editor-facing-surface-specification-as-the-execution-standard.md) on 2026-09-09.** 本文是实现编辑面时的执行标准：它规定每一屏的最终形态、状态、措辞、需要的数据与对应的后端能力。它不是实现证据；实现状态只记在根 `PROGRESS.md` 与 [E2E journeys](../development/e2e-journeys.md)。交付顺序只记在 [development plan](../development/development-plan.md)。

## 0 · 总则

### 0.1 权威与阅读方式

- 本文与 [`requirements.md`](./requirements.md)、[`information-architecture.md`](./information-architecture.md)、[`interaction-spec.md`](./interaction-spec.md)、[`visual-direction.md`](./visual-direction.md)、[`journeys.md`](./journeys.md) 同为冻结参考；条款冲突时以 ADR 0077 命名的条款为准，其次以本文为准。本文引用条款只写编号（如 PLAN-011），条款正文在 `requirements.md`。
- 每屏附一个可点击的原型（Artifact 链接）。原型是证据与讨论工具，不是权威；原型与本文不一致时以本文为准。原型内容全部为合成示例，书名只用已准入的 Public SampleBooks。
- Owner 的决定按日期引用原话；引用的是决定，不是措辞的最终形式——最终措辞是本文「用词」小节里的目标词。
- 本文用中文写，产品标签用中文；英文规范术语在首次出现时加括号，定义归各上下文（`docs/ui-ux-v2/CONTEXT.md`、`docs/domain/editorial/CONTEXT.md`、`docs/domain/execution/CONTEXT.md`），本文不重新定义。

### 0.2 三条总原则（来自 Owner，2026-09-08 / 09）

1. **稿件优先**。「对于中文编辑而言，点开一个稿件，最优先需要被看到的就是上次以工作的稿件本身」——打开有稿件的图书进入稿件上次位置；工作概览是目的地，不是入口（RET-002、IA-012）。
2. **编辑语言，决定层与技术层分开**。「我现在看到的 UI 依旧不是一个中文编辑应该看到的，它更像程序员、工程师或者运维专家的操作面」——每个面先说编辑要决定的事，精确身份收进一处「查看技术详情」（LAYER-001 ~ 008）。任何处置类选项不预选。
3. **少打扰**。一次性提示用悬浮窗自动消失；不常用的动作收进菜单；任务入口按需呼出；精简模式优先；能自动的（范例归入、索引、备份）不问。

### 0.3 外壳与视觉

- 一个两层侧栏（IA-006/007/010/012）：全局五项 `待我处理 · 书库 · 书系 · 知识库 · 质量与学习`；置顶与最近的图书；当前图书三组 `工作（稿件 / 审阅 / 评估 / 交付物）· 处理（发现）· 资料与记录（分析 / 来源与证据 / 工作概览 / 历史与恢复）`；底部 `设置`。可收起，收起状态记住；上下文头左端有收起 / 展开按钮。
- 上下文头：书名（宋体）· 位置 · 一句状态；右端是本页动作与「已写入修订日志 ▾」保存菜单。
- 视觉记号（visual-direction 已定）：冷灰外壳 `#f2f4f7`、暖白稿面 `#fbf9f4`、青黛主色 `#2f5d8a`；界面字 Noto Sans SC，书名与正文 Noto Serif SC；正文 17 px、行高 1.9 ~ 2.0、每行 30 ~ 38 字；标记固定色：修改建议 `#c4566a / #fbe3e7`，批注 `#3b6ea8 / #dde9f8`，备注 `#7a5fb0 / #ebe4f7`，自选高亮三色 `#fff1a8 / #ffe0c2 / #d2eedb`；深色主题成套定义。
- 状态词一律用带形状的状态药丸（VIS）：好 / 注意 / 阻塞 / 进行中，文字与形状并用，不只靠颜色。
- 所有面都要在 1120 px 以下把右侧辅助面改为覆盖抽屉，760 px 以下侧栏只留图标。

## 1 · ① 稿件入口

**目的**：编辑打开图书后立刻回到上次工作的稿件位置，在同一个面上读、改、标、发起任务、看结果。

**入口**：书库「打开稿件」、侧栏「稿件」、启动时的上次位置（RET-002）。尚无稿件的图书进入工作概览（①b）。

**最终形态**

- 中央：连续稿件（VIEW-005 排版），段落左缘 3 px 标记线，行内标记高亮；顶部一次性悬浮提示「回到上次位置 / 分析有新发现」自动消失（COPY-015）。
- 右缘一列：三个入口 `导航（大纲 + 搜索）· 分析 · 任务` 与一条带章节刻度的位置轨；轨旁三条并行车道标出修改建议、批注、备注与分析未覆盖处；原生滚动条隐藏，滚动时短暂浮现（ED-015 合并后的一个导航、ED-059）。
- 右侧辅助面（按需，覆盖式）：`导航` 展开大纲与搜索；`分析` 展开当前段落相关的人物 / 事件 / 设定；`任务` 展开任务面（§1.3）。
- 保存菜单「已写入修订日志 ▾」：`保存为里程碑版本…` 等低频动作（ED-052）。
- 专注模式保留（ED-020）。

**标记系统**（MARK-001 ~ 010）

| 对象 | 颜色 | 作者 / 来源 | 左键 | 右键 | 导出 |
| --- | --- | --- | --- | --- | --- |
| 修改建议 = 提案修改项 | 玫红 | 你 / AI7（任务 · 审阅类别 · 分析）/ 导入文件的作者 | 原地预览「预览 · 未应用」+ 标记浮卡：理由、依据、`接受并应用` / `拒绝` / `修改后接受`（可填「为什么这样改」，填了不再二问） | 转为批注 / 查看任务 / 看依据 / 复制 | 可选 `不含修改建议`；含时作为 Word 修订 |
| 批注 | 青蓝 | 同上 | 浮卡：内容、回复、`标记为已处理` | 回复 / 标记为已处理 / 转为修改建议（AI7 的批注可转）/ 查看任务 / 看依据 | 可选 `不含批注`；含时作为 Word 批注 |
| 备注 | 淡紫 | 只有你 | 浮卡：编辑 | 转为批注 / 删除 | 从不导出，不发给模型，不进任务范围 |
| 自选高亮（三色） | 三个个人色 | 你 | — | 换颜色 / 取消高亮 / 转为备注 / 转为批注 / 提出修改建议 / 复制 / 发起任务 | 不导出 |

- 一键：`接受并应用` = 提案决定 + 应用批准 + 派发，记录分开保存（PDEC-012、EAPP-003）。
- AI7 产出的标记标明来源任务或审阅类别，浮卡提供 `查看任务`、`看依据`，打开与正文列对齐的浮窗，或跳转并在上下文头留「回到<位置>」芯片（TASK-045、MARK-008）。
- 导入的 DOCX 批注与修订以文件作者为来源进入为批注与修改建议（MARK-009）。

**右键菜单**（TASK-046）三组：`文字处理`（复制 / 粘贴 / 剪切 / 查找）· `编辑标记`（三色高亮 / 批注 / 备注说明 / 提出修改建议）· `AI7 任务`（`就这段发起任务…` / `就这段提问…` / 本社 `常用工序`）。没有「加入任务范围」「在稿件中搜索」。

**任务面**（§1.3，TASK-001/044/045）：`发起全书任务` 撰写框（`快速开始` / `准备任务`）；三组 `等你处理 · 进行中 · 最近完成`；对话任务给 `回答` / `打开对话`；非对话任务是一张卡（内容 + 状态 + 暂停 / 取消）；完成的任务 `查看结果（浮窗）` 或跳转 + 回到芯片。撰写框只在选区右键与任务面出现，不常驻（TASK-001）。

**状态**：回到上次位置 · 分析有发现 · 导航 / 搜索 · 辅助面（分析 / 任务）· 跳转后（回到芯片）· 浮窗（结果 / 任务详情）· 右键菜单三种 · 就选区发起任务 · 专注 · 尚无稿件 · 标记三种浮卡。

**数据**：现有 `ManuscriptWindowProjection`、`OutlineProjection`、`SearchResultsProjection`、`MilestoneProjection`、`DurableHistoryProjection`；需新增：标记投影（种类、范围、作者 / 来源、状态、来源任务 / 类别、依据链接）、任务面投影（三组任务卡与对话）、结果浮窗投影、位置轨车道数据（每章 / 每段的标记与未覆盖计数）。

**后端对齐**：标记对象（批注 / 备注 / 自选高亮）与提案修改项的一键接受并应用命令；任务列表（按图书）；标记与审阅发现的双向同步（REV-005）；标记处置进入学习（FDBK）。现状：提案 / 标记 / 任务列表服务缺；稿件窗口、大纲、搜索、里程碑、恢复已有。

**现状代码**：`renderEditorWindow`（稿件窗口）、`renderBookOverview`（入口错放为概览，改为目的地）、`renderResolvedBookWorkbenchRoute`；无标记、任务面、浮窗。

**Owner 决定**：2026-09-09「对于中文编辑而言，点开一个稿件，最优先需要被看到的就是上次以工作的稿件本身」「底部任务输入框不需要长时间显示，反而应当在选中文字后右键呼出」「至少三种对象"修改建议""批注""备注"……都需要标注作者来源」「给一些系统功能性高亮固定对应颜色，另外提供3种个性化颜色给用户即可」「改为一键，接受即应用」「大纲与搜索应当与全稿位置合并设计一个整体导航」「这一屏定了」。

## 2 · ①b 工作概览

**目的**：看这本书的全貌；只是目的地。**入口**：侧栏「工作概览」；尚无稿件的图书的默认入口。

**形态**：稿件锚点（修订版、上次位置、保存状态、`打开稿件`）优先（BOOK-001）；交付物一行计数；来源与证据、最近发生的事、记录。尚无稿件时提供 `导入稿件`。第一次导入完成进一次概览（IMP-011、IMP-056）。

**现状代码**：`renderBookOverview`（保留为目的地）。

## 3 · ②A 分析（基线）

**目的**：基线分析是复杂操作的基础，本身对编辑不那么重要（Owner：「A的排序应该往后一些」），放在 `资料与记录 › 分析`。

**形态**：标签页 `梗概 · 人物与名称 · 事件 · 关系 · 设定 · 各章 · 历史与更新`；四句话说明是什么、覆盖到哪、新鲜度、保证级别（ANALYSIS-025）；矛盾线索不在这里（归审阅第 3 类）；三种更新方式（同步到当前稿件 / 重新分析所选范围 / 全部重来）各自说清复用与重算；弹层里 `开始同步`（快速开始）或 `先看计划`（→ ③）。

**数据**：现有 `BaselineAnalysisProjection` 全套（覆盖清单、结果集修订版、复用计划、历史、运行）。**后端**：已有（分析链服务端完成）。**现状代码**：`renderBaselineAnalysisOverview`、`renderBaselineAnalysis`、`renderAnalysisHistory`、`renderAnalysisUpdateControls`。

**Owner 决定**：2026-09-09「A 作为稿件的基本操作（基线分析）……对于编辑而言不那么重要」「②A ok」。

## 4 · ②B 审阅

**目的**：按类别对稿件做可配置的审读，结果同步到稿件上的标记，并出报告（REV-001 ~ 013）。

**形态**

- 目的地页：审阅覆盖矩阵（类别 × 当前稿件，改动后提示复审）；审阅记录列表（一次审阅 = 类别集 + 范围 + 运行 + 发现 + 报告）；`新建审阅`。
- 新建审阅弹层：九类可多选——`错别字与规范用语 · 体例与格式 · 情节逻辑与前后一致 · 事实核查 · 学术道德与引用 · 出版政策与风险 · 文学性与表达改进 · 书系一致性 · 跨交付物一致性`；每类写明依据（知识库规范文件 / 工序 / 是否用搜索引擎——一次性说明，不单独授权，REV-010）；范围四选一（全书 / 选章 / 只审改动过的章 / 当前选区）；四行后果（会读取 / 会发送 / 不会做 / 费用）；`开始审阅`（快速开始）或 `先看计划`。
- 运行中：按类别显示进度，完成的类别立即可处理。
- 结果：按类别分组，筛选类别 / 严重度（必须处理 / 建议处理 / 提示）/ 状态（待处理 / 已处理 / 已忽略）/ 章；第 1、7 类产出修改建议（可单条 `接受并应用`，第 1 类可批量，批量前一条确认条说明写入范围）；第 2 ~ 6、8、9 类产出批注（标记为已处理 / 转为修改建议 / 忽略并说明）；第 5、6 类只标「需人工复核的风险点」。
- 报告：版本化、可导出、可附交付包。
- 书系一致性（第 8 类，ADR 0077）：以书系知识为依据检查跨书的人物、设定、时间线；书不在书系时不可选；发现回到各书稿件上。

**数据**：需新增：审阅记录、类别配置、按类别的发现投影、报告投影。**后端**：审阅运行编排（多类别一次运行、按类别返回）、规范文件条款引用、发现 ↔ 标记同步、报告生成、书系知识读取。现状：事实核查有 `FactualReviewProjection` 与合同；其余缺。

**Owner 决定**：2026-09-09 六类原话（见 ADR 0076 §6）；「4类查重需要允许外网查询」「查重主要是使用搜索引擎……无需在界面上显示这些信息和单独授权」「这一屏定了」「要注意这里的审阅结果是要同步到稿件视图的」；「保留全部设计，主要是书系知识和内容逻辑的一致性检查」（2026-09-09，⑤ 讨论中）。

## 5 · ②C 评估与审稿意见

**目的**：多维评分、总评与分项评语、优缺点、市场定位与策略、预测；编辑调分定稿；审稿意见作为固定特殊任务（EVAL-001 ~ 013）。

**形态**：总分 100，各评分项按评估方案平均分配满分，只显示 `满分 / 得分`，不显示权重；风险项（事实与来源 / 法律与政策）用低 / 中 / 高并封顶结论；就绪清单；AI7 初评与编辑定稿并列，记录保留编辑的；结论由编辑选；市场板块含标「低确定性」的预测块（v1）；定价与首印在设为发稿版本后提醒录入；社内校准后台进行、设置里可看；版本间逐项比较；审稿意见两个模板（给作者 / 给编辑部 · 选题会），草稿是编辑构件，以本社范例为参照。

**数据 / 后端**：评估记录、评估方案（知识库）、校准、预测（阈值 30 本实际数据）、审稿意见任务与构件。现状：全缺。

**Owner 决定**：2026-09-09「应当是总分100分，每一项要平均分配分数」「权重不要显示给编辑」「默认情况下定价与首印区间不主动预测……在设置中才允许打开」「（预测）放进v1」「v1只针对两种就可以了，营销要点可以从写作任务生成」「（校准）后台处理，在设置中留入口查看」「实际部署时会有很多过往已出版的真实审稿意见作为参考」「这一屏定了」。

## 6 · ③ 任务计划与授权

**目的**：所有任务（选区任务、全书任务、审阅、评估、分析更新、写作任务）共用一个「先看计划」面；编辑能看懂、能改、一次点击开始（PLAN-001 ~ 012、AUTH-001 ~ 010、TASK-017/019 修订）。

**入口**：撰写框的 `准备任务`；②A / ②B / ②C / ⑥ 弹层里的 `先看计划`；`快速开始` 不经过此面但同一份计划冻结可查。

**最终形态**

- 位置：右侧任务面（Task Drawer）展开，稿件仍在左边可见可编辑；窄屏覆盖。头部：`← 任务` · `任务计划` · 状态药丸 · `精简 / 完整` 切换 · 关闭。
- 目标块：任务一句（`修改` 回到撰写）、上下文芯片（书 · 位置 · 已选字数 · 任务输入修订版 · 工序）、一行说明（准备任务时自动保存了修订版，之后的编辑不影响本次任务，TASK-039/040）。
- **精简模式**（默认，记住选择；PLAN-010）：一张卡五行——`处理 · 发送（含费用与预算上限）· 会得到 · 不会 · 中途`——即 LAYER-002 不可降级的全部；一行 `完整计划（6 段）· 可以改步骤与限制`。

## 7 · ④ 导入与保真、重新导入、导出

**目的**：把 DOCX 稿件安全地导进来、再导进来、导出去，编辑看得懂每一类内容会怎样（IMP-001 ~ 057、EXP-001 ~ 024）。

**目的**：把稿件的发稿、生产文档的交付、图书级的交付包三件事分开管理（DELIV-001 ~ 007、BUNDLE-001 ~ 005、MILE-014、WORK-013）。

**三者**

| | 对象 | 版本语言 | 完成叫 | 之后 |
| --- | --- | --- | --- | --- |
| 发稿 | 稿件 | 里程碑版本（① 保存菜单 / 稿件历史） | `设为发稿版本`（从里程碑选一版 + 发稿范围 + 依据；固定句「仅表示此版本可用于上述发稿范围；AI7 不会发布或发送」） | 提醒录入定价与首印；审稿意见自动归入范例；再改出「自发稿版本后有修改」；更正 / 勘误 / 替代 / 撤回 / 再版 / 归档按维护事项记录 |
| 交付 | 生产文档（本社配置的类型：新闻稿 / 宣传文章 / 评论文章 / 发布会材料 / 营销要点 …） | 版本（没有里程碑 / 发稿字样） | `交付` = 选一版（当前工作状态先保存为版本）+ 交给谁（本社清单：宣传部 / 编辑部 / 外部媒体 / 其他）+ 备注 → 交付记录 + 导出文件（④） | 交付后再改是新版本，标「交付后有修改」，可再交付；与发稿互不影响；可标「本书不做」 |
| 图书交付包 | 整本书 | 包 v1、v2 … | 条件表：发稿已设 + 各文档已交付（或标为不做）+ 工作记录齐 → `准备图书交付包` 冻结清单 → `图书交付包已准备 · 暂无导出记录` → 导出为文件夹或压缩包（④） | 任何一项变了生成包 v2，v1 不动；包不是发稿也不是交付 |

**总览页**：三块并排——稿件发稿一行（里程碑列表、`设为发稿版本…`）；文档卡（下一项需要处理 → 七个阶段并行状态 → 交付状态 → 打开 / 处理关口 / 交付 / 再交付）；图书交付包条件摘要。没有百分比（WORK-007）。

**新建文档 · 写作任务**（DELIV-007）：选类型；AI7 参考稿件梗概与人物、评估结论与营销要点、按图书的范例、图书信息，加受众与渠道；四行后果；`先看计划`（→ ③）/ `快速开始`；产出是「起草」阶段的草稿（编辑构件），范例只参照不复制。

**文档稿件面**：与稿件相同的面与标记系统；右侧「工作流程」栏：方案版本、`下一项需要处理`（按阻塞 · 决定 · 相关度排序）、七阶段 `接收与准备 · 来源建设 · 起草 · 审阅与核查 · 定稿 · 交付 · 维护`（可并行；跳过 / 重开要写原因，WORK-003 ~ 009）、版本与交付、这份文档的材料（任务简报 / 引语台账 / 事实核查记录 / 参考的范例）。

**关口卡**（WGATE-001 ~ 011）：强制条件与建议项各带证据或缺项；就绪只算不决；处置不预选（`通过此关口` 在强制条件未满足时不可用 / `退回补充` / `有条件通过`（方案允许时）/ `暂不决定` / `自行输入`）；AI7 建议只显示不预选；`记录关口决定` 是一条确定性命令。

**维护事项**（MAINT-001 ~ 012）：发稿后稿件的六类不预选；更正走修改建议 → 接受并应用 → 新修订版 → 新里程碑 → 另设发稿版本；撤回 / 归档只在 AI7 内记录；文档交付后要改走新版本再交付，不在这里。

**数据 / 后端**：生产文档对象与类型配置；工作流程实例与关口（方案启用已有）；文档版本与交付记录；图书交付包（条件、清单、版本、导出记录）；发稿版本（现 Publication Version）；维护事项；写作任务（参考集合与产出构件）。现状：只有工作流程方案的获取 / 启用（`renderEditorialWorkspaceProfile`、`native-workflow-profile.ts`）；其余缺。

**Owner 决定**：2026-09-09「D. 新闻稿，宣发稿等附属文档的生产」「最后交付物有一点不符合业务设计，保存为里程碑版本主要绑定的是稿件变化，而新闻稿，发布会，营销等等文档是图书项目中产生的生产文档，这些文档本身的版本变动与交付与稿件本身的交付（发稿）是相互独立的……把针对图书稿件本身的里程碑发布称为发稿，而其他相关文档为交付，同时在管理上要相对区分。 交付包是在发稿和其他工作全部完成后将所有工作文档（含发稿稿件）的总和。这三者要进行区别」「Q1 ok Q2 ok Q3 ok Q4 ok Q5 ok Q6 ok，这一屏定了」。
