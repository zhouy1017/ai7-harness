# AI7 V2 visual direction

Status: **candidate visual direction complete for this session; no prototype or Figma artifact**

## Intent

AI7 should be recognizably its own Chinese professional editorial product while its overall visual presentation and interaction manner feels similar to the owner-provided Codex Desktop screenshot. The intended resemblance is the experience of a quiet, capable desktop workbench: low visual noise, clear spatial continuity, progressive work disclosure, and consequential actions kept close to their exact context.

## Qualities to retain from the reference

- a calm low-noise desktop shell whose light theme uses subtle cool-neutral separation;
- restrained application chrome, borders, radii, shadows, and iconography;
- a persistent but collapsible navigation surface;
- one visually dominant central work surface;
- contextual supporting information that appears without replacing the primary object;
- a compact bottom task-entry pattern that can expand when needed;
- progressive activity, interruption, clarification, history, and review close to the work;
- concise action and outcome cards rather than modal-heavy interaction; and
- strong whitespace, readable rhythm, and subdued status treatment suitable for long sessions.

## Required AI7 reinterpretation

| Reference characteristic | AI7 reinterpretation |
| --- | --- |
| Codex tasks and thread list | A Book-anchored navigation and Global Attention View; Tasks remain context-bound AI7 records rather than conversations. |
| Conversation-dominant center | The current manuscript, Editorial Deliverable, proposal comparison, evidence review, workflow record, or other authoritative AI7 work object. |
| Environment, worktree, Git, and pull-request actions | Exact Book, deliverable, manuscript pin, workflow, source scope, named authority, Effect, and receipt context. |

## Explicit exclusions

- Codex name, logo, proprietary assets, GUI source, or copied microcopy;
- pixel-for-pixel geometry, exact proportions, or a replica component tree;
- coding objects such as repositories, worktrees, branches, commits, terminals, pull requests, or developer access levels;
- a generic chat-first hierarchy that displaces Books, manuscripts, deliverables, evidence, proposals, or workflows;
- raw model reasoning, DSH technical sessions, tool traces, or provider internals as the normal user experience; a separately labeled Live Reasoning Summary may describe user-facing approach/checks but never claims those internals; and
- visual similarity that merges AI7's distinct authority or factual-status records.

## Theme and color roles

`跟随系统` is the default Application Theme Preference, with manual `浅色` and `深色` alternatives. The choice applies to all AI7 windows and changes presentation only. Light mode keeps the reference's cool-neutral shell and slightly warm manuscript surface; dark mode uses low-glare charcoal shell chrome and a neutral reading surface, avoiding pure black/white glare and saturated decoration during long professional sessions.

Native accessibility appearance takes unconditional priority over either AI7 theme. This includes Windows high contrast/forced-colors and applicable macOS contrast, transparency, and color-accessibility settings; each is a system-owned rendering layer rather than a fourth appearance preset. Components use semantic roles—surface, manuscript surface, raised surface, primary/subdued text, focus, selection, boundary, informational, caution, danger, disabled and action—whose meaning stays stable across mappings. Exact words, icon/shape and structure remain authoritative; color is only reinforcement. V1 does not offer custom accent or palette controls.

## Semantic state language

Across cards, virtualized rows, panels, notices and action bars, AI7 uses one quiet presentation grammar: exact Chinese status text leads, icon/shape and necessary boundary reinforce it, and consequence/detail plus one safe next action appear only when useful. The system standardizes focus, selection, disabled, loading, error and completion behavior without turning distinct editorial states into generic success/warning/error badges.

Selection remains visually neutral and cannot resemble a recorded decision. Disabled consequential actions stay legible with their reason. Local loading is lighter than a Run phase or provider wait. Error prominence follows consequence while keeping manuscript text and retained input stable. Authoritative completion treatment is withheld until an AI7 record, classified evidence or verified Effect Receipt supports the precise claim; model activity, Harness success and optimistic animation stay visually provisional. Repeated colorful badges, status-card walls, flashing indicators and celebratory motion are excluded.

## Microcopy and error tone

AI7's primary language is compact but complete: `对象 + 状态` leads, consequence follows, retained-safe/unchanged state prevents panic, and one `动词 + 对象` action gives the next safe move. Errors stay where the affected input or record lives; persistence and authority blockers remain visible without covering manuscript prose. AI7-owned modal treatment is rare and reserved for possible manuscript-input loss or an irreversible misunderstanding; OS-owned pickers and file-conflict dialogs retain native presentation.

Technical detail recedes under `查看技术详情` and uses a sanitized, copyable support presentation. It never becomes a console, raw Harness transcript or Provider request inspector. The ordinary layer avoids generic `出错了`, `失败，请重试`, `任务完成`, `已保存` and `AI 正在思考`. Tone stays calm, specific and non-blaming; durable records show absolute local time without turning routine transient activity into an audit wall.

Mode transitions should feel spatially continuous and preserve object identity, location, and focus. They must not use celebratory motion or attention-stealing transitions when a background Run changes state.

The right contextual navigation keeps `大纲` and `搜索与跳转` continuously discoverable through restrained icon-and-label entries. The Whole-manuscript Position Rail is visually quieter than the local editing surface and reveals marker detail on focus, hover, or selection rather than becoming a colorful permanent minimap.
