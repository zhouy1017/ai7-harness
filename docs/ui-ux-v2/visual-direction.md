# AI7 V2 visual direction

Status: **candidate visual direction complete for this session; no prototype or Figma artifact**

## Intent

AI7 should be recognizably its own Chinese professional editorial product while its overall visual presentation and interaction manner feels similar to the owner-provided Codex Desktop screenshot. The intended resemblance is the experience of a quiet, capable desktop workbench: low visual noise, clear spatial continuity, progressive work disclosure, and consequential actions kept close to their exact context.

## Qualities to retain from the reference

- a calm low-noise desktop shell whose light theme uses subtle cool-neutral separation;
- restrained application chrome, borders, radii, shadows, and iconography;
- a persistent but collapsible navigation surface;
- one visually dominant central work surface;
- contextual supporting information that appears without replacing the primary object;
- a compact bottom task-entry pattern that can expand when needed;
- progressive activity, interruption, clarification, history, and review close to the work;
- concise action and outcome cards rather than modal-heavy interaction; and
- strong whitespace, readable rhythm, and subdued status treatment suitable for long sessions.

## Required AI7 reinterpretation

| Reference characteristic | AI7 reinterpretation |
| --- | --- |
| Codex tasks and thread list | A Book-anchored navigation and Global Attention View; Tasks remain context-bound AI7 records rather than conversations. |
| Conversation-dominant center | The current manuscript, Editorial Deliverable, proposal comparison, evidence review, workflow record, or other authoritative AI7 work object. |
| Environment, worktree, Git, and pull-request actions | Exact Book, deliverable, manuscript pin, workflow, source scope, named authority, Effect, and receipt context. |
| Generic prompt composer | A context-bound Task Intent entry that exposes source scope, Plan Preview, provider processing, budget, and possible Effects before Run Authorization. |
| Technical activity | Editorially meaningful progress, clarification, partial outcome, interruption, and continuation state. |
| Generic approval or access level | The exact named AI7 decision; target-house Signoff/Public Release records project as `里程碑版本` and `发稿版本`, while other authorities retain their own names. |

## Explicit exclusions

- Codex name, logo, proprietary assets, GUI source, or copied microcopy;
- pixel-for-pixel geometry, exact proportions, or a replica component tree;
- coding objects such as repositories, worktrees, branches, commits, terminals, pull requests, or developer access levels;
- a generic chat-first hierarchy that displaces Books, manuscripts, deliverables, evidence, proposals, or workflows;
- raw model reasoning, DSH technical sessions, tool traces, or provider internals as the normal user experience; and
- visual similarity that merges AI7's distinct authority or factual-status records.

## Theme and color roles

`跟随系统` is the default Application Theme Preference, with manual `浅色` and `深色` alternatives. The choice applies to all AI7 windows and changes presentation only. Light mode keeps the reference's cool-neutral shell and slightly warm manuscript surface; dark mode uses low-glare charcoal shell chrome and a neutral reading surface, avoiding pure black/white glare and saturated decoration during long professional sessions.

Windows high contrast/forced-colors takes unconditional priority over either AI7 theme. It is a system-owned rendering layer rather than a fourth appearance preset. Components use semantic roles—surface, manuscript surface, raised surface, primary/subdued text, focus, selection, boundary, informational, caution, danger, disabled and action—whose meaning stays stable across mappings. Exact words, icon/shape and structure remain authoritative; color is only reinforcement. V1 does not offer custom accent or palette controls.

## Semantic state language

Across cards, virtualized rows, panels, notices and action bars, AI7 uses one quiet presentation grammar: exact Chinese status text leads, icon/shape and necessary boundary reinforce it, and consequence/detail plus one safe next action appear only when useful. The system standardizes focus, selection, disabled, loading, error and completion behavior without turning distinct editorial states into generic success/warning/error badges.

Selection remains visually neutral and cannot resemble a recorded decision. Disabled consequential actions stay legible with their reason. Local loading is lighter than a Run phase or provider wait. Error prominence follows consequence while keeping manuscript text and retained input stable. Authoritative completion treatment is withheld until an AI7 record, classified evidence or verified Effect Receipt supports the precise claim; model activity, Harness success and optimistic animation stay visually provisional. Repeated colorful badges, status-card walls, flashing indicators and celebratory motion are excluded.

## Microcopy and error tone

AI7's primary language is compact but complete: `对象 + 状态` leads, consequence follows, retained-safe/unchanged state prevents panic, and one `动词 + 对象` action gives the next safe move. Errors stay where the affected input or record lives; persistence and authority blockers remain visible without covering manuscript prose. Modal treatment is rare and reserved for possible manuscript-input loss or an irreversible misunderstanding.

Technical detail recedes under `查看技术详情` and uses a sanitized, copyable support presentation. It never becomes a console, raw Harness transcript or Provider request inspector. The ordinary layer avoids generic `出错了`, `失败，请重试`, `任务完成`, `已保存` and `AI 正在思考`. Tone stays calm, specific and non-blaming; durable records show absolute local time without turning routine transient activity into an audit wall.

## V1 visual migration boundary

Retain the frozen package's visual intent only where it expresses semantics: editor-first content priority, calm progressive disclosure, multi-channel state meaning, exact focus/return behavior and long-session Windows readability. Reshape that intent through the accepted AI7-owned Codex-referential shell, system-following themes, semantic state grammar, adjustable density/typography and dedicated review workspaces. Drop every frozen A/B/C layout, exact token/value, HTML prototype, Figma frame and component tree. No V1 pixel or screen arrangement is a visual default.

## Accepted work-surface rhythm

The Codex-referential shell is reinterpreted around four explicit presentation states rather than a conversation-first center: Manuscript Editing Mode, Contextual Collaboration Mode, Dedicated Work Workspace, and Editorial Focus Mode. The normal visual rhythm keeps the Manuscript dominant, reveals one contextual surface on demand, and reserves full central replacement for comparison or evidence work that materially needs the space.

Mode transitions should feel spatially continuous and preserve object identity, location, and focus. They must not use celebratory motion or attention-stealing transitions when a background Run changes state.

The right contextual navigation keeps `大纲` and `搜索与跳转` continuously discoverable through restrained icon-and-label entries. The Whole-manuscript Position Rail is visually quieter than the local editing surface and reveals marker detail on focus, hover, or selection rather than becoming a colorful permanent minimap.

The bottom task composer may closely echo the reference's compact floating field and circular arrow rhythm, but its content chips, tooltip, accessible name, and expansion behavior identify it as `准备任务`. No visual sending or streaming state begins until later Run Authorization and dispatch actually occur.

Model choice follows the same restraint: one compact Model Selection Strip presents Model Role and capability requirements, while provider/budget disclosure appears as a quiet secondary line or popover. Blocking state may expand, but normal credential, fallback, billing, and usage detail belongs to lower-level surfaces rather than adding permanent cards beside the manuscript.

Reusable-procedure capture begins with one professional-language action and one compact classification preview. The recommended Default Execution Rule, Task Skill Candidate, Workflow Profile Draft or Developer Capability Proposal is presented as a purpose-and-consequence choice rather than four technical tiles; Plugin mechanics remain inside developer detail and never appear as an editor-installable marketplace object.

Before classification, a compact extraction preview gives equal textual weight to `将提取什么` and `不会保存什么`. Selected business steps form one calm reorderable list; parameterized fields and branches are readable without showing hidden Harness traffic. Excluded manuscript content, Book identity, secrets, provider/model bindings and historical authority appear as concise named categories rather than copied sensitive excerpts, so the privacy explanation itself cannot leak the material it promises not to save.

Task Skill creation uses a quiet lifecycle strip rather than one magical generation button. `候选版本`, `准入中`, `已安装但未启用`, `检查未通过`, `已检查但未启用` and `已启用` are named text states. The exact Authority Ceiling appears in a focused consequence sheet before `启用此版本`; capabilities and exclusions receive equal hierarchy, while Run/effect authority remains a concise explicit non-effect. Repair is presented as a new-version action, never an overwrite or retry that erases the failed version.

The Automation Center uses a restrained catalog-and-version-history layout. Typed top-level sections prevent Task Skills, Workflow Profiles, rules and developer proposals from looking interchangeable; one stable entry expands into a vertical exact-version list with `最新可用`, active-default, disabled, retired and blocked states written in text. Version detail gives linked work and deliveries stronger navigation weight than package mechanics. Removal uses a consequence sheet distinguishing `永久删除`, `停止未来使用并保留历史`, and `暂不可删除`; associated deliveries never appear inside the deletion selection or as collateral damage.

The new Task's current Book and readable sources remain in the established target/scope regions, so broad catalog availability never looks like broad manuscript access.

Workflow Profile, Default Execution Rule and Developer Capability Proposal cards share catalog typography but not primary actions. Profile draft, publication, future-default designation and existing-instance migration occupy distinct labeled states; rule draft and enabled status expose the exact envelope before activation; developer proposals end with a calm saved handoff state and no install affordance.
