# Stage DSH artifact acquisition, enablement, Run and Apply

AI7 presents native DSH Skills, Plugins, Bundles, Profiles and Agent Presets with their native identity and exact version while keeping AI7 authority/compatibility sidecar information visibly separate. The former Task Skill package/candidate/installed-version hierarchy is not a parallel runtime model. Any retained `Workflow Profile / 工作流程方案` wording is only a product projection over an exact native definition carrier; durable Workflow Instances remain AI7-owned and no exact Profile/Bundle mapping is selected here.

Catalog discovery, acquisition/pinning, foreign-Skill conversion and compatibility validation are non-executing. Artifacts that require lifecycle hooks, dependency scripts or native code show a `restricted` disposition until separate executable-admission and sandbox authority exists. For a compatible artifact, install and scoped enablement may be one compact visible action, but the product preserves the internal boundaries and explains the consequence truthfully.

Installation or enablement grants no Book/manuscript access, Provider processing, credential resolution, network access, external Effect, background analysis or formal mutation authority. Foreground execution requires an exact Run for a newly user-initiated Task, directly authorized or matched by an active Default Execution Rule. A new autonomous background Provider dispatch requires a separate active Background Analysis Enrollment and its own exact Run.

Foreign Skill history visibly distinguishes the immutable Source Skill Snapshot, the locally editable DSH-native Imported Skill Working Revision and the separate AI7 compatibility/authority sidecar concept. Upstream reconciliation creates an inert candidate. The working revision changes only through explicit adoption or an exact revocable Artifact Update Rule limited to trusted, conflict-free, validator-clean, semantically and operationally non-expansive imported-Skill changes. Rollback restores artifact history but never restores revoked grants, rules, enrollments or Runs.

Every formal agent-originated Manuscript mutation uses one AI7 Apply boundary. Apply is single-use and binds the exact Book, base pin, diff and targets; it rechecks drift and requires explicit editor confirmation. No artifact, install, enablement, update rule, enrollment, Run or DSH Session may contain or inherit Apply.

This ADR partially refines UI ADRs 0001 and 0008 only for their old Task Skill/version carrier wording, and UI ADR 0013 for native artifact/update history. Their exact user-initiated Default Execution Rule, deferred-start, latest-eligible exact pin and immutable historical-link semantics remain. It also refines reusable-procedure and Automation Center presentation without choosing a catalog source, final global label, trust tiers, sidecar schema, sandbox mechanics or exact native carrier mapping.
