# Use versioned coverage-aware manuscript analysis

AI7 distinguishes targeted retrieval from analysis that claims whole-manuscript or comprehensive coverage. Targeted retrieval remains a ranked-candidate path whose authoritative wording comes from Exact Fetch. Covered analysis visibly binds the exact Manuscript Revision, deterministic Coverage Manifest, completely enumerated Analysis Units, typed partials/reducer stages, provenance and every gap or unresolved conflict.

The analysis surface never reduces status to one `complete` flag. It keeps mechanical coverage, synthesis/reducer closure, exact-revision freshness and semantic/evidence assurance independently visible. It makes no absolute semantic-completeness claim.

Covered analysis persists in immutable Book-bound Manuscript Analysis Result Set Revisions. Users may distinguish `同步到当前稿件`, `重新分析所选范围` and `重新分析全书`; every action appends history and discloses cache reuse or bypass. A Task Outcome may link a result, but analysis is not the Manuscript, a retrieval projection, DSH cache or an Editorial Artifact unless separately promoted.

Background work requires a separate active Background Analysis Enrollment. Baseline manuscript analysis is the default selection inside that active Enrollment, while all eight built-in Editorial Dimensions are optional individually or through an all-eight shortcut. Plugin installation or enablement enrolls nothing. After import, matching enrollment may queue selected analysis as a separate outcome; otherwise import succeeds with analysis pending and no Provider call or cost.

Each analysis kind retains independent Result Set, coverage/freshness/failure and feedback state even when one authorized batch Run shares dispatch work. Exact immutable Quality Signals and a separate Analysis Quality Metric family apply to analysis results; user feedback is not factual proof, learning, Policy activation or behavior mutation.

This ADR extends existing manuscript-scale, factual-review, feedback and import presentation without creating new journey IDs. Exact status enums, compact layout, Result Set schemas, scheduling, notifications, onboarding, pause/budget and failure-recovery mechanics remain implementation-facing.
