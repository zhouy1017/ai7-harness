## Cross-journey invariants

- Every journey starts from and returns to an exact Book, manuscript/deliverable version and authoritative record rather than an unbound generic conversation or Harness Session.
- Local reading, editing, search, history, recovery and export do not require Harness, Provider, credentials or network.
- Renderer views remain bounded; the service/store remains authoritative for whole-manuscript work and durable state.
- Run Authorization, Proposal Decision, Review Decision, Effect Approval, Effect Receipt, internal Signoff, Milestone Version, Publication Version and Public Release Permission never collapse into generic approval/completion.
- Model/Harness/tool completion is never business proof. Every authoritative or externally visible Effect needs its own exact outcome evidence/receipt.
- Reference Integrity, Claim Support and Factual Verification remain independent; model knowledge is never evidence.
- Chinese IME composition, keyboard access, visible focus, zoom/reflow, forced colors and retained-safe error behavior apply throughout.
- Restart returns to authoritative durable state and names any uncertainty; an ordinary interrupted Run waits in `任务已中断 · 可续行` for explicit `续行`, while only a previously authorized Start When Online Run may auto-dispatch after unchanged Reconnect Preflight.
- Series membership changes are prospective, while a newly effective Series Retrieval Exclusion blocks every later affected read immediately; historical authorization never overrides a current restriction.
- Delivery Package identity is destination/format-independent; every concrete local export and post-designation Maintenance Case keeps its own exact authority and immutable history.
- An explicitly entered Book-bound Agent Workspace may host an eligible DSH composition or compatible UI Plugin inside the AI7 shell while preserving the exact Book, safety state and prior Active Work Object; it is never a generic root or authority owner.
- Discovery, acquisition, validation, install, scoped enablement, Provider/Model Service setup, Default Execution Rule and DSH Session membership grant no Run, Background Analysis Enrollment, source, Provider, Effect or Apply authority.
- A Default Execution Rule can match only a newly user-initiated Task. Every new idle, scheduled, import-triggered, post-checkpoint or cross-Run Provider analysis dispatch requires an active matching Background Analysis Enrollment; moving the same already-authorized Run out of the foreground changes presentation only.
- Targeted retrieval plus Exact Fetch and deterministic whole-revision covered analysis are separate contracts. Coverage, reducer/synthesis closure, exact-revision freshness and semantic/evidence assurance never collapse into one score or factual truth.
- Every formal agent-originated Manuscript mutation crosses one exact single-use AI7 Apply bound to Book/base pin/diff/targets with drift recheck, explicit editor confirmation and verified outcome. No artifact, Rule, Enrollment, Run, Session, Plugin or result inherits it; direct typing and deterministic import/domain commands remain separate.

## V2-specific journey reshaping notes

### J-03 exact `Task Input / 任务输入` and budget state

Continuous editing stays journal-first. When J-03 begins from acknowledged text newer than the latest Manuscript Revision, pending ranges remain `待保存修订版` and any attached prior-revision pin becomes `待核对到任务修订版`. AI7 locally creates the existing Manuscript Checkpoint type with purpose `Task Input / 任务输入` before Plan Preview or any standard/Quick/default authorization, then exact-resolves every attached manuscript target/range/source/evidence reference into a new task-bound pin on the resulting revision without mutating the original. Checkpoint failure retains the Task draft and journaled work; a changed or ambiguous reference after successful checkpointing retains the new revision and draft but requires explicit reselection/removal. Either condition blocks planning/authorization. Once resolved, every target/range/source/evidence/Run binds the same revision, and later editing never retargets it. The default Run Budget Ceiling is visibly `未设置任务预算上限`, which means no AI7 product-side per-Run stop—not free or unlimited Provider service. An explicit ceiling is optional and exact.

### J-01 import completion

The global import entry leaves every new/existing target unselected; current context may recommend an exact Book but never selects it. A complete verified Staged Import Snapshot persists locally before consequential review. Exact original-file identity and exact parsed content/structure are disclosed separately from same-name/different-content collision and fuzzy similarity, and none selects a target, relationship, or duplicate action. A cross-Book match may help the editor change target but never reuses one Book's Source Version as another Book's authority.

Choosing `新建图书` for manuscript import creates only a manuscript-import-bound Book Creation Draft. Once its editor-confirmed working title and preflight are valid, AI7 immediately guides the editor through fidelity review to Review Before Import rather than committing an empty Book. Book Title Suggestion may locally inspect bounded document metadata and title-bearing early content, with filename fallback, but always labels its source and remains editable. A separate standalone `新建图书` path may intentionally create an empty zero-Manuscript Book, while a source-bound path may create a zero-Manuscript Book plus first Source Version; all three require their own exact review and never share final consequences silently.

The successful new-Book commit requires persistence of the Book/stable identity, effective Book Editorial Dimension Set, primary Manuscript, initial branch/revision, exact Workflow Instance plus AI7 Workflow Profile projection/native definition pin, original-file/provenance and Import Fidelity Review records, applicable Import Degradation Decision, and Manuscript Import Record before `稿件已导入` appears. An existing empty Book may instead receive its first and only primary Manuscript through the same fidelity contract without recreating Book identity or dimensions. Both paths create no Series membership, learning eligibility, Provider permission/transmission, Publication Version, public release, or delivery record. `打开稿件` and `查看导入记录` preserve direct access.

For source-only retention, target stays unselected. An exact existing Book receives a new or explicitly selected exact same-Book Source Version plus Source Import Record. When no Book exists, the editor may instead confirm a source-bound Book Creation Draft and use `新建图书并导入来源材料` to atomically create a zero-Manuscript Book and first Source Version. Both end at `来源材料已导入` and create no Manuscript Revision or Workflow Instance. Reimport first checkpoints dirty journal state, uses a three-way comparison only when prior Source Version lineage is verified, and otherwise labels a conservative current-versus-staged comparison `来源关系未确认`. Changed content creates a descendant revision and Manuscript Reimport Record; a verified no-change result records `未发现稿件变化` without creating an empty revision.

Restart never resumes or commits automatically. AI7 offers unselected continuation or abandonment after revalidating target, relationship, lineage, fidelity, and review. A complete snapshot may continue when the original file is unavailable; incomplete staging requires exact native-picker reselection. Cancellation deletes the draft and stage. If restart cannot prove whether the atomic commit crossed its boundary, `导入提交结果待确认` preserves evidence and blocks retry, cleanup, and double dispatch until reconciliation. Import records are not exported files, checkpoints, export/Apply receipts, or generic optimistic success.

Import completion is never delayed by analysis. A pre-existing matching active Background Analysis Enrollment may issue one or more exact Task/Plan/Run records after commit; compatible kinds may share one authorized batch Run while keeping independent Result Sets, status, failures and feedback. Without Enrollment, analysis remains pending and no Provider request, outbound payload or cost occurs. Import, source retention, Provider setup and artifact enablement create neither Enrollment nor analysis/Apply authority.

### J-04 source acquisition and factual boundary

Initial external research retrieval is described as a fully retrieved external research snapshot, never as Exact Fetch. Search snippets, incomplete retrievals, model answers, attachments and mere Task use create no Source Version automatically, although their separate Task/evidence records may remain durable. `保存为来源材料` starts with an unselected exact target Book or explicit source-bound new-Book draft, shows retained content and provenance, and commits only the Book-owned Source Version plus Source Acquisition Record (and zero-Manuscript Book when explicitly selected). Retention makes the exact material retrievable only through a later authorized scope; it does not establish Claim Support, Factual Verification, Learning Eligibility, Provider transmission or publication authority.

Targeted retrieval remains ranked-candidate discovery followed by canonical Exact Fetch. Comprehensive analysis separately requires a deterministic Coverage Manifest, complete structure-aware Analysis Units, provenance-preserving reduction and immutable Result Set Revision. Its coverage, reducer closure, exact-revision freshness and semantic/evidence assurance stay independent, and explicit gaps/conflicts remain visible. `同步到当前稿件`, `重新分析所选范围`, and `重新分析全书` preserve their distinct reuse/bypass meanings and create successor revisions rather than rewriting history.

### J-05 universal AI7 Apply

J-05 is the only formal agent-originated Manuscript mutation journey, regardless of Agent Workspace, dialogue, native Skill/Plugin, imported Skill or foreground/background Run origin. Preparation freezes the exact Book, base pin, diff and target set, rechecks drift and current authority, then one explicit editor interaction creates and consumes the single-use approval. Installation, scoped enablement, Artifact Update Rule, Default Execution Rule, Background Analysis Enrollment, DSH Session, result or Run Authorization never supplies it. Direct editor typing and deterministic import/domain commands remain separate. Lost acknowledgement enters idempotent outcome recovery, never a second Apply.

### J-07 target-house completion

The user-facing `签发` step is replaced by `保存为里程碑版本`. Delivery Package freezes exact content, artifacts, applicable Gate/Signoff references, purpose, exclusions and limitations without a format or destination; one package may link zero or many later Local Export Preparations/receipts. Format, filename, fidelity and destination are selected per export. An existing target is resolved through the current platform's native alternative-name/cancel/replace workflow; cancellation records no Effect, while a final create/replace target receives exact Effect Approval and a reconciled per-file receipt. Delivery stops there with no direct transmission or handoff record.

`发稿版本` remains a separate exact-version/publication-scope designation and never means AI7 published or sent anything. A later Correction, Errata, Supersession, Withdrawal, Reissue or Archive begins one exact versioned Maintenance Case. Correction follows Proposal/Apply into a new revision, Errata remains an Editorial Artifact, and any successor/reissue requires another separately designated exact Publication Version. Withdrawal/Archive copy states that it is internal AI7 status only; no earlier version, permission, package, file or receipt is rewritten and no external recall/takedown is claimed.

### J-10 rewind addition

Rewind appends a new continuation branch/direction inside the accepted history model. It does not erase Run attempts, decisions, Effects or receipts; any material plan boundary change still needs a new authorization. Ordinary restart reconciliation stops at a Resume-ready Run State until the editor explicitly chooses `续行`; Start When Online remains the narrow already-authorized auto-dispatch exception. Reaching an explicit Run Budget Ceiling is terminal for that Run and routes a changed ceiling through Plan Revision and Redo, while a Provider Account Limit remains a distinct remediable service blocker whose unchanged Run may Resume only after explicit action and revalidation.

### J-09 enrolled background analysis

Background Analysis Enrollment is the only standing origin for new autonomous Provider-backed manuscript-analysis dispatch. Before a separate explicit editor decision creates or revises one, AI7 discloses exact scope, selected kinds, Provider/data categories, budget and prospective/backfill consequences; Baseline analysis is the default within that decision while each Editorial Dimension and Plugin/user kind remains independent. Every dispatch still receives exact Task/Plan/Run provenance, and compatible kinds may share one authorized batch Run without merging per-kind Result Sets or state. Revocation stops future dispatch under the Enrollment but does not rewrite issued Runs, recall Provider data or reverse an Effect. Exact entry, label and pause/disable mechanics remain deferred. Moving the same existing authorized Run out of the foreground is merely presentation and requires no new authority.

### J-11 analysis feedback and metrics

An Analysis Feedback Card binds an exact immutable Quality Signal to one Result Set Revision, kind/dimension, item/range and evidence/provenance. Corrections and reanalysis append successor signals/results; silence is not approval. Analysis Quality Metrics are a separate versioned family from Delivery Quality Metrics. Neither a signal nor metric establishes factual truth, learning eligibility, Policy, artifact update, Provider/source scope, Effect or AI7 Apply.

### J-13 Series membership, knowledge, and retrieval exclusion

`书系 > 成员与共享范围` provides exact add/remove commands and a four-part Series Membership Impact Preview. Membership changes only explicit future Series-scope availability; already frozen Runs and immutable history remain exact, and each successful command appends a Series Membership Change Record.

Series Knowledge is a separate candidate/promotion path. Only editor-authored material or exact provenance from a member-Book Manuscript Revision, Source Version or reviewed evidence can enter `书系知识纳入审阅` for a proposed new or exact existing Series Knowledge Item. A conflict must be edited and re-reviewed, explicitly preserved, or cancelled; preservation records rather than resolves it. `纳入书系知识` creates the item with its first immutable revision or appends one immutable revision and promotion decision without replacing its source of record. Promotion does not itself create Run Source Scope, authorize or perform retrieval, permit Provider transmission, decide factual or learning status, mutate a manuscript, or authorize publication; the revision becomes eligible only for later exact Series-scoped selection and pinning.

Series Retrieval Exclusion is an immediate current-read restriction, not a membership edit. Add/change/end actions append revisions after `书系检索排除影响预览`. A new exclusion stops queued/authorized/active work before later affected use and requires `修改计划并重新授权` or `取消任务`; same-binding Resume, Retry, fallback and silent substitution remain unavailable. Original authorization/evidence/history remains immutable, already-sent Provider data cannot be recalled, completed affected results receive `此结果使用的材料后来被排除`, and ending an exclusion never restores old authorization or auto-resumes work. Separately authorized Cross-project scope remains governed separately rather than being silently decided by the Series exclusion.

### J-14 coverage boundary

Keyboard, IME, focus, scaling/reflow, native accessibility appearance and reduced-space behavior are unconditional design requirements throughout the journeys on both supported platforms. Their inclusion here does not authorize a separate usability/accessibility/performance/platform/UI validation gate.

### J-15 native DSH artifact and version lineage

The common capture entry produces a Default Execution Rule draft, native DSH Skill draft, Workflow-definition/Profile draft, or Developer Capability Proposal and never a generic automation object. Native DSH Skill is the semantic procedure unit; Plugin/Bundle is packaging, while DSH Profile/Agent Preset remains a native carrier. AI7 displays exact identity/version/provenance plus separate compatibility/authority consequences without choosing catalog sources, sidecar schema, trust tiers, sandbox mechanics or exact Workflow carrier mapping.

Acquisition and validation are non-executing. Imported Skills retain an immutable Source Skill Snapshot and minimally derived versioned working revision. An upstream change creates an inert three-way candidate; only explicit adoption or an exact active rule limited to trusted, conflict-free, validator-clean, semantically and operationally non-expansive Imported-Skill change may update current working state. Plugins, core DSH dependencies and Policies are excluded. Rollback preserves history and cannot revive revoked authority. Scoped enablement creates no Task/Run/Enrollment/Apply, and exact authorized pins never move silently.

### J-16 interactive editorial dialogue

The dialogue is attached to an exact Book/work object and Task context and may be hosted inside Agent Workspace, but neither becomes AI7's product root. `Interactive Stream` is the sole progressive-Provider-content exception; every other task type remains Waiting Only. Foreground presentation may show a transient Live Reasoning Summary and then semantic answer fragments, while background presentation is only `等待回答` and has no execution consequence. Stop/interruption retains only complete fragments as an Incomplete Dialogue Answer and creates no silent Retry or fallback. Questions and answer attempts remain recoverable across restart through exact Execution Binding/Span joins to the Harness Session Ledger, but reasoning summaries do not; no third ledger or Task Ledger transcript copy is created. Even a completed answer remains generated content until an explicit named action begins a separate governed Proposal, Task Intent Draft, or other object; any later formal manuscript mutation follows J-05. The draft does not become the `Task Input / 任务输入` checkpoint purpose unless D-075 later applies.
