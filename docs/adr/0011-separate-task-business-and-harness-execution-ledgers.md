# Separate task-business and Harness-execution ledgers

AI7 uses one causal graph with two authoritative persistence planes: the Task Ledger owns task-business facts and provenance, while the Harness Session Ledger owns the model/executor event stream. Exact Execution Bindings and Harness Execution Spans join them without copied transcripts or inferred causality. The legacy Operation Record, Operation Event, `operationRuns`, and Operation Checkpoint are retired from the active model; their valuable facts move to Run Records, Workflow Instances, named decisions, Domain Commands, Effects/receipts, and Run Continuation Checkpoints. This avoids a competing execution loop and duplicate audit history while preserving AI7 authority, restart safety, and stable Effect identity across Harness attempts.
