Its instruction paragraph excludes a house person's name; amended [ADR 0079 §4.4](0079-record-the-owner-s-decisions-of-2026-09-10-on-storage-policies-export-egress-providers-and-samplebooks.md#4--network-egress-in-the-product) says both new categories are without any person's name. That mechanism does not recognize every possible person's name in arbitrary new instructions. No name-detection claim, compliance checkbox, missing known-name match or user assertion can substitute for the current rule. This proposal resolves that content restriction for one deliberate instruction use; it does not declare a filter sufficient by assumption.

## 1. Accepted decision and exact scope

Later precedence ([ADR 0099 §1](0099-distinguish-public-release-from-scoped-global-agent-processing.md#1-proposed-decision-ordinary-production-original-field-processing)): this branch's privacy exclusivity — ‘only the following instruction processing’ and ‘every other part of the same Run's payload … keeps its existing redaction’ — yields to [ADR 0099 §1](0099-distinguish-public-release-from-scoped-global-agent-processing.md#1-proposed-decision-ordinary-production-original-field-processing) for other independently admitted original fields and purposes, including this Run's manuscript units and guideline clauses where they independently qualify. The branch's own conditions are unchanged: the House-authored saved `editorInstruction` of at most 1,200 graphemes with exact version attribution, the explicitly started foreground `editorial-review/typos-and-usage` Run, the bound Main Editorial Role, the tools-free pipeline with no web, secondary recipient or subagent, and its origin limits. ADR 0099 permits no run of this branch under another role or origin; a successor still distinguishes the authored branch for those reasons, and [ADR 0099 §1](0099-distinguish-public-release-from-scoped-global-agent-processing.md#1-proposed-decision-ordinary-production-original-field-processing) is no review-wide flag either.

After the recorded Owner acceptance of this exact text, dependent-clause alignment, a separately reviewed/selected immutable policy successor and a faithful runtime consumer, **only the following instruction processing** may send a person's name, a house-person role or deliberately supplied private-note wording without removing or refusing it solely for that reason:

- Ordinary-production, one explicitly started foreground `editorial-review/typos-and-usage` Run using an editor-selected saved immutable Procedure Definition authored by the House and the existing tool-free typos template.
- Recipient: the provider bound in that Run to the editor's configured **Main Editorial Role**. This exception does not follow a switch to Fast Role or another recipient. ADR 0080's older row 5 names Fast Role for the general typos entry; §3 qualifies only this authored-procedure branch and leaves other assignments unchanged.
- Source: the exact saved `editorInstruction` that the editor deliberately entered or explicitly retained when editing/capturing that procedure version. At most 1,200 graphemes, attributed to the exact Procedure Definition identity/version/document digest. The user-visible title and local provenance are not additional model inputs.
- Execution: the existing chunked-review → local synthesis/reducer → derived-report pipeline, with no local or platform tools, web, new model synthesis stage, secondary recipient, subagent or background origin. Existing queued/resumed units remain part of the same explicitly authorized foreground Run; “human-attended” does not require a new click for each unit or physical presence throughout execution.
- Authority: ordinary preparation/start disclosure names the actual instruction, selected version, sources and recipient; normal Run Authorization authorizes that frozen processing. No extra privacy checkbox, per-request authorization or second start confirmation is introduced. Procedure enablement alone grants no processing.

“Instruction processing of ADR 0100 §1” in §3 means exactly this conjunction and covers only that saved instruction text: every other part of the same Run's payload, including its manuscript units, category guidelines and guideline clauses, keeps its existing redaction and category rules. A successor rule must distinguish this authored branch from other typos runs and other review kinds; flipping a shared review-wide name flag would exceed it. This is a content exception within the existing `editor-task-instruction` category, not category-free processing or a new outbound category.

A Deferred Start (空闲时处理), Background Processing Enrollment, other background origin or Default Execution Rule cannot start this exempt processing. Queuing or explicitly resuming units of the same authorized foreground Run, or moving its presentation into the background as Run Authorization already allows, does not change its origin or create a new permission.

The instruction remains subordinate to AI7's product-built contract. It cannot replace framing/output schema, expand readable sources, grant a tool/recipient, alter the Run ceiling, claim factual authority or mutate a manuscript. Every finding still passes exact-anchor validation; only the normal single-use Apply changes manuscript text.

Deliberately typing or pasting note wording into the saved instruction is editor input, **not permission to read an Editor Note object** or its anchored manuscript. No note picker, note-object retrieval, automatic note copying, note-to-learning admission or hidden source reconstruction follows. Capture may retain only the source Run's already-frozen instruction through the explicit procedure-capture flow; it does not recover words that were removed or read a note/manuscript to recreate them. Capture copies no note/manuscript source content, findings, decisions or source authority into reusable procedure content; it retains only the actual frozen instruction.

No ambient Book/library/memory/Working Corpus read is granted. The Run's actual manuscript/material sources retain their own explicit source grants, pins, current availability and applicable eligibility/exclusions. The saved instruction is not a side route for an unbounded source corpus or source-object read. Nothing in this proposal changes those source contracts or claims that mere provider configuration grants processing.
