# Retire runtime policy locks and frozen fixture admission

The Owner's [2026-11-12 D2 decision in #1453](https://github.com/zhouy1017/ai7-harness/issues/1453) opens product runtime manuscript processing and retires static policy SHA-256 locks. The [2026-11-14 decisions](https://github.com/zhouy1017/ai7-harness/issues/1458#issuecomment-6870691052) state: 「samplebook应当保留，但是无需要求验证指纹，不能只用合成样本进行检测」 and authorize recording expressed Owner intent directly as accepted. This record implements that bounded decision under #1472; it grants no publication, repository manuscript admission or live-test authorization.

1. Model processing no longer selects, reads or fingerprints Provider Processing documents or an active-policy-set manifest. Configured channels supply their protocol, endpoint and credential slot; valid custom model IDs inherit the channel encoder. Runtime recipes and execution limits live in `config/runtime-execution-defaults.json`, with no model inventory or document fingerprint admission. This bundled, non-editor-overridable projection comes from the former v35/v24 task rules. It still registers task kinds and origins, material/deliverable/clarification and synthesis composition, fixed source envelopes, registered tool schemas, search backends, counters and deadlines; consumers refuse missing, ambiguous, malformed or mismatched task compositions. These rules decide what an implemented task consists of, including its authorized pinned sources, rather than which manuscript words or configured model may be processed. Material flags and tool-schema equality stay as composition rules where they describe implemented task inputs. A flag cannot close an otherwise implemented content path: ordinary-production 初评 already implements frozen Series scopes and their read-only unit/synthesis context, so its recipe enables Series knowledge; Series selection is not a policy permission. One ordinary-production content gate remains: a procedure with an editor instruction still requires the existing editorTaskInstruction recipe prerequisite, exactly as in 0.7.0. Opening it exposed incomplete task-authorization/profile-digest reconstruction for 初评, so the Commander explicitly deferred that work to [#1476](https://github.com/zhouy1017/ai7-harness/issues/1476), coordinated with #1455. This is incomplete composition, not a policy decision; the editor is told that this task does not yet support a procedure carrying an editor instruction. Already-supported recipes retain their base behavior; no incomplete procedure kind is newly opened. #1476 owns removing this remaining prerequisite after proving preparation, authorization and execution end to end. Frozen source revisions, exact prompt derivation, exclusion guards, stage definitions and budgets still apply. The R1 reducer descriptors themselves are unchanged. Search-backend registry equality is tested so the projection cannot silently omit a registered backend. The three frozen R1 reducer descriptors remain owned by #1471. The final transport boundary retains current binding, retained-output/tool provenance, execution budget, cancellation and circuit breaking.
2. Frozen fixture-manifest admission retires with the lock. `LocalFixturePolicyCatalog` retains compatibility with historical callers but reads no policy document, compares no fixture or lineage bytes with a frozen inventory, and supplies the loaded fixture's entries. Fixture parsing, request lookup and capture provenance remain. SampleBooks and SampleBook-based fixtures stay in tests. No new fixture fingerprint is introduced; the existing developer-live Public SampleBook source fingerprint boundary stays. Existing request/result digests describe particular execution data; they are not an admission inventory.
3. Existing persisted `policyPin`, `selectedPolicyIdentity` and `retainedPolicyPin` values remain readable without a destructive migration. New records keep their existing columns and use active-set marker `no-policy-lock` and fixed zero digest placeholders. Existing version fields (`v1`, `v24`, `v35`) identify compatibility shapes, never a policy selection. Historical record readers retain the original values; resuming an analysis reads no policy file. No database schema or protocol version is raised by this slice.
4. **The External Export Policy fingerprint no longer gates model processing; export eligibility and effect authority are unchanged and remain with `ManuscriptExportStore` in `src/service/manuscript-export.ts`, database-export preparation/approval in `EditorialStore`, and the existing delivery-package export/job owners.** Service export handlers formerly consumed the verified launch's `currentExportEffectAvailable`; they still receive the same available capability, now independent of policy bytes. Every existing preparation, review digest, destination, approval, staging, atomic write and outcome-receipt check remains in its existing owner. No new export check replaces the fingerprint and no existing export check is removed. This independently reversible clause supersedes only the launch/retained-analysis External Export v2 fingerprint prerequisite and active-set coupling of ADR 0046's selection contract and ADR 0079 §2.5; ADR 0079 §3's export eligibility and approvals stay.
5. `development-ci` still installs process-wide network denial before service owners load and receives no live runtime transport. Model, search, public-fetch and discovery/probe transports remain blocked. Public URL, DNS, private-IP and redirect checks of ADR 0074 §3 stay, as do protected-secret storage and final-consumer credential release, cancellation, budgets, circuit breaking and provenance retraction. Results retain their frozen `model@effort` mark. Repository protected-material rules and provider-free CI/Gate remain. Developer-live transmits only the admitted Public SampleBooks, checked by the existing exact source bytes/SHA-256 set (including tester edits within an imported sample1 Book), and the existing authored public material passage for translation. Ordinary production may send the editor’s manuscripts; development-ci may analyse any Book on the local fixture route because it has no network transport. The R1 reducer descriptors and verified-quote text exception are unchanged; #1471 owns their successor.

The superseded clauses are runtime document selection, exact digest verification, default-deny model/tool/content admission and selected-successor prerequisites in ADR 0046 (Decision, Ordinary production authority and Retained stricter Policy rule), ADR 0080 §§4/7, ADR 0088's policy-bound dialogue contract, ADR 0095 §6, ADR 0099 §§1/4/5/6, and ADR 0100/0101's selected-policy/content-scope prerequisites. Their independent task, source ownership, effect and publication authorities remain. ADR 0065's exact launch-policy carrier and ADR 0079 §2's active-set bundling cease to govern runtime processing. Provider Processing v1–v35 and active-set v1–v26 runtime restriction clauses, including v29's `legacyLocalFixtureCompatibility`/`fixtureReplayRules` and manifest SHA-256, are historical records rather than executable admission. ADR 0044’s frozen reviewed-fixture fingerprint admission is superseded; its provenance and sample1 compatibility baseline stay. ADR 0091’s application of the source set to local development-ci analysis is superseded; its repository source bytes/SHA-256 and developer-live Public SampleBook boundary stay.

Historical policy JSON, schemas and projections remain in Git and are not shipped by the build. The policy index identifies their historical role. This ADR changes neither underlying model requests nor prompt contracts; developer-live recordings are not invalidated by this retirement alone.
