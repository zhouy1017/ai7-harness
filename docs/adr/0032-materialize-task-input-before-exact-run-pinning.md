# Materialize task input before exact Run pinning

Whenever a Task would use acknowledged Edit Journal state newer than the latest Manuscript Revision as manuscript target, range, source, or evidence, AI7 creates a Manuscript Checkpoint with purpose `Task Input / 任务输入` before it produces a Plan Preview or Run Authorization. The checkpoint creates an immutable reconstructable Manuscript Revision without creating a Milestone Version or Signoff. Every attached manuscript target, range, source, and evidence reference—including a Pinned Manuscript Range on the prior revision and a pending draft range—must exact-resolve on the resulting revision and create a new task-bound pin; the original pin and its provenance remain immutable. A changed or ambiguous reference that cannot exact-resolve preserves the checkpoint and Task draft but blocks planning/authorization until explicit reselection or removal. The Task Intent, resulting pins, sources, evidence, Plan Envelope, and Run then bind that one exact revision; later edits do not retarget them, and checkpoint failure preserves the Task draft and journaled work while blocking authorization. This keeps continuous editing lightweight while ensuring every authority-bearing model task and its evidence can name one reconstructable textual state.

## Considered options

Binding directly to journal offsets would make the Edit Journal a second revision authority and complicate exact reconstruction. Requiring the editor to create a Milestone Version would add unrelated lifecycle meaning and ceremony. Silently checkpointing without a purpose label would preserve text but make the additional revision difficult to interpret in history.
