# Keep one agent-loop implementation and schedule from AI7

Harness owns the generic agent loop — the cycle that assembles context, calls the model, dispatches tool calls, and repeats until a stop condition — and AI7 never writes a second implementation of it. The prohibition is about implementations, not instances: ten Books worked at once means ten Harness Sessions each running an instance of the same loop, which is not a second loop any more than many browser tabs are many browsers. Parallel Runs across multiple Books, together with background analysis and learning work, are required product behavior rather than a tolerated exception. A genuine second implementation is refused because four accepted decisions would break: the Session Ledger would stop being the authoritative execution record, ambiguous-outcome handling would have two answers, the capability guard would have a hole in one dispatch path, and the request-fingerprint guard would leave replay evidence silently partial.

AI7 schedules; Harness converses. AI7 decides what work exists and when it runs — Runs and their business state, Workflow Instances and gates, start and pause and resume and cancel, concurrency, usage observation and optional explicit Run Budget Ceiling enforcement across Books, Effects and receipts, and background jobs such as indexing, metric computation, and diffing that involve no model at all. Harness decides how one unit of agent work executes: turn and step structure, tool dispatch, in-turn transient retry, subagents, context compaction, and Session events. Business scheduling does not use Harness `schedule`, `jobs`, or workflow packages, since those weaken durable business continuation and, under the package-subset rule, are most likely not installed at all — making the boundary structural rather than conventional. Parallelism makes two things AI7's responsibility: an instance-level concurrency governor plus isolation of each Run's exact ceiling/usage state, and strict non-sharing of scratch and cache between concurrent Runs on different Books. ADR 0033 refines the budget clause: the AI7 Run Budget Ceiling defaults to `unset`, while Provider Account Limits remain external service blockers rather than shared scheduler capacity.

AI7 learns the Harness framework rather than cloning it. Harness is built primarily for agentic coding while AI7 works in specialized Chinese literary publishing, so AI7 takes the agentic capability that makes the editorial job better without adopting Harness's purpose or product shape. What is adopted is composition machinery: profiles, bundles, presets, plugins, context assembly, tool pipelines, policy seams, and deterministic replay. What is not adopted is its coding-agent identity, its default presets and prompts and persona, its default tool set of shell and terminal and generic filesystem and web, and its web surface. Adopting a framework is not adopting its defaults — every Harness default that reaches an editorial Run must be justified for publishing work rather than inherited because it shipped, and AI7's own Agent Behavior Assets are authored for editorial work rather than adapted from coding presets. This is why "full engine" means full composition capability rather than the full package set.
