# Ship portable and installer channels with a self-contained data root

Status: **accepted for Windows; macOS distribution and data-root policy are opened by ADR 0027**

AI7 ships two Windows channels, a zip portable folder and an NSIS installer, produced by the same builder from the same source so that neither is a separate product. The portable channel is the reason this Windows design exists: the intended users are publishing professionals on managed corporate machines, and needing no admin rights, no registry writes, and no IT ticket removes a real adoption gate. The predecessor shipped portable builds for the same audience, and dropping the embedded Python interpreter makes the folder substantially smaller. The installer serves users who simply expect one. This revises the original decision, which shipped portable only and deferred an installer until a concrete need appeared. ADR 0027 does not copy this channel shape to macOS; its native package, update, mutable-data, signing, and notarization design remains open.

In the portable channel the Agent Data Root lives inside the AI7 folder, so that installation is genuinely self-contained: copying the folder moves the work, and backing up the folder backs up everything. Program files and user data are separated within it — `app/` is replaced wholesale on update while `data/` is preserved — and the data root carries a version marker so an older build refuses newer data rather than corrupting it. Where the folder cannot host a writable data root, AI7 detects this on first run, falls back to `%LOCALAPPDATA%\AI7`, and says plainly where the data went rather than failing silently. Under the two-channel revision that fallback stops being an edge case and becomes the installer channel's normal path, since an application installed under Program Files cannot write beside itself; the rule is unchanged, only its frequency. The Protected Secret Store is the deliberate exception in both channels and stays outside in Windows Credential Manager behind the Credential Broker, because a portable folder is designed to be copied and a copied folder carrying credential material to another machine would be a real leak.

The residual exposure is that portable folders end up on synced cloud drives, which would carry every manuscript off the machine. This does not violate the egress rule as written, since that rule governs paths AI7 automates while folder placement is a user decision, so the mitigation is detection rather than a different default: AI7 warns clearly, in editorial rather than technical language, when its folder sits beneath a known sync or backup root, and the warning informs without blocking because the user is authorized personnel. Because user data lives inside the application folder in the portable channel, ADR 0016's prohibition extends to the whole folder, which must never sit inside a repository working tree. Release verification covers both channels — extract, first-run data-root creation, launch, canonical journey, and removal leaving no residue for the zip; install, launch, canonical journey, and uninstall for the installer. Code signing is deferred until the owner explicitly requests it; unsigned builds trigger SmartScreen, which for a non-expert user on a corporate machine is a hard stop rather than a warning, so this is recorded as a known adoption cost to be paid when chosen rather than as a cosmetic gap.
