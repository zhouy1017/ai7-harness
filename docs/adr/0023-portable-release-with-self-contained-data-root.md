# Ship a portable release with a self-contained data root

AI7 ships as an all-in-one portable Windows folder and this is the only V1 release channel: no installer, no admin rights, no registry writes. The intended users are publishing professionals on managed corporate machines, so removing the installer removes an IT gate and is an adoption lever rather than a convenience. The predecessor already shipped portable builds for the same audience, one artifact suits the concise verification contract better than two, and dropping the embedded Python interpreter makes the folder substantially smaller. An installer is deferred until a concrete need appears.

The Agent Data Root lives inside the AI7 folder, so an installation is genuinely self-contained: copying the folder moves the work, and backing up the folder backs up everything. Program files and user data are separated within it — `app/` is replaced wholesale on update while `data/` is preserved — and the data root carries a version marker so an older build refuses newer data rather than corrupting it. The Protected Secret Store is the deliberate exception and stays outside, in Windows Credential Manager behind the Credential Broker: a portable folder is designed to be copied, and a copied folder carrying credential material to another machine would be a real leak. If the folder sits somewhere unwritable, AI7 detects this on first run, falls back to `%LOCALAPPDATA%\AI7`, and says plainly where the data went rather than failing silently.

The residual exposure is that portable folders end up on synced cloud drives, which would carry every manuscript off the machine. This does not violate the egress rule as written, since that rule governs paths AI7 automates and folder placement is a user decision, so the mitigation is detection rather than a different default: AI7 warns clearly, in editorial rather than technical language, when its folder sits beneath a known sync or backup root, and the warning informs without blocking because the user is authorized personnel. Because user data now lives inside the application folder, ADR 0016's prohibition extends to the whole folder, which must never sit inside a repository working tree. Release verification is amended accordingly — extract, first-run data-root creation, launch, canonical journey, and removal leaving no residue outside the folder — and the executable is still signed, because an unsigned binary triggers SmartScreen, which for a non-expert user on a corporate machine is a hard stop rather than a warning.
