# Run an Electron shell with an isolated AI7 service process

AI7 ships as an Electron application over three processes. Electron main is a thin shell owning window lifecycle, file pickers, the single-instance lock, data-root resolution, and the sync-root warning. The renderer holds the AI7 UI and editor with context isolation enabled and Node integration disabled. A separate Node process hosts AI7 domain services and the composed Harness runtime, and that process is the one local AI7 authority. Electron is chosen because AI7 is TypeScript and Node and Harness is Node, so a Node runtime ships regardless, and Electron 43.4.0 bundles Node 24.18.1, which satisfies the Harness engine requirement directly. Tauri would add a Rust toolchain while still needing a Node sidecar, since Harness cannot run in Rust — two runtimes to avoid one — and hosting WebView2 directly means writing native glue for a problem Electron already solves.

The service is separate rather than embedded in Electron main for four reasons that each trace to an accepted decision. Parallel Runs are required, so a busy agent loop must never block paint. A provider or Harness failure must not take down an editor holding unsaved text, which the no-silent-loss obligation forbids. The same service must be drivable headlessly, because the ten-minute pull-request gate and the first tracer slice both need it without a GUI, and a service inside Electron main would force every test through an Electron harness. Finally, the instance-level concurrency and budget governor gets a natural home. Inter-process communication uses stdio or a Windows named pipe and never a TCP listener, which removes the exposed-web-server risk structurally rather than configuring it away.

The recorded risk that Electron and native dependencies would conflict with the Harness package stack turns out smaller than written. Electron 43's bundled Node already satisfies the engines constraint, and the core packages AI7 selects are pure JavaScript — the agent loop depends only on a schema library. The native modules live in the sandbox and shell packages that the package-subset decision already excludes, so narrowing the dependency graph defused most of this risk as a side effect rather than by design.
