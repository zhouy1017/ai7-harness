# Edit through bounded windows over a paging manuscript store

Long Chinese manuscripts are a required product feature with three binding tiers, counted in Chinese characters. Below 500K characters there must be no sensible performance degradation and editing must feel the same as with a short document. Up to 1M characters there must be no critical performance issue: operations may be visibly slower, but nothing blocks work and long operations report progress. Up to 10M characters there must be no crash and no unresponsiveness — the application opens, stays interactive, never hangs the UI thread, never exhausts memory, and never loses data, with degraded speed acceptable and breaking not. For scale, 10M Chinese characters is roughly 30 MB of UTF-8 text and between 50,000 and 100,000 Manuscript Blocks at typical prose paragraph lengths, while the existing sample Books at 290K to 396K characters sit inside the easiest tier.

Windowed display is accepted rather than merely tolerated: an editor reads only part of a manuscript at a time, so rendering everything at once is not a requirement. The binding performance constraint is consequently whole-manuscript index time — find, replace, and jump must complete in reasonable time at every tier — which moves the principal risk from the renderer to the store and its indexes. Three indexes are disk-backed and incrementally maintained: a block index carrying identity, order, cumulative offsets, and length so that offset jumps binary-search rather than scan; a CJK-aware full-text index, which must be substring-capable such as a trigram tokenizer because Chinese has no word boundaries and a space-delimited word tokenizer will not serve; and an outline index for navigation. Typing latency depends on window size and never on manuscript size. Because the editor only ever holds a bounded window, the library choice matters considerably less than the store, so the spike's primary target is the paging store and its indexes rather than the editor.

These tiers force the architecture rather than merely describing a goal. The renderer never holds a whole manuscript; the editor always operates on a bounded window of Manuscript Blocks, and that single constraint is what makes the 10M tier reachable. The authoritative document model lives in the AI7 service process over a store that pages by block rather than by whole document. Whole-manuscript operations — search, replace, statistics, verification passes, export — stream over blocks inside the service, are cancellable, report progress, and never touch the UI thread. No unbounded in-memory structure is permitted at any layer, so indexes are disk-backed or explicitly bounded, and the memory ceiling is tested at the 10M tier rather than assumed. Because the editor only ever holds a bounded window, the largest tier is satisfied by the store and the windowing rather than by the editor library, which makes the editor choice more robust rather than less.

ProseMirror is the editor foundation. Its schema-validated node tree maps onto Manuscript Blocks, its first-class positions let Task Intents, findings, quotations, proposals, and Effects anchor exactly, its composition handling is mature enough for Chinese input, its decorations annotate without mutating text, and its steps and transforms map onto Proposal Branch comparison. Slate is rejected for IME fragility that is disqualifying in Chinese-first work, CodeMirror 6 is built for code rather than structured documents, and a custom editor is what the predecessor's 26,484-line renderer was and what the Standalone-only decision already rejected. Lexical is the credible alternative but carries a thinner ecosystem for tables and comment anchoring. Each loaded window is its own ProseMirror document with its own coordinate space mapped to global block identities, while whole-manuscript navigation uses an outline that never materializes text. Confidence in the library choice is medium, so an early performance gate proves the tiers against generated corpora and the real 396K-character sample before the editor is built out — not at the end, where the Standalone Editing Sufficiency Gate would discover the problem too late to act on it.
