# 0096 · Edit manuscript structure, recognize structure on import, and remove editor-facing ceremony

On 2026-10-23 the Owner accepted the assessment that the manuscript editor cannot split, merge, insert or delete a paragraph or change a heading level, that a DOCX without Word heading styles enters AI7 as one unstructured run of paragraphs, that footnotes are neither shown nor editable, and that several confirmations, identifiers and one static status label stand between the editor and the work. This record decides the editor-side changes; [ADR 0095](0095-make-procedures-the-central-object-govern-concurrent-execution-and-use-dsh-as-the-complex-task-harness.md) decides the execution side. It is design, not implementation; [PROGRESS](../../PROGRESS.md) owns delivered behavior.

## 1. Structural edits are ordinary edits

Splitting a paragraph, merging two, inserting or deleting one, and changing a heading's level are ordinary manuscript edits recorded in the Edit Journal as **structural edit kinds** beside the single-block text replacement that exists today. Each records the lineage ADR 0006 requires — which blocks a new block descends from, and which block absorbed a merged one — so that pinned ranges, marks and reimport comparison keep resolving. A ranged 修改建议 whose text a structural edit touches becomes a Drifted Manuscript Range exactly as ED-044 states. Enter splits at the caret, Backspace at the start of a paragraph merges with the previous one, and both work inside the bounded window with no round trip the editor must wait for. Hierarchy changes across many headings and section moves remain Structure Adjustment Mode (ED-018), deferred in F-15.

Owner #1279 / #1288 clarify this ordinary-edit surface: successive keys queue locally while journal writes stay ordered; Enter at a title or heading's end creates a plain paragraph; the paragraph-style selector switches one block between body and heading styles. Existing text-and-style-bound command digests carry each style change through undo, redo and recovery. Automatic import pieces remain reimportable with their source paragraph and piece lineage. Tables and images use read-only projections from the retained Source Version, keeping original XML/media for DOCX restoration rather than persisting a lossy editable table or image copy.

Two block kinds join title, heading and paragraph: a **note block** that carries a footnote or endnote with its reference position, shown and editable in the manuscript, and a **table block** that shows a table's cells read-only while the table's structure stays with the Source Version; an image is shown read-only from the Source Version. Export restores unedited structures from the original file as today and discloses, per edited structure, what it could not restore.

Applying a suggestion no longer cuts the undo history: the Apply is one more journal entry that `撤销` steps over; reversing an Apply remains the governed reversal Effect of UI ADR 0003.

## 2. Structure recognition on import, and long paragraphs

When an imported DOCX carries no heading styles, AI7 proposes a **candidate structure** from the text itself — lines such as 第X章 / 第X节 / 一、/ 1., short standalone lines between long paragraphs, and a table-of-contents block — and shows it in the import fidelity review as a list the editor confirms, adjusts or declines; nothing is preselected and nothing is committed without the confirmation. Confirmed candidates are written back as heading kinds with their levels. The resulting chapter table drives 选章, 各章 and every report's position label. A manuscript with heading styles behaves as today.

A paragraph longer than the block bound no longer refuses the whole import: AI7 splits it at soft line breaks when the file has them, and otherwise shows the paragraph in the fidelity review with the choice to split it at a sentence boundary or import it as several blocks with disclosed lineage. The block bound stays a bound on blocks, not on imports.

## 3. Less ceremony, more trust

- **Every Book has the built-in editorial capabilities immediately.** Owner #1279 / #1284 supersede the default-profile pin decision: no editor-facing workspace profile, Revision 2 installation or enablement gate remains. Historical carrier identities remain internal compatibility data only.
- **Starting a procedure from its sheet is the one explicit action.** Under Owner #1279 / #1284, each task start prepares and authorizes its exact plan in one action; `查看计划` remains optional. A changed pinned target still requires the current version before dispatch.
- **One decision system on a card.** A 修改建议 card offers `接受并应用`, `修改后接受`, `拒绝` and `转为批注`; the draft dispositions 拟采纳 / 拟拒绝 / 暂不决定 live only in the proposal workspace where batches are prepared.
- **Identifiers live in the technical layer.** Book identifiers, revision and decision identifiers and raw receipts are never printed inline on 书库 cards, in the proposal workspace, in reimport choices or in model settings; they stay one disclosure away as ADR 0071 §1 requires.
- **The processing indicator tells the truth.** The context header's 「本地处理 · 未联网」 label is replaced by a live indicator derived from the execution state: `本地处理` when nothing is in flight, `正在发送至〈渠道〉` while a request is out, `等待网络` during a connectivity wait, and nothing it cannot vouch for.
- **Smaller frictions**: the Main Editorial Role gains the same connection test the Fast role has; `返回` returns to the screen the editor came from; the manuscript surface says 段落, not 内容块; a search result set is marked stale after an edit instead of being discarded; the search query and replacement limits are one value in the service and the surface.
- **The one explicit action reaches further** (Owner #1400 / #1410): `起草` of a 审稿意见, `按我的修改重新生成` of an evaluation report (which first saves unsaved edits and starts nothing when that save is refused), a custom analysis's `运行` and the baseline-update modes start in the same one action; a plan whose route still needs a decision (connection, network or boundary) opens the Task Drawer instead.

## 4. Finish removing editor-facing ceremony (Owner #1400 / #1414)

The Owner's 0.6.1 human test (#1400) found that the code still asked for a second confirmation after the system Save dialog, four steps for a whole-manuscript replacement, administrative forms for milestones and Publication Versions, impact previews before ordinary one-click changes and `不会做` disclaimers on every ordinary screen — because the ADRs, the UI requirements and the editor-surface standard still prescribed them. Under the Owner's #1400 session authority (and [#1279](https://github.com/zhouy1017/ai7-harness/issues/1279)) Issues #1401–#1413 removed them on `codex/integration-1400`; #1414 records the result here and amends the named clauses in place. Service validation, stale/drift guards, persisted decisions, events, Effect Approvals, receipts and the request protocol are unchanged: only the editor-facing preview and approval clicks are gone.

### 4.1 The editor's own choice is the action

When the choice the editor has just made already fixes the exact consequence, AI7 validates and commits in that same step. For the task starts migrated under [ADR 0104](0104-launch-tasks-with-an-immutable-execution-snapshot.md), start captures one execution snapshot and creates the runnable task atomically, without a prepared/awaiting-approval phase:

- **Export.** Choosing the place in the system Save or folder dialog is the final export authorization — for a manuscript, a document, a review report, a 审稿意见 draft, the Book delivery package (folder or archive) and the database export. AI7 binds the Local Export Preparation to the returned target and records its Effect Approval and per-file receipt at once; native cancellation writes nothing, and `按上述方式导出` survives only as a retry after a refused write. A delivery package defaults to the purpose 常规交付打包 with every available file included.
- **Series.** `加入书系`, `移出书系`, `添加检索排除` and `停止此排除` record in one click against the impact read at that click; the impact groups stay on the record. Knowledge and exclusion forms open on their first choice. `纳入书系知识` stays explicit, and a real knowledge conflict still requires editing the candidate or `保留已披露冲突`.
- **Background processing.** `登记后台处理…` opens with the first offered starting point and a 100,000-token ceiling filled in, so one `登记` records the Enrollment; the ceiling stays mandatory and a cleared ceiling holds `登记` with its reason. `撤销登记` is one click and its result says what is kept.
- **Milestone and Publication Version.** `保存里程碑版本` starts on 阶段留档 and an empty label saves as 「阶段留档 · 日期 时间」. `设为发稿版本` opens its compact form on the newest milestone with 发稿范围 `全书定稿` and 依据 `编辑审定通过` written in; a cleared field falls back to them; one press records the designation and its separate internal Public Release Permission.
- **Everyday decisions.** `新建图书` creates the Book in one step with no review page. `接受并应用全部` applies a review batch at once with `撤销本批应用` beside the result; `忽略` is one click with the reason 编辑决定忽略 and `忽略并备注…` takes an optional note. A proposal batch saves and `应用已采纳修改` records and applies. `撤销本次修改` reverses one applied change in one click, still as a new Reverse Apply Effect. `设为快速开始默认` is one click with its binding in a closed disclosure. Import review treats choosing `直接并入正文` as its confirmation, preselects same-Book reuse and reimport lineage, and `接受降级并提交` accepts and commits. Guideline, word-list, library, imported-Skill (service validation kept; a restricted or rejected package stops with its reasons), learning and Series forms complete in one step with a recommended choice selected; `停止今后使用` records in one step. An Agent workspace submission opens its marks; a dialogue answer converts with `转为修改建议` directly.
- **Kept confirmations.** A single concise confirmation remains only for database import or restore, storage migration or cleanup, permanent deletion and cancelling a running task. Judgements on the work itself — accepting or rejecting a suggestion, an evaluation's conclusion and risk levels, reimport ambiguity and gate dispositions — remain unselected.

### 4.2 Ordinary mode carries no not-do lists

With developer mode off, no surface renders a `不会做` list, named non-effects, a fixed disclaimer such as the package or Publication Version sentence, the review sheet's not-do row, the background not-granted list or a credential or legal boundary lecture. Those statements live in developer mode's technical layer and in Help. Ordinary surfaces keep short action and state wording, and every real failure, blocker, refusal reason and the Run Budget Ceiling stays visible. The Task Drawer's 精简 plan reads `处理 · 发送 · 会得到 · 中途` and the writing-task sheet `会读取 · 会发送 · 费用`; each adds its `不会` / `不会做` row only on the technical layer. A statement of what a saved or exported object contains — Export Fidelity Review's `无法导出`, the procedure capture's `不会保存什么` — is a fact about that object, not a not-do list, and stays.

### 4.3 Reading and Revision Mode by default

Owner #1428 replaces the input guard with direct inline revision editing for the manuscript and every derivative document: typing, Backspace/Delete, selection replacement, paste and IME commits edit the text in place. A per-paragraph baseline and grapheme diff create/coalesce editor revision cards after about 700ms or on leaving the paragraph; composition produces no card before it ends and baseline-equal text leaves no card. The persisted 「人工修改自动应用」 preference defaults on: applied cards show clean text and the clickable `✎ 已改` badge; off keeps open cards with deletion widgets, insertion underlines and a margin bar. The journal saves the currently edited text in both states, and card acceptance keeps that text while ignore/reversal writes the original span back through the same journal; undo/redo synchronizes cards and text in one transaction. The journal/card links are additive schema revision 113 and do not change the separate AI7 Apply authority for agent proposals. 「直接改稿（不留痕）」 explicitly opts out of cards; the optional selection-menu 「修改此处」 composer remains available as a deliberate command.

### 4.4 Find and replace without a frozen-set ceremony

`导航` counts only active search hits. Its outline covers the whole Book at full height with its own filter (Enter steps chapters, never searches) and marks the current chapter; 查找 shows `m / N` with ↑/↓ and Enter/Shift+Enter across pages and highlighted contexts; 替换 keeps the replacement field directly under the query. `替换当前处` writes one applied editor revision and moves to the next match. `全部替换（N 处）` is one click: the service prepares, freezes and revalidates the match set internally, then writes one applied, individually reversible editor revision per occurrence in one all-or-none transaction — any failure writes none. Plain `撤销` steps over those Applies as over any Apply. Replacement Preview and the Frozen Match Set are service internals; developer mode shows 替换详情 afterwards. The single-command `commitReplacement` path stays in the service for compatibility but is no editor path, and its manual-replacement learning capture is not produced by per-occurrence revisions.

### 4.5 Scoped AI edits and locks

On the manuscript and on every derivative document, `就选中部分让 AI 修改…` changes exactly the selected words (including a cross-paragraph span with partial ends), and the toolbar's `让 AI 修改…` changes only unlocked blocks of the document or one section; the old refusal of a selection-started AI edit on a Production Document is withdrawn. `🔒 锁定 / 解锁` applies to selected blocks and, from the outline, to whole sections; locks are append-only per-branch events with a lock-set digest. The **Deterministic Scoped Splice & Lock Guard** freezes the base (revision, journal position, each target's block digest and the lock digest), sends targets apart from read-only context, reads only answer entries that name a frozen target, replaces exactly each target's range, and in one synchronous step rechecks the digests before turning each changed target into an AI7 修改建议 applied as its own Effect (so it shows `✎ 已改` with its own undo). Drift applies nothing, an all-locked scope is refused before any model route is consulted, and applying any AI7 suggestion onto a block that is locked now is refused; the editor's own edits are never held back. An evaluation version can lock each scored item and its 总评, strengths and problems: `按我的修改重新生成` leaves locked parts exactly as saved. A writing task never rewrites an existing document: opening its draft creates a new derivative document with new blocks, and opening the same result again returns that document untouched, edits and locks included; iterating on an existing document goes through the scoped edit and the Apply guard above, so no writing-specific lock exists or is needed.

### 4.6 Workbench consequences

The same pass settles the shell rules the editor-surface standard now states (editor surfaces §0.3, §1, §2, §4): the current Book's navigation leads the sidebar and at most three other Books show before `更多图书（N）`; every navigation entry has its own icon and the right edge keeps short labels; cards keep at most two core actions plus `⋯`, show 原文 → 修改后 and hide an empty `更多`; reading continues across windows without paging buttons; the overview is a hero card over a 2×2 grid; review results lead with findings.

### 4.7 Derivative documents and evaluation reports

Derivative documents — 新闻稿, 内容简介, 审稿意见 and the house's other types — live on `稿件` beside the manuscript: every way of creating one asks for its title first and opens it in the editor, and its title is renamed in place without reloading the text. Ordinary mode shows no seven-phase workflow, delivery registration or maintenance form for them; those records stay in developer mode and historical records stay compatible, and the Book delivery package takes saved document versions directly. 评估 opens on AI7's complete report even beside an unfinished hand-started version; `修改报告` begins the editor's version from it, and `按我的修改重新生成` rewrites the words around the editor's unchanged scores, conclusion, risks, readiness, market section and evidence (#1403–#1407).
