# 0097 · Defer every macOS gate and target indefinitely; Windows is the only delivery platform

On 2026-10-24 the Owner directed that the development plan defer every macOS platform gate and every macOS target indefinitely, and that only the Windows platform be considered for now. Until this record, macOS was the second half of a one-product contract ([ADR 0028](0028-support-windows-and-macos-as-one-product.md)) whose public releases alone were on hold ([ADR 0093](0093-automate-nightly-packages-and-windows-version-tag-releases.md)): the hosted full Gate, every nightly candidate and the final-`dev` occurrence still ran on macOS 15 arm64 beside Windows Server 2025, the nightly queue still built an unsigned macOS inspection DMG, the receipt validator and the release helper still required both platform jobs, and the plan still carried a consolidated Windows/macOS re-entry ahead of any release path. Wave 20's integration spent one extra slice ([#1096](https://github.com/zhouy1017/ai7-harness/issues/1096) / [#1097](https://github.com/zhouy1017/ai7-harness/pull/1097)) and three hosted occurrences on a macOS-only Journey failure of a platform nobody ships. This record removes that cost by decision rather than by neglect: it is design and process scope, not evidence about macOS, and it deletes nothing from the tree.

## Decision

### 1 · Windows is the only delivery platform

AI7 is delivered, verified and packaged for Windows 11 24H2+ on x64 only — the zip-portable and NSIS channels of [ADR 0023](0023-portable-release-with-self-contained-data-root.md). The macOS half of ADR 0028's one-product contract is **suspended indefinitely**: no macOS Journey evidence, source-checkout verification, packaging, inspection artifact, signing, notarization, publication or re-entry validation is planned, scheduled, required or claimed, and no date is attached. Suspension is not revocation — ADR 0028's one-product semantics and [ADR 0052](0052-select-the-macos-v1-distribution-and-data-location-profile.md)'s selected macOS profile (macOS 15+ on Apple Silicon arm64, bundle `io.github.zhouy1017.ai7`, a signed, hardened and notarized DMG, the Application Support data root, Keychain) stay the recorded design a resumption would pick up. No Mac edition, lower support tier or second product is created in the meantime; while the hold lasts there is simply no macOS delivery.

### 2 · The hosted Gate runs on Windows only

The one logical, provider-free E2E Functional Gate of [ADR 0027](0027-concentrate-ci-on-e2e-functionality.md) keeps its two occurrences under [ADR 0075](0075-split-the-hosted-gate-into-a-fast-pull-request-lane-and-a-nightly-full-gate.md) and the queue of [ADR 0081](0081-run-the-nightly-full-gate-over-every-open-pull-request-merge-the-ones-that-pass-and-then-over-dev.md); no third occurrence is created. Every occurrence now runs on Windows Server 2025 x64 only:

- the pull-request Gate (`.github/workflows/e2e.yml`) is unchanged — it was already Windows-only and bounded to `GATE_JOURNEYS`;
- the Nightly Full Gate (`.github/workflows/e2e-nightly.yml`) runs its single Windows job over every admitted Journey, whether the queue calls it for the final `dev` tip or the responsible integration role dispatches it against an exact ref; its matrix keeps its form with one Windows entry so that a resumption is a re-addition, not a rewrite;
- each nightly candidate (`.github/workflows/e2e-candidate.yml`) runs the same Windows job and merges when that job passed and the target tip has not moved;
- the receipt validator (`tools/ci/release-authority.mjs`) and the release helper (`tools/release.mjs`) require exactly the Windows job of the occurrence they examine.

"Paired-platform", "both platforms" and "either platform fails" leave the current rules: a successful full Gate is the Windows job completing the whole admitted set. The Local Verification Ladder on the Windows test guests ([ADR 0083](0083-run-every-agent-s-electron-journeys-on-the-background-test-guests.md)) is unchanged and remains the required pre-Ready layer. A guest result is Windows evidence and the hosted occurrence is Windows evidence; there is no macOS evidence source, and none is missing.

### 3 · No macOS target is built

The nightly queue (`.github/workflows/e2e-nightly-queue.yml`) packages its final tested `dev` commit for Windows x64 only; the macOS package job and its `inspection-…-mac-arm64` artifact are removed. Version-tag publication (`.github/workflows/release.yml`, unchanged) keeps publishing the same four Windows files, and its helper verifies one Gate job, one package job and one artifact. ADR 0093's release hold on macOS is absorbed into this wider hold: not only publication but the inspection build itself stops. [ADR 0054](0054-defer-macos-evidence-until-after-initial-v1-0-0-development-milestone.md)'s consolidated Windows/macOS re-entry, which that record placed before any `main` promotion, tag, package or release action, is deferred with the platform; the Windows-only lifecycle — ladder on a guest, fast pull-request Gate, Windows full Gate, Windows packages, Windows publication — is the current and complete release path. Signing, tag creation, publication and `main` promotion keep their separate authorizations.

### 4 · What stays in the tree

This record authorizes no deletion. The macOS code paths and declarations remain as they are, unexecuted and unverified: the renderer's Command-key shortcuts and menu conventions, the Application Support data root and the Finder reveal, the Keychain carrier, the darwin branches of `tools/doctor.mjs`, `tools/electron-runtime.mjs` and the E2E runners, the DMG target of `tools/package.mjs`, the `electron-builder` `mac` and `dmg` configuration, and the darwin entries of `config/dependency-artifacts.json` with their digests and licenses. The macOS row of the source-checkout host matrix is a declared but unverified host. No new macOS-specific work is planned or accepted; a macOS-only problem, if one is noticed, is recorded truthfully in its Issue and is neither a merge blocker nor a priority. The UI requirements' macOS conventions remain written for the deferred platform and are not delivered. Removing any of this is a separate Owner decision.

### 5 · Resumption

Only a new, explicit Owner request resumes any macOS gate or target, recorded as an ADR that names what resumes. Resumption re-adds the macOS entry to the full Gate matrix, the macOS job to the candidate workflow, the `mac-arm64` package job, and the validator's and helper's platform labels, and it runs ADR 0054's consolidated re-entry on integrated `dev` before any macOS claim is made. Nothing resumes by date, by signing readiness, by a green run on a developer's Mac, or by silence.

## Consequences

- The development plan's Waves 20–23 target Windows only; F-12 (Windows package hygiene) and F-13 (the packaged Windows walkthrough) already did, and the method-alignment acceptance of Wave 22 runs on Windows. F-15's deferred pool records the macOS platform hold.
- A full Gate occurrence costs one Windows job; no change waits on macOS runner allocation and no macOS-only intermittency returns a change to Draft. The J-11 robustness fix of #1097 stays — it hardened a shared Journey.
- Every current document that said "Windows and macOS", "both platforms" or "paired" for the Gate, the queue, packaging or evidence now says Windows; historical records — the milestone 1.0.0 scope, earlier pull-request evidence, ADR 0054's pre-boundary disclosures, kick-in reasoning — keep their text as history with a pointer here.
- Resuming macOS later is a bounded re-addition, not archaeology: the removed jobs, labels and matrix entries are recoverable from Git at this record's commit.

## What this record does not do

It does not sign, release, tag or promote `main`; it creates no hosted gate and changes neither the fast pull-request Gate nor the admitted Journey set; it removes no code, pin or UI convention; it does not reopen the Initial v1.0.0 Development Milestone record; it grants no product authority. Implementing the Windows-only workflows is not evidence that they have run — the next nightly occurrence and PROGRESS record that.
