# Remove Actions usage observation from development gating

On 2026-09-03 the Owner directed AI7 repository development to proceed without agent-side attention to GitHub Actions usage and retained independent Owner monitoring with explicit intervention if needed. Agents and the Commander therefore do not query, estimate, report, or consider Actions minutes, balance, allowance, cost, billing, or usage attribution when deciding whether work continues or a pull request becomes Ready or merges. Unknown, unreadable, or apparently insufficient usage is not a blocker, does not keep a pull request Draft, and does not activate the CI-degraded route. The Owner may later issue an explicit instruction based on independent monitoring; until then, repository development follows its source, local-completion, Gate-evidence, and failure rules without a usage prerequisite.

This decision narrowly supersedes [ADR 0057](./0057-restore-hosted-gate-under-observed-actions-usage.md)'s pre-Ready and post-occurrence meter reads, unreadable/insufficient-meter Draft blocker, and usage-driven containment or escalation duties. ADR 0057's restoration of exact workflow `E2E Functional Gate` (ID `342459594`) and [ADR 0049](./0049-bound-hosted-actions-consumption-inside-the-e2e-gate.md)'s Draft-first local-development lifecycle remain current. A product pull request still obtains fresh exact-head Windows Local completion before its single normal Ready transition; that transition starts one paired occurrence running all then-current executable admitted Journeys—currently J-01, J-02, J-08, J-12, J-15, and J-03—on both Windows and macOS. Either-platform product, bootstrap, build, or Journey failure blocks integration. Only the Commander may rerun one clearly external GitHub runner, network, or infrastructure transient without a source change; a second occurrence or ambiguous failure returns the pull request to Draft.

Hosted Gate evidence is established from workflow, run, check, and job status and conclusions. Viewing that state is allowed and remains necessary; it is distinct from querying a billing, minute, balance, cost, attribution, or run/job Usage view. Occurrence identity and multiplicity remain workflow facts, so an unexpected duplicate occurrence is handled as a lifecycle/topology problem without estimating or reporting its consumption.

[ADR 0053](./0053-preserve-local-first-development-through-a-bounded-ci-degraded-mode.md) remains the only bounded fallback when a separately recorded external CI condition genuinely prevents the Gate from producing paired evidence. A usage balance, unreadable usage surface, cost estimate, or usage inference neither activates nor blocks that route. This decision changes no workflow bytes or topology, product or E2E behavior, dependency, Journey admission, Provider or credential authority, payload/log/artifact restriction, public-test-material rule, `sample1` recording or fixture authority, Effect or export authority, publication, distribution, release, or `main` promotion. Product-internal usage observation, Run Budget Ceiling, actual Run cost, and Provider Account Limit meanings are unrelated and unchanged.
