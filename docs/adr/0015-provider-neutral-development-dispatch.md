# Keep development dispatch rules provider-neutral

Repository development uses three agent roles. The Commander decides dispatch, reviews returned work, and is the sole integrator and sole external-action authority. A Worker writes only its own worktree and branch, runs the gate, and reports; it never merges, pushes, publishes, or touches credentials, manuscripts, or private sample Books. A Reviewer is an independent agent that reads a branch with fresh context and returns an advisory verdict, never writing or merging. Every dispatched branch is reviewed by an agent that is not its author, the reviewer's task class is at least that of the work it reviews, and cross-provider review is the default; where the two conflict, the tier floor is hard and cross-provider independence is preferred with disclosure.

Operating rules are provider-neutral and may never be conditioned on which model is running. Layer B of the dispatch contract is the only provider-specific policy surface: it owns the class-to-model table, Worker provider order, and quota fallback, while T0 work is never dispatched at all. Effort ladders differ in length and meaning between providers, so bindings map task outcome to setting rather than matching label to label. Codex normally holds the commander seat at top capability because a persistent seat would drain the scarcer provider. For dispatch-eligible, bounded parallel Worker tasks, the 2026-08-22 owner revision selects the same-class Claude Code binding first until its usable quota is unavailable or exhausted, then uses the existing same-class Codex fallback. Each dispatch records the requested and actual binding plus any exact availability or quota downgrade reason; that operational evidence does not create another policy surface. Fallback is bidirectional and downgrades the provider, never the task class — either provider can be the constrained one, as on 2026-08-17 when Codex was exhausted and Claude was not. This selection order does not transfer Commander, final-integration, external-action, or independent-Reviewer authority.

The legacy multi-agent pilot is rejected as a baseline. Its bespoke lifecycle state machine and its host connector with DPAPI and Windows Hello enrollment had not completed required real-host observations at the audit pin and address a host-authority problem this repository does not have. Cross-provider dispatch needs only a thin shim over installed CLIs. Typed authority requests, replay-safe dispatch receipts, and any richer role taxonomy are deferred behind stated triggers. This design governs repository tooling exclusively; it is not AI7 product runtime behavior, its Reviewer is not a product Review Decision, and its Layer B binding policy is not a Provider Resolution Plan.
