# Send role reasoning effort through protocol families

The Owner's [#1453](https://github.com/zhouy1017/ai7-harness/issues/1453) E1–E3 decisions require 思考强度 to be declared, selectable and actually transmitted, including tool continuation. This implements that decision after ADR 0102; it grants no development live-call authority.

1. `RuntimeExecutionConfig` is defined once in `src/shared/runtime-execution-config.ts`: optional `modelConnectionId`, `modelId` and `reasoningEffort`. Role defaults and dispatch overrides resolve through it; #1455 can pass the same shape. Provider records declare only vendor-documented controls and suggestions, at model level where the protocol differs (Gemini level versus budget). Undocumented routes advertise no control or levels; a manual value is explicitly disclosed as subject to upstream acceptance. Suggestions are not an admission list. A bounded custom identifier reaches the provider; a provider refusal receives an editorial explanation. Unset or `off` omits control and uses the service default, without promising thinking is disabled.
2. Family encoders send Chat Completions `reasoning_effort` (plus DeepSeek's declared thinking toggle), Responses `reasoning.effort`, Messages `output_config.effort` with adaptive thinking, and Gemini model-declared `generationConfig.thinkingConfig.thinkingLevel` or `thinkingBudget`. Gemini 2.5 Pro offers numeric budgets from its documented range; no level-to-budget mapping is invented. Stateless official Responses requests also explicitly request `include: ["reasoning.encrypted_content"]`, with and without a selected effort, so subsequent tool rounds carry reusable native state. These supersede only ADR 0094's unsupported reasoning-control/continuation dispositions. Historical per-model/live evidence remains historical, not a refusal of configured models.
3. Complete native reasoning items, signed/redacted thinking blocks and thought signatures stay in adapter-private replay state, in native order. Chat preserves `reasoning_content`, including preceding assistant turns. The actual DSH loop carries this state through repeated tool rounds. Its accepted-output digest includes the native bytes. The recorded payload digest for new controlled/tool transmissions includes the effort, tool definitions, canonical blocks and the native items that the family encoder will replay. Historical digests remain stored as written and are not recomputed or migrated; uncontrolled text-only payloads retain their predecessor digest. Existing frozen system-prompt equality, closed canonical roles, text-only ordinary blocks, tool schemas, provenance, budgets, cancellation, circuit breaking and network/credential boundaries remain. No thinking block is converted into editorial output.
4. Preparation freezes the actual sent effort in the existing execution route; result cards and task rows use that frozen value. Changing a role default cannot relabel old results. Schema 114 adds nullable main/fast role defaults through the existing channel migrator, preserving schema 113 rows and credential references. The migrator seeds a selected predecessor role's implicit effort from the historical provider record (the DeepSeek thinking profile was high); every other predecessor role stays unset. This preserves its request and attribution when the editor has made no change. It does not rewrite historical result JSON. Protocol 202 and package 0.7.0 remain unchanged for wave closure.
5. Automated verification is provider-free, including buffered/streamed multi-round wire fixtures built from the official protocol documentation cited in the provider records. Existing admitted SampleBook fixtures remain. No fixture fingerprint is introduced and no live recording is regenerated; the PR lists request changes and any invalidated developer-live recordings for closure.

6. Reasoning text and native replay are attempt-memory only for new ledger writes: the live DSH session retains the complete state until its tool loop ends, while the JSONL backend projects canonical reasoning text and private replay state to digests before append. Editorial text, tool calls/results, sequence numbers and terminal events remain durable. No durable mid-tool resume across process death is introduced: the existing interrupted state remains visible, and an editor's continue action opens a fresh technical session from editorial history. This amends only the exact-copy statement for model reasoning in the Harness Session Ledger owner; its append-only storage and recovery contracts remain.
7. Existing session ledgers are not rewritten. Ledgers written before this change may contain model reasoning text where the route returned it; the base already carried DeepSeek `reasoning_content`. These are local files and never part of diagnostics export. `tests/unit/diagnostics.test.ts` proves an injected harness-session file is excluded by the diagnostics allowlist. Dialogue/workspace is the sole production caller enabling session persistence; Fast, analysis and review harnesses retain spans, editorial results and accounting, not raw attempt events. Provider-free wire tests read newly written ledgers for every family and find no reasoning text, signatures, redacted thinking or encrypted items in clear.

Protocol sources read on 2026-11-14: [OpenAI stateless include](https://developers.openai.com/api/reference/resources/responses/methods/create), [DeepSeek thinking and tool loops](https://api-docs.deepseek.com/guides/thinking_mode/), [Gemini levels and budgets](https://ai.google.dev/gemini-api/docs/generate-content/thinking), [Anthropic effort](https://platform.claude.com/docs/en/build-with-claude/effort). DeepSeek explicitly requires reasoning content to be passed back while tools are offered; it is not displayed as an editorial answer.
