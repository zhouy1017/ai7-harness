# Retrieve over manuscripts, returning candidates rather than truth

Long manuscripts exceed any model context window, so AI7 retrieves over the manuscript itself to preserve detail. This extends the accepted Source Search, Exact Fetch, and Synthesis pipeline from imported sources to manuscripts, and places two indexes over the same paging block store doing different jobs: a lexical index serving find, replace, and jump, which is exact, deterministic, and complete; and a retrieval index assembling model context beyond the editing window, which is ranked, approximate, and partial. The rule separating them is the one already accepted for sources and it carries over unchanged — search discovers candidates, and only an Exact Fetch against the pinned Manuscript Revision returns authoritative text. A retrieved chunk is a pointer, never a quotation source, and fuzzy or vector matching can never certify a quotation. This matters more for manuscripts than for sources, because the model is being asked about text the editor is actively changing.

That mutation is the genuinely new problem. Source Versions are immutable, while a manuscript is the thing being edited, so a retrieval index over changing text will feed the model superseded content unless it is revision-aware — and it will do so silently, because a stale hit is indistinguishable from a fresh one. Invalidation is therefore block-level and incremental: Manuscript Blocks carry stable identities, so a changed block is re-indexed alone, and every index entry is stamped with the revision it was built from so that a stale hit becomes detectable rather than invisible, with Exact Fetch against the current pin resolving it. The block model consequently serves three separate jobs — editor windowing, lexical indexing, and retrieval invalidation — which is a strong argument for keeping block identity stable under every operation that touches text.

Retrieval strategy stays open between lexical, vector, and hybrid, to be settled by the store-and-index spike rather than in advance. Two considerations shape that choice honestly: a well-built lexical index performs better for Chinese than is commonly assumed and costs no model call, while vector retrieval at the 10M-character tier means embedding fifty to a hundred thousand blocks, which is real build time and, with a remote embedding model, real cost and a per-block outbound call. A local embedding runtime is viable in Node through ONNX or transformers.js but is a dependency decision rather than a free one. Embeddings and retrieval indexes derived from manuscript text are manuscript derivatives, so they never enter a repository, hosted CI, or a distributable artifact.
