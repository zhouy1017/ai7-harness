# Retrieve over manuscripts, returning candidates rather than truth

Long manuscripts exceed any model context window, so AI7 retrieves over the manuscript itself to preserve detail. This extends the accepted Source Search, Exact Fetch, and Synthesis pipeline from imported sources to manuscripts. The rule separating retrieval from authority is the one already accepted for sources and carries over unchanged: search discovers candidates, and only an Exact Fetch against the pinned Manuscript Revision returns authoritative text. A retrieved chunk is a pointer, never a quotation source, and fuzzy or vector matching can never certify a quotation. This matters more for manuscripts than for sources, because the model is being asked about text the editor is actively changing.

**One authority, many projections.** Chunks, rankings, and embeddings exist for models and agents; the editor reads ordinary text. These are different consumers, and the design does not force them onto a shared unit. The Manuscript Revision is the sole authority. Everything else — the editor's display window, the lexical find index, the outline, retrieval chunks and their embeddings — is a derived projection that is disposable and rebuildable from the authority alone. Each projection may choose boundaries suited to its consumer: a retrieval chunk may span or subdivide the units the editor renders, sized for a model's context rather than for a reader's eye. If a shared block boundary turns out to help windowed display, that is a convenience to exploit, not a constraint to design toward.

What is required is **consistency across forms**, expressed as four obligations. Every projection records the Manuscript Revision it was derived from. Every projection is reconstructable from the authority without reference to any other projection. A change marks overlapping projection entries dirty by text-range overlap rather than by structural identity, so projections with unrelated boundaries invalidate correctly. And a stale entry is always detectable rather than silently served as current, with deletions tombstoned so that absence fails differently from staleness. Re-derivation is cadenced at Manuscript Checkpoints rather than per keystroke, reusing the journal-versus-checkpoint separation already accepted so that staleness has a bounded, explainable window.

Two consequences follow. Because retrieval ranks on projected content, a stale projection produces not merely stale text but a **stale ranking** — a chunk selected on superseded content, while the now-relevant passage never surfaced; fetching fresh text for a stale ranking would look well-formed while being wrong, so the remedy is re-derivation of the affected range and re-ranking, not text substitution. And because a Run pins a revision while the editor keeps working, candidates may be drawn from a newer projection than the pin the answer is bound to; this is acceptable precisely because retrieval yields candidates rather than truth, but it is stated outright rather than left as an accident. Retrieval strategy between lexical, vector, and hybrid is deferred to the store-and-index spike: a well-built lexical index performs better for Chinese than commonly assumed and costs no model call, while vector retrieval at the 10M-character tier means embedding a very large number of chunks with real build time and, with a remote model, real per-chunk cost. Retrieval indexes and embeddings derived from manuscript text are manuscript derivatives and never enter a repository, hosted CI, or a distributable artifact.

## Later refinement

[ADR 0047](./0047-separate-targeted-retrieval-from-covered-manuscript-analysis.md) preserves this targeted candidate/Exact Fetch contract and adds a separate deterministic whole-revision coverage contract for Tasks claiming comprehensive analysis. Retrieval relevance never proves coverage, and covered analysis may not omit a manifest range because it ranked below a top-K threshold.
