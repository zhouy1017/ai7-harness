# Support Windows and macOS as one AI7 product

Status: **platform target accepted on 2026-08-21; consistency contract and platform mechanics remain proposed; supersedes the Windows-only clauses of ADRs 0013, 0014, 0023, and 0024**

AI7 V1 targets Windows and macOS as a Chinese-first Standalone desktop product and must maintain what the owner called a “consistent product outlook.” This supersedes the earlier Windows-only target. The exact consistency boundary is not yet accepted: the current recommendation is one AI7 identity, renderer and visual system, information architecture, core feature set, workflows, domain and authority semantics, document fidelity contract, and release version, while allowing explicit and tested native differences in menus, shortcuts, dialogs, accessibility behavior, filesystem locations, secret stores, local IPC, packaging, signing, and security prompts. That recommendation must not be treated as accepted through silence.

The accepted Electron three-process architecture, ProseMirror editor, TypeScript/Node runtime, Standalone-only scope, Word exclusion, no-TCP local boundary, and Windows zip-plus-NSIS channels remain. The two concise provider-free workflow names, `pr` and `release`, also remain, but their required Windows/macOS evidence topology is reopened. macOS minimum version and CPU architectures, package/update channel, Agent Data Root location, Keychain integration, signing/notarization, and exact release proof are not inferred from Windows and block the Phase 0 exit until accepted. Windows signing remains deferred; that decision does not decide Apple signing or notarization.

The Agent Data Root remains an intended platform filesystem boundary, not a proven one. The audited Harness Windows ACL mechanism is partial, while its macOS Seatbelt mechanism governs file writes but not reads, networking, or process visibility and depends on deprecated `sandbox-exec`. AI7 therefore cannot claim OS-level confinement on either target until a platform design is accepted and verified; AI7 capability and service facades remain the only accepted enforceable product boundary in the interim.
