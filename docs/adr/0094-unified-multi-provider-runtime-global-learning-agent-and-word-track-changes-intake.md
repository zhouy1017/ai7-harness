# Unify model selection, global editorial learning and tracked-change intake

The Owner's 2026-10-22 v3.2 execution guide, recorded by [#1019](https://github.com/zhouy1017/ai7-harness/issues/1019), chooses a Windows-first publishing workflow with selectable model services, DeepSeek/Bocha research, automatic local editorial learning, a Global Agent and two explicit Word tracked-change import modes. These replace the restrictions named below so that ordinary editorial work needs fewer repeated decisions while manuscript changes retain exact human authority. This is accepted design, not implementation or evidence of a working provider protocol; [PROGRESS](../../PROGRESS.md) owns delivered behavior.

## 1. One model-service interface and one governed runtime

Offer one channel → protected credential/connection test → eligible model selection flow in Settings, with a compact channel/model selector in the workbench. Advanced settings may assign the four Model Roles separately. The intended set is OpenCode Zen's Claude/Gemini/ChatGPT families; official Anthropic, Google Gemini, OpenAI and DeepSeek APIs; and all available OpenCode Go models, including its DeepSeek route. Availability means a reviewed declaration, implemented protocol and capabilities, selected processing policy and ready credential; a gateway catalogue alone establishes none of these.

Normalize Chat Completions, Responses, Anthropic Messages and Gemini native requests, streams, tools, usage and failures behind the existing AI7 provider seam and single DSH loop. Adapter/SDK choice is an implementation detail within that seam. Preserve generated typed declarations, capability evidence, protected credential brokering, exact per-attempt binding, preflight, and the final Payload/Egress Gate. Selecting a model never grants source access, processing, Apply or publication authority. No arbitrary endpoint or silent provider/spend fallback is admitted.

ADR 0089's Go DeepSeek target remains the current implemented baseline rather than a permanent exclusive production set. This decision changes intended eligibility; immutable policy versions and launch selections keep their bytes and behavior until separately implemented, reviewed successor policies activate the new set. This session's ChatGPT-only repository/model-use exception is recorded in assignment records, not a rewrite of the standing Orca pairing rules or proof that other providers were tested.

## 2. Research engines remain evidence producers

Adopt DeepSeek WebSearch/WebFetch and Bocha as intended peer research backends with a default-source setting and an optional admitted fallback chain. F-02 must first establish current primary protocol, endpoint, authentication, availability and credential-reuse evidence, using the current official [Search](https://api-docs.deepseek.com/api/search/), [Fetch](https://api-docs.deepseek.com/api/fetch/) and [Search/Fetch guide](https://api-docs.deepseek.com/guides/search/) as protocol inputs. The Commander’s 2026-10-22 primary-source reading identifies those direct APIs, unlike the older Messages-tool measurement. Implementation must verify the exact current contract and non-token call billing; this ADR supplies no live integration evidence and makes no Bocha free-tier claim. A missing capability stays unavailable with a disclosed reason.

Search/fetch runs through existing research capabilities. Freeze backend identity and any eligible fallback candidates in the exact execution plan/binding; record which backend served each result. A change outside that envelope needs renewed authorization. Reuse an existing credential only through the broker and an admitted slot mapping. Keep citation-bound fetching, snapshot provenance, retained-source identity, freshness, assurance and conflict handling. A model answer or accepted wording remains no factual evidence. CI and the Gate stay provider-free.

## 3. Opt-out local learning with intelligent curation

Default local learning admits eligible acceptance/rejection reasons, editor rewrites and imported Word revision pairs into the local Working Corpus learning pipeline, with a visible global off switch and per-Book/material/scope exclusion controls. Show what is collected and its future cross-Book influence; an explicit exclusion or narrower scope wins immediately. This automatic local admission is recorded with its governing basis and provenance, rather than represented as a human inclusion click. It grants no ambient manuscript retrieval, external egress, Series membership or Series Knowledge promotion.

A background Curation Pass filters noise, merges duplicates, identifies recurring patterns and proposes or activates inspectable Global Editorial Memory Items and Editorial Exemplars. Schedule a pass after roughly 5–10 effective decisions or one imported revision batch; six decisions are a trigger to evaluate, not proof that a useful general rule exists. Automatically activate only eligible, sufficiently supported derived editorial preferences inside the disclosed local scope. Preserve title, Editorial Dimension, positive/negative examples, confidence, exact decision/source lineage and activation history. Keep uncertain or conflicting patterns inspectable without inventing a rule. This is retrieval/context adaptation, never Foundation Model training.

The existing scheduler, task/authorization, store and composition owners must carry curation. The disclosed enabled-learning state records an automatic-curation authorization envelope: eligible source/material and outbound categories, selected provider/policy, scope, supervision, budget and disable/exclusion consequences. Threshold/import events may schedule model-driven passes under that active envelope without a repeated per-pass click, with exact task/dispatch provenance and preflight. Local collection alone grants no unrelated egress, and a missing or exceeded envelope blocks the pass. Background Analysis Enrollment remains specific to manuscript analysis; it is not a generic curation grant. Disabling learning stops new capture/curation/use as applicable, and exclusion/remediation invalidates later consumption without rewriting completed history.

Subsequent review, polish and dialogue retrieve the most relevant eligible memory/exemplars (initial target Top-5), pin their exact revisions, and record their actual use. Suggestions identify the preference followed in plain language. Revalidate exclusion, supervision and source/egress eligibility at consumption. A remembered preference cannot turn a factual claim into truth or override the editor's task-specific direction.

## 4. Global Agent alongside the Book-bound workspace

Add the top-level `全域智能体（记忆与全局指导）` destination, usable with no Book open. A Global Agent Session owns dialogue about learning direction and governed cross-Book retrieval; it does not invent a Book or borrow the last Book's manuscript authority. Retain the separate Book-bound Agent Workspace. The foreground Global Agent dialogue may stream under its exact session/turn and explicitly scoped source authority, using the same complete-fragment, citation-binding, interruption and foreground/background rules as Book dialogue. Its history is the existing non-authoritative join to Harness Session Ledger messages, with no third transcript ledger or inferred Book binding.

Each deliberate ask, continue or regenerate action creates an exact dialogue attempt with its selected model/policy, question, eligible memory revisions and declared source scope; the final payload gate rechecks those pins. The session itself never supplies missing read or egress authority.

The controlled operations are learning-direction supervision, memory creation/merge/correction/deactivation, scoped cross-workspace retrieval over manuscripts/research evidence/comments, and a readable editorial-habits summary. Learning Supervision Directives immediately constrain subsequent curation and consumption and freeze or correct affected derived memory with lineage. Scope retrieval to explicitly identified eligible workspace sources/Working Corpus and current exclusions; global entry is no whole-library read or egress grant. Any manuscript proposal returns to its exact Book, revision and normal Apply chain. No generic shell, filesystem or unrestricted network tool is implied.

## 5. Two tracked-change import choices

For a DOCX containing `w:ins`, `w:del`, `w:moveFrom` or `w:moveTo`, show two explicit modes before import, with `转为 AI7 修订建议` recommended/default and the import confirmation committing the displayed choice: `直接并入正文（作为定稿基线）` or `转为 AI7 修订建议`. The first deterministically materializes the selected final text as the initial imported baseline; the second retains the pre-change baseline and exact author-attributed proposal marks for later editorial decisions. Moves keep their linked origin and destination; unsupported or ambiguous mappings are disclosed and blocked or resolved through the existing fidelity review, never guessed.

Both modes preserve the original Source Version and exact before/after Word Tracked Edit Samples for the local learning pipeline when enabled and eligible. Import parsing/sample extraction is local and starts no model call; a later curation job has its own authority. Choosing the imported baseline is an import decision, not blanket Apply permission. Reimport still compares against current work and cannot silently overwrite it; later AI7 suggestion adoption crosses the exact single-use Apply boundary.

## 6. One explicit action for frequent operations

Polish, research and analysis redo may default to a direct action with a concise processing/sending/result summary and a reachable full plan, rather than a mandatory six-section preview every time. The user's click initiates the exact task and authorizes its exact processing/egress after preflight under the displayed default plan or matching Default Execution Rule; internally preserve Plan Envelope, scope, model, policy, budget, immutable custom-dimension pins and Run Authorization where required. Dialogue retains ADR 0088's exact ask/continue/regenerate authority.

If preflight finds a changed material boundary, unavailable binding or unresolved choice, disclose it before dispatch and request the required exact decision. Ordinary editorial tasks never originate from opening a page, importing a file or passive defaults. Automatic curation is the separately governed exception in §3; the enabled learning envelope, not the import itself, authorizes its exact scheduled pass. Review/Apply remains a later separate explicit action: one-click execution cannot accept suggestions, write the manuscript, export or publish. Cancellation, interruption and outcome-unknown semantics remain intact.

## Delivery and proof

Use actual **Wave 18** for authority preparation, then product **Waves 19–22**, as ordered by the [development plan](../development/development-plan.md). The guide's ADR 0093/Waves 17–20 names are illustrative and already occupied; ADR 0093 and completed Wave 17 remain intact. F-01/F-02 share policy, generated configuration and launch owners; F-07/F-05/F-06/F-08 share schema, protocol, store, composition and retrieval. Establish those contracts serially before independent implementation. No new Data Version, destructive migration, signing credential, release or `main` promotion is authorized here.

Walk through a selector change during a Run (re-preflight/re-authorize if outside its binding); unavailable DeepSeek Fetch (disclose, do not simulate support); six noisy decisions (curate without forcing activation); an excluded Book (no later learning/retrieval/use); supervision of a misgeneralized rule (freeze/correct with lineage); both import modes (same preserved original, different explicit baselines/marks); direct polish (exact processing authority followed by separate Apply). Product slices must prove these outcomes with applicable guest Journeys and admitted material. This documentation decision supplies no product or live-model pass.
