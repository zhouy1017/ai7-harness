# Consume a pinned subset of Harness packages

AI7 consumes DeepSeek Harness as exactly pinned public npm packages rather than forking the monorepo or vendoring source. All 219 packages publish under `@deepseek-ai/dsh-*` with an identical version ladder, so the family is coherent when pinned to a single version — but the registry carries a trap that makes how AI7 pins the decisive part of the decision. On nearly every package the `latest` dist-tag still points at `0.0.1-rc.1` while `next` is `0.1.0-rc.6`, so a bare install or a caret range silently pulls a build from two minor eras earlier. Pins are therefore exact versions with a committed lockfile and integrity hashes, one coherent version across the selected subset, never a range and never `latest`. The audited revision `0.1.0-rc.5` was never published, so `0.1.0-rc.6` becomes the consumed baseline while the audited commit is retained separately as provenance; design documents must not imply the two are one artifact. Upstream publishes no git tags and no GitHub releases, so AI7 tracks commits and npm versions itself and will learn of breaking changes by reading diffs rather than receiving notice.

AI7 depends only on the packages its composition needs, and never on the `@deepseek-ai/dsh` CLI aggregate, which transitively installs `dsh-tool-bash`, `dsh-tool-pwsh`, `dsh-shell`, `dsh-tool-web`, and `dsh-terminal` — exactly the generic tool surface ADR 0017 excluded from an editorial Run. Not depending on a package is a stronger guarantee than not wiring it: with the generic tool packages absent from the dependency graph, the narrow surface is a fact about what is installed rather than a configuration choice a later composition edit could quietly reverse. It also shrinks both the upgrade surface and the third-party notices obligation. Every inclusion requires a stated reason; convenience is not one. A source fork is rejected because 219 packages against a fast-moving upstream carry a severe merge burden that composition-by-configuration does not require, and it remains available only after a documented seam gap. The published `dsh-sdk-client` is retained as a fallback process-isolation seam should Electron or Node ABI conflicts force one.

Pin bumps enter through a dedicated pull request, one at a time, verifying the effective composed Cordis configuration diff, the capability exposure diff, session schema compatibility against stored fixtures, AI7 journey replay on the fixed scenario corpus, regenerated third-party notices, and Node and Electron ABI compatibility. Compilation is never acceptance. One exposure is recorded rather than resolved: the published native sandbox addons are Landlock, which is Linux-only, while the Windows-only target sandboxes through a different path. Because ADR 0017 treats an OS sandbox as the outer boundary of the Agent Data Root, that mechanism's actual enforcement strength must be verified on Windows before the boundary is described as enforced; if it proves advisory, the AI7 capability facade is the only real boundary and the design must say so rather than claim a defence in depth it does not have.
