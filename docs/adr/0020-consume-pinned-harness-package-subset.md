# Consume a pinned subset of Harness packages

Status: **accepted; platform package and sandbox consequences are extended by ADR 0027**

AI7 consumes DeepSeek Harness as exactly pinned public npm packages rather than forking the monorepo or vendoring source. The registry carries a trap that makes how AI7 pins the decisive part of the decision: dist-tags are not coherent admission signals. As verified on 2026-08-21, most sampled AI7-relevant packages still expose `latest = 0.0.1-rc.1` while `next = 0.1.0-rc.8`; `dsh-agent-loop` instead exposes `latest = 0.1.0-rc.6`. Pins are therefore exact versions with a committed lockfile and integrity hashes, one coherent version across the selected subset, never a range, dist-tag, or release name. The audited revision `0.1.0-rc.5` was never published, so `0.1.0-rc.6` remains the accepted consumed baseline while the audited commit is retained separately as provenance; design documents must not imply the two are one artifact. That baseline is not implementation-ready until Phase 0 identifies the candidate subset and audits the rc.5-to-rc.6 delta across its exact closure and AI7 seams. Native installed-closure and ABI proof belongs in separately authorized disposable audit environments on Windows and macOS, not in this design repository. Upstream now has Git tags and GitHub pre-releases for rc.7 and rc.8; neither is adopted and either may enter only through the pin-bump contract below. AI7 tracks tags/releases and commits together with npm versions/dist-tags because no one channel is admission authority.

AI7 depends only on the packages its composition needs, and never on the `@deepseek-ai/dsh` CLI aggregate, which transitively installs `dsh-tool-bash`, `dsh-tool-pwsh`, `dsh-shell`, `dsh-tool-web`, and `dsh-terminal` — exactly the generic tool surface ADR 0017 excluded from an editorial Run. Not depending on a package is a stronger guarantee than not wiring it: with the generic tool packages absent from the dependency graph, the narrow surface is a fact about what is installed rather than a configuration choice a later composition edit could quietly reverse. It also shrinks both the upgrade surface and the third-party notices obligation. Every inclusion requires a stated reason; convenience is not one. A source fork is rejected because 219 packages against a fast-moving upstream carry a severe merge burden that composition-by-configuration does not require, and it remains available only after a documented seam gap. The published `dsh-sdk-client` is retained as a fallback process-isolation seam should Electron or Node ABI conflicts force one.

Pin bumps enter through a dedicated pull request, one at a time, verifying the effective composed Cordis configuration diff, the capability exposure diff, session schema compatibility against stored fixtures, AI7 journey replay on the fixed scenario corpus, regenerated third-party notices, and Node and Electron ABI compatibility on every supported platform. Compilation is never acceptance. The consumed package closure must also be inspected per platform: `dsh-sandbox-local` pulls platform-specific native dependencies even though AI7 excludes the generic shell/tool surface. Harness Windows ACL confinement is partial; its macOS Seatbelt profile governs file writes but not reads, networking, or process visibility and depends on deprecated `sandbox-exec`; and its local credential provider is not an OS-keychain boundary. None may be promoted into an AI7 security claim without an explicit accepted seam and installed-composition proof.
