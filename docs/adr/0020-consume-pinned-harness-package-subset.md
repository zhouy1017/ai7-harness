# Consume a pinned subset of Harness packages

AI7 consumes DeepSeek Harness as exactly pinned public npm packages rather than forking the monorepo or vendoring source. The accepted consumed baseline is the exact `0.1.0-rc.6` version across the selected subset, with a committed lockfile and integrity hashes; never use a range, bare install, branch, `latest`, or `next`. Registry dist-tags are mutable discovery evidence, not authority: on 2026-08-25 `@deepseek-ai/dsh-agent-loop` reported `latest=0.1.0-rc.6`, `next=0.1.1-rc.2`, while the excluded `@deepseek-ai/dsh` CLI aggregate reported `latest=next=0.1.1-rc.2`. The audited revision `0.1.0-rc.5` was not published at the frozen audit, so the installable `0.1.0-rc.6` baseline and audited commit remain separate provenance facts. Implementation planning verifies immutable metadata for every selected package before locking; if the exact coherent subset is unavailable, it stops for re-scoping instead of mixing eras. Upstream publishes no git tags and no GitHub releases, so AI7 tracks commits and npm versions itself and reads diffs rather than treating a dist-tag as a release signal.

AI7 depends only on the packages its composition needs, and never on the `@deepseek-ai/dsh` CLI aggregate, which transitively installs `dsh-tool-bash`, `dsh-tool-pwsh`, `dsh-shell`, `dsh-tool-web`, and `dsh-terminal` — exactly the generic tool surface ADR 0017 excluded from an editorial Run. Not depending on a package is a stronger guarantee than not wiring it: with the generic tool packages absent from the dependency graph, the narrow surface is a fact about what is installed rather than a configuration choice a later composition edit could quietly reverse. It also shrinks both the upgrade surface and the third-party notices obligation. Every inclusion requires a stated reason; convenience is not one. A source fork is rejected because 219 packages against a fast-moving upstream carry a severe merge burden that composition-by-configuration does not require, and it remains available only after a documented seam gap. The published `dsh-sdk-client` is retained as a fallback process-isolation seam should Electron or Node ABI conflicts force one.

Pin bumps enter one at a time as explicit development changes. Under ADR 0027, only applicable Windows-and-macOS complete E2E journeys and observed-bug regressions are standing verification; composition diffs, capability-exposure diffs, schema checks, notice regeneration, ABI checks, and replay do not become separate gates. Applicable third-party notices still remain current in every build. The published native sandbox addons are Landlock, which is Linux-only, while Windows and macOS require different platform mechanisms. Until either mechanism justifies a stronger claim, the AI7 capability and service facades are the enforceable boundary and the Agent Data Root must not be described as whole-process OS confinement.
