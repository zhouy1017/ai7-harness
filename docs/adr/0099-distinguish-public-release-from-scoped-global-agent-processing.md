## Context

The [Editorial context](../domain/editorial/CONTEXT.md) distinguishes Unpublished Editorial Material from Public Release Permission: internal editorial processing and public release are different actions. An inference request to the editor's configured provider is not publication merely because its endpoint is internet-accessible. Processing still needs its own source, policy and execution authority; provider configuration alone supplies none of them ([Execution context](../domain/execution/CONTEXT.md)).

[#1071 decision 2](https://github.com/zhouy1017/ai7-harness/issues/1071#issuecomment-6379596688) records the Owner's principle that ordinary-production Book-less Global Agent dialogue has no outbound-category restriction, with disclosure retained and categories used for bookkeeping. The [Commander's application](https://github.com/zhouy1017/ai7-harness/issues/1071#issuecomment-6381981177) quotes the Owner's words 「在生产状态下不设限 … 隐私限制公开发布，不限制向LLM供应商传输」 and also proposed removing house-people/internal-note redaction, but the [controlling correction](https://github.com/zhouy1017/ai7-harness/issues/1071#issuecomment-6382289920) superseded that application: accepted ADR 0079 §4.4 requires an Owner-accepted amendment naming its affected clauses. The [v27 landing record](https://github.com/zhouy1017/ai7-harness/issues/1071#issuecomment-6383282475) retains redaction. Recorded intent is not acceptance of this exact proposal. The correction's “v28 lifts the redaction” named a then-future successor: [#1121](https://github.com/zhouy1017/ai7-harness/pull/1121) now prepares unselected candidates v28 (ordinary production, redaction retained) and v29 with candidate set v20, so a lift needs a separately allocated later successor, and this proposal reserves no number.

## 1. Proposed exception and source boundary

After Owner acceptance of this exact text, dependent-clause alignment and separately authorized policy selection/runtime work, **only human-attended ordinary-production Book-less Global Agent `ask`, `continue` and `regenerate` attempts** (“the Book-less Global Agent attempts of ADR 0099 §1” in §3 means exactly these) may send their already-admitted payload to the Model Provider bound to the editor's configured Fast Interaction Role without stripping words merely because they contain house-people names/roles or internal-note wording.

The payload remains the frozen dialogue contract, explicitly listed eligible memory/preference revision **projections**, the editor's deliberately supplied words, and already-retained complete continuation fragments under the existing attempt contract. It does not become the full memory record, source lineage, examples, all preferences, a Book, a manuscript or a library scan. Eligibility, supervision, exclusion, deactivation, exact revision pins and consumption-time revalidation still govern each projection; removing redaction cannot admit an otherwise ineligible source.

Deliberately typing or pasting one's note wording is editor input, distinct from authorizing AI7 to read an **Editor Note object** or its anchored manuscript. The object remains excluded as a model source and from Task/Run readable source scope. Outside these attempts the same words keep the current strip. Mentioning a note or Book grants no read authority. This proposal supplies no note picker, note-to-learning admission, ambient memory/Book/library retrieval or new source kind.

For this dedicated dialogue, outbound categories remain disclosure/accounting classifications rather than a content-category refusal gate, as v27 already records. This changes neither the category definitions nor their bounds on other rules. Book dialogue, curation, review, polish, evaluation, factual verification, search and background stages receive no exception.

Current `localTools.targetedRetrieval.allowed: false` and `oneBoundedPayloadPerAttempt: true` remain intact, together with one technical session per attempt, the existing source/count/format/size limits and no web tool. Continue/regenerate remain explicit new attempts, with no automatic resend inside the old session. The wider F06 tool/source/attempt authority needs its own contract; neither category-free wording nor this redaction proposal grants it.

## 4. Current evidence and later validation

At the recorded candidate base, static inspection shows the restriction is intentional:

- [Provider Processing v27](../policies/provider-processing-policy.v27.json), rule `ordinary-production-global-agent-dialogue`, has both redaction booleans true, explicit memory/preference revision sources, `targetedRetrieval.allowed: false` and `oneBoundedPayloadPerAttempt: true`. The [policy index](../policies/README.md) qualifies its integration-line selection; #1121's candidates stay separate and unselected, and its v28 keeps both redaction booleans true.
- [`readWave21Eligibility`](../../src/service/launch-policy.ts) requires `HOUSE_PEOPLE_REDACTION`. [`admittedGlobalAgentRoute` and `startGlobalAgentTurn`](../../src/service/dialogue/global-agent-session.ts) require it and recheck disclosed sources/text/binding at send. [`inspectGlobalAgent`, `globalAgentRedact`, `prepareGlobalAgentTurn` and `globalAgentAttempt`](../../src/service/store.ts) build the limited projections and strip the house's known people names — the review-preference consumer's shared `withoutNames` filter over every Book's authors, editors and related people and the preference attributions — from listed text, the question and retained fragments; notes, roles, examples and manuscript references are never assembled. Continue and regenerate rebuild from the first attempt's recorded text, and the final gate requires each listed projection's current text to equal the disclosed text.
- Existing [Global Agent service tests](../../tests/service/ordinary-production-global-agent.test.ts) and [launch-policy tests](../../tests/unit/launch-policy.test.ts) specify redaction, stale disclosure refusal and absent retrieval/tools. They were read as implementation evidence, not executed for this proposal. Because the filter is shared and rechecked at the final gate, changing only policy flags or the shared filter would neither satisfy these readers nor preserve predecessor and other-rule behavior.

## 5. Consequences and Owner choices

The proposed distinction removes one content strip from an already bounded processing action while preserving source admission and public-release authority. It requires coordinated later policy/runtime/disclosure work; it cannot safely be implemented as a global filter toggle. Retaining universal redaction remains the current behavior and the alternative if this text is not accepted.

The Owner must still choose:

1. This bounded Global Agent scope, or a separately inventoried wider ordinary-production scope covering affected tasks, categories, sources and tool recipients. No wider exception is inferred.
2. Deliberately supplied wording only, or separately authorized note-object/source/learning capabilities with their own affected-clause inventory. This proposal grants only the former if accepted.
3. Whether to accept this exact named ADR text after independent review. The recorded principle does not accept the draft by implication.

Until that acceptance and separately authorized follow-through, current redaction and permissions remain unchanged. Drafting completion does not close #1123 or #1071, authorize merge/Ready, or complete runtime delivery.
