## Product and platform

The new AI7 is one Chinese-first Standalone desktop product for Windows and macOS, serving professionals in leading literary publishing houses in mainland China. Both platforms share the exact AI7 identity, domain and authority semantics, workflows, core features, document-fidelity contract, data compatibility, and UI/UX outcomes. Native menus, shortcuts, dialogs, accessibility integration, filesystem locations, protected secret stores, local IPC adapters, packages, signing/notarization, and OS security prompts may differ explicitly without creating separate product editions. Microsoft Word integration is excluded from V1 scope: there is no cross-surface parity, COM add-in, synchronization protocol, Word packaging, or Word verification gate. The legacy Standalone and Word UI implementations, layouts, editors, and component models are not migration baselines; retain or revise user outcomes only when individually accepted.

Long Chinese manuscripts are a required feature with design targets counted in Chinese characters: no sensible performance degradation below 500K, no critical performance issue up to 1M, and no crash or unresponsiveness up to 10M. The renderer never holds a whole manuscript; the authoritative model lives in the AI7 service over a store that pages by Manuscript Block, whole-manuscript operations stream in the service off the UI thread with cancellation and progress, no unbounded in-memory structure exists at any layer, and indexes remain disk-backed or bounded. Windowed display is accepted rather than tolerated, so find, replace, and jump should remain reasonable at every tier and typing latency should depend on window size rather than manuscript size. These are architecture targets, not a separate performance-validation gate.

AI7 ships as an Electron application over three processes on both supported platforms: a thin Electron main shell, a renderer holding the UI and editor with context isolation on and Node integration off, and a separate Node service process holding AI7 domain services plus the composed Harness runtime as the one local authority. That separation keeps the UI responsive under parallel Runs and isolates service crashes from unsaved text. The E2E Functional Gate follows the launchable product path across these processes; a service-only headless check is not a substitute or separate gate. IPC uses stdio or a private platform-local adapter, such as a Windows named pipe when needed, and never a TCP listener. ProseMirror is the editor foundation, operating over bounded windows mapped to global Manuscript Block identities.

Treat professional long-form text editing as a release-critical Standalone outcome. The accepted V2 UI/UX baseline addresses long Chinese manuscripts, extensible structure and exact selection, durable editing/recovery, proposals/review, Chinese input/typography, and import/export fidelity without assuming the old editor. For representative publishing workflows, classify inline styles, comments/revisions, notes, tables, images/captions, sections, headers/footers, and round-trip behavior explicitly as preserve, degrade with disclosure, or reject—never lose them silently. Cover the representative editing journey in the E2E Functional Gate; do not create a separate Standalone Editing Sufficiency Gate. Word may enter a later release only through a separate Owner decision.

Treat manuscripts, sources, and derivatives as Unpublished Editorial Material until Public Release Permission exists, except that an Owner-designated Public SampleBook has the narrow repository-development classification established by ADR 0043. That designation grants only repository tracking and provider-free local/hosted-CI test-input use, not any product-domain authority. ## Editorial authority and workflow

Keep the Book as the source, privacy, and mutation authority. One Book may own at most one primary Manuscript: an empty Book may receive its first Manuscript, a later external version may reimport only into that Manuscript, supporting material remains a Source Version, and a distinct intended work requires another Book. A Source Version is created only by explicit retention of a supported local file, exact editor-pasted or entered material, or a retention-permitted fully retrieved external research snapshot into an explicitly selected Book; search snippets, failed retrievals, model answers, attachments, and Task use never create a Source Version automatically, while any separate Task/evidence retention remains governed by its owning record. An exact existing Source Version identity may be selected only when it is already owned by that same target Book; cross-Book acquisition creates a new target-owned Source Version with its own provenance. With no Book, a reviewed source-bound Book Creation Draft may atomically create a zero-Manuscript Book and its first Source Version without creating a Workflow Instance or unrelated authority. Every Book-owned Editorial Deliverable follows its own Workflow Instance pinned to an AI7-facing versioned Workflow Profile projection/selector and exact native DSH definition. The accepted V1 profile outcomes cover Manuscript, Promotion Article, News Report, and Review Article and expose seven shared phases—intake, source development, drafting, review/verification, finalization, delivery, and maintenance—which may overlap, reopen, or be skipped with a recorded reason.

Workflow state is durable AI7 editorial business state, not DSH Session or artifact-local state. An exact native DSH artifact owns each versioned Workflow definition and technical logic; an AI7 Workflow Profile is only its product-facing projection/selector. AI7 alone owns the durable Workflow Instance, phases/gates, signoffs, scheduling and deterministic business transitions. Native artifacts may retain self-contained presentation, in-memory or artifact-local behavior, but every crossing into AI7 business state, unpublished material, credentials, Provider egress, background work or an Effect remains behind exact AI7 capabilities and authority. AI-assisted native DSH artifacts may propose content and records, but only narrow deterministic AI7 commands may mutate Workflow Instances, Editorial Artifacts, Workflow Gates, Signoff Records, or Delivery Packages. Every formal agent-originated Manuscript diff additionally crosses one explicitly confirmed, exact-base/diff/target, drift-reconciled, single-use AI7 Apply; no artifact, Artifact Update Rule, Default Execution Rule, Background Analysis Enrollment, Run, Session, or Plugin contains or inherits that authority, and a Default Execution Rule grants neither Effect Approval nor Apply. Completion or signoff never implies factual truth, legal or regulatory authority, Public Release Permission, or Learning Eligibility.

An Editorial Deliverable is preserved through immutable exact Editorial Deliverable Revisions; Manuscript Revision is the manuscript realization of that shared revision boundary. A Delivery Package is a versioned, destination- and format-independent manifest bound to one exact Editorial Deliverable Revision, optionally identified by an exact Milestone Version, plus its purpose, included artifacts, gate/signoff references, exclusions, and limitations. Every concrete local file export instead has a frozen per-file Local Export Preparation, exact Effect Intent and Effect Approval, and its own Effect Receipt or classified outcome. Existing-target collisions use the platform-native save/copy workflow with rename, cancel, and replace outcomes rather than a second AI7 modal: the AI7 service records the exact final target and disposition before commit, cancellation attempts no file Effect, target drift invalidates approval, and ambiguity blocks retry pending reconciliation. This never grants a Harness Run roaming filesystem access and no local receipt proves sending, handoff, delivery, or publication. Post-designation maintenance uses a stable Maintenance Case and immutable revisions, permanently bound to one exact Publication Version and Editorial Deliverable Revision under one of `correction`, `errata`, `supersession`, `withdrawal`, `reissue`, or `archive`; content changes create proposals and new revisions, replacement Publication Versions require a separate manual designation, and withdrawal/archive remain internal states rather than external recall or takedown claims.

Keep task source/mutation scope separate from editorial learning scope. A manuscript task may use its Book plus explicitly selected Cross-project sources; corpus-wide adaptation must flow through governed House Editorial Memory and must not silently expose another Book's raw text or facts.

Treat Series as an explicit richer-sharing exception: member Books may share governed Series Knowledge and a Series read scope, but every manuscript mutation remains targeted to a specific Book and revision. Editor-authored drafts and provenance-bound proposals remain non-authoritative Series Knowledge Candidates until an explicit Series Knowledge Promotion Decision creates a stable Series Knowledge Item with its first immutable revision or appends one revision to an exact existing item after provenance, conflict, and reuse-scope review; a preserved conflict requires explicit disposition, stays recorded, and never becomes factual resolution. Membership, accepted proposals, Milestone Versions, Learning Eligibility, and model output never promote candidates automatically. Promotion only makes the revision eligible for later exact Series-scoped selection and does not itself create Run Source Scope, authorize retrieval, or permit provider transmission. A versioned Series Retrieval Exclusion immediately blocks every later affected Series-scoped read, including not-yet-performed reads in an authorized or active Run, without rewriting its frozen scope or history; that Run stops for Plan Revision plus renewed authorization or cancellation, its old authorization remains historical evidence rather than dispatch authority, and changing or ending the exclusion appends a superseding revision without automatic Resume. An item-targeted exclusion covers its current and future revisions, while a stable-class exclusion covers later matching items. The exclusion is neither global Book/source deletion nor a Learning Eligibility exclusion and does not silently decide a separately authorized Cross-project path.

Long manuscripts exceed any model context window, so AI7 retrieves over manuscripts as well as explicitly retained sources. Retrieval returns candidates and never truth: only Exact Fetch against an already-authorized pinned Manuscript Revision or Source Version yields authoritative text for that exact record, and fuzzy or vector matching can never certify a quotation. The Manuscript Revision remains the sole manuscript authority; the editor window, lexical index, outline, and retrieval chunks with their embeddings are derived projections that are disposable and rebuildable from it. Chunks and embeddings serve models while the editor reads ordinary text, so projections may use boundaries suited to their consumer rather than a shared unit. The requirement is consistency across forms: every projection records its derivation revision, rebuilds from the authority alone, invalidates by text-range overlap, tombstones deletions, and re-derives at Manuscript Checkpoints. A stale projection yields a stale ranking rather than merely stale text, so the remedy is re-derivation and re-ranking, not text substitution. Retrieval strategy — lexical, vector, or hybrid — is a later authorized implementation choice. A concrete blocker may justify a bounded non-gating diagnostic, never a standing spike or proof programme. Retrieval indexes derived from manuscript text are manuscript derivatives and never enter a repository, hosted CI, or a distributable artifact.

Whole-manuscript or comprehensive analysis uses a different contract. AI7 deterministically enumerates a structure-aware, bounded-overlap Coverage Manifest and every Analysis Unit for one exact Manuscript Pin; DSH owns the typed analysis/reducer contract while AI7 owns coverage, provenance, immutable Manuscript Analysis Result Set Revisions, conflicts/gaps, reuse or bypass lineage, and currentness. Ranked relevance never substitutes for coverage. Incremental synchronization, selected-range forced reanalysis, and whole-Book forced reanalysis each append a revision. Coverage, reducer/synthesis closure, exact-revision freshness, and semantic/evidence assurance remain independent visible states. A Manuscript Checkpoint only marks deterministic invalidation by default. New idle, scheduled, post-checkpoint, import-triggered, or cross-Run Provider work requires a matching active Background Analysis Enrollment; import succeeds with analysis pending when none exists or analysis later fails. Artifact installation or enablement enrolls nothing.

Treat an imported manuscript revision as the Textual Source of Record for what the document exactly says, never as a truth oracle for its assertions. AI7 must identify possible factual and semantic errors through evidence-bearing review, distinguish textual fidelity from factual verification, and express fixes as exact-revision Correction Proposals rather than silently rewriting source text.

Factual Verification follows the active versioned Factual Verification Policy Document. Record Reference Integrity, Claim Support, and Factual Verification independently; preserve unresolved or conflicting evidence, and use Foundation Model knowledge only to raise verification questions or guide research, never as factual evidence by itself.

Preserve manuscript history through stable Manuscript Blocks, immutable reconstructable Manuscript Revisions, text-only Manuscript Branches, per-branch durable Edit Journals, meaningful Manuscript Checkpoints, and independent verified Recovery Snapshots. Keep these records distinct from Source Versions, Source Index Chunks, Run Continuation Checkpoints, Harness technical checkpoints, and Harness Sessions. Whenever a Task would use acknowledged journal state newer than the latest Manuscript Revision as manuscript target, range, source, or evidence, materialize that state first through a Manuscript Checkpoint carrying the purpose label `Task Input / 任务输入`; this creates an immutable reconstructable revision but no Milestone Version or Signoff. Every attached manuscript target, range, source, and evidence reference—whether already pinned to the prior revision or still pending—must exact-resolve on the new revision and create a new task-bound pin without mutating the original pin or losing its provenance. Any unresolved changed or ambiguous reference preserves the checkpoint and Task draft but blocks Plan Preview and Run Authorization until the editor reselects or removes it. The Task Intent, resolved ranges, sources, evidence, Plan Envelope, and later Run then bind that one exact revision; checkpoint failure preserves the Task draft and journaled edits but blocks authorization, and later edits never retarget an authorized Run. Reimport uses a prior Source Version as a three-way comparison base only when exact lineage proves it; otherwise label the relationship unconfirmed, compare current and staged states conservatively, and never invent ancestry or empty revisions.

All model-generated manuscript changes begin on Proposal Branches. Apply is atomic and exact-pin-bound: identical or non-interacting different-block changes may merge automatically, while different same-block changes and ambiguous structural interactions require explicit editor resolution; model-composed resolutions remain proposals.

Never use unqualified Approval as a domain authority. Distinguish Run Authorization, Execution Grant, Proposal Decision, Review Decision, Effect Approval, and Public Release Permission. One user interaction may create more than one exact record, but no decision or grant is proof that an Effect committed.

Every authoritative or externally visible Effect has stable identity, declared replay policy, exact target/payload binding, staged verification when applicable, per-Effect atomic publication, and an Effect Receipt or explicitly classified outcome evidence. Material drift invalidates Effect Approval; ambiguous external outcomes stop automatic retry and fallback; cancellation never claims to undo committed Effects.

Keep stable English domain terms for architecture and record identifiers, and maintain one preferred Simplified Chinese label for every accepted glossary term. Chinese-first product surfaces use the preferred Chinese label; `GLOSSARY.md` is the bilingual index, while each context `CONTEXT.md` remains the canonical definition owner.

## Learning, quality, and policy

AI7 owns the quality evaluator Harness does not provide. Capture Quality Signals from explicit editor feedback, editor-authored content, and proposal decision/version differences; derive verbatim acceptance, revision distance, survival to delivery, dissatisfaction by dimension, and workload displacement measured as edit volume weighted by a once-declared phase effort weight. Per-task time tracking is rejected. Signals are captured globally on the local instance and attributed for per-Book, per-editor, and per-house aggregation, but aggregating metrics globally never grants global retrieval access. AI7 must operate at zero data: no sample threshold may block operation or proposal, and sample size gates auto-activation alone. Query accept/reject/change reasons through a quick non-blocking one-click interaction that offers several alternatives, pre-selects none, and tracks guess acceptance versus correction — otherwise the system learns its own suggestion instead of the editor's judgment. Editor decisions are the oracle for taste, style, and editorial judgment, never for factual correctness.

Privacy is an egress boundary, not an identity boundary. Any authorized person may read a manuscript locally and Quality Signals may retain manuscript excerpts locally, but no automated product path may carry a manuscript off the machine except a configured model call. Repositories, hosted CI, runners, artifacts, and logs stay closed to manuscripts except that an admitted Public SampleBook may be tracked and used as provider-free local/hosted-CI test input under ADR 0043, and only exact `sample1` may later produce a separately admitted reviewed fixture under ADR 0044. Public input and recording payload still stay out of logs and uploaded artifacts; raw recording stays in protected local staging outside repositories.

No material may influence learned editorial behavior without Learning Lineage visible in the Learning Audit Log. Explicit inclusion/exclusion decisions outrank inferred Learning Eligibility Policy, and eligibility learning remains separate from editorial-preference learning.

Rules that grant or constrain product authority live in versioned, human-reviewable, machine-validatable Policy Documents rather than hidden prompts or code-only defaults. Production-run evidence may trigger AI-agent review and a Proposed Policy Revision, but historical versions remain immutable and no revision may expand its own scope or authority. Existing ADRs conflict over bounded non-expansive Policy activation; until a separately authorized supersession resolves that conflict, the stricter ADR 0018 developer-review rule governs every Policy revision. No native artifact, Artifact Update Rule, Default Execution Rule, or Background Analysis Enrollment may activate one.

AI7 does not train or fine-tune an LLM. All model-facing design uses replaceable provided Foundation Models behind the AI7 Editorial Intelligence Layer. Preserve Professional Editorial Knowledge, provenance, memory, policies, and evaluations outside model weights, and judge changes by Editor-comparable Delivery Quality plus measurable workload reduction.

## Task execution, providers, and records

Every production task binds an exact Task Intent and versioned Execution Plan to a machine-authoritative Plan Envelope. Its Plan Preview is only the human-readable projection; Run Authorization permits logged Plan Adaptations inside the unchanged envelope, while material changes to goal, scope, capabilities, providers, privacy category, Run Budget Ceiling state, outcome, Effect class, or authority-bearing pins suspend work and require a Plan Revision plus renewed Run Authorization. Every envelope binds an exact Run Budget Ceiling state: `unset` by default or an optional explicit hard ceiling. `Unset` means AI7 will not stop model dispatch on a product-side monetary/token ceiling; it never means free service or freedom from the Model Provider's account quota, spending control, credit condition, or billing terms.

Run Authorization never grants Effect Approval, Proposal Decision, Review Decision, or Public Release Permission. Clarification Requests, pause/cancel, and Task Outcomes are durable and restart-safe; every outcome records actual-versus-planned work, evidence, unresolved matters, Effects/receipts, and a safe next action without silently becoming an authoritative manuscript, Editorial Artifact, factual resolution, or public release.

Use one logical causal graph with two authoritative ledgers. The AI7 Task Ledger owns Task Intents, Run Records, business commands, decisions, Effects, outcomes, workflow references, and provenance; the Harness Session Ledger alone owns model messages, turns, steps, tool calls/results, technical events, checkpoints, diagnostics, and attempt history. Join them through exact Execution Bindings and Harness Execution Spans without copying transcripts. Do not create active Operation Records, Operation Events, or `operationRuns`; legacy instances remain old-repository or offline evidence only and are not imported.

Resume continues the same unchanged Run from authoritative AI7 state, Retry creates a new safe execution attempt within that Run, Redo creates a newly authorized Run, and Replay performs no execution.
